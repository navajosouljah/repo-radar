● Core capabilities

AI-driven vulnerability detection

Goes beyond regex pattern matching. Codex Security uses OpenAI's models to understand code flow, trace data from source to sink, and identify vulnerabilities that rule-based scanners miss - including logic errors, authorization bypasses, and unsafe deserialization chains.

Automatic fix generation

For each vulnerability found, the scanner generates a proposed fix as a code diff. Fixes are validated against the project's test suite when available. The output includes both the vulnerable code and the remediated version for easy review.

SARIF output for CI/CD

Results export in SARIF (Static Analysis Results Interchange Format), the standard that GitHub, Azure DevOps, and other platforms consume natively. Pipe scan results directly into your existing security dashboard with zero transformation.

OWASP Top 10 coverage

Covers all ten categories of the OWASP Top 10: injection, broken auth, sensitive data exposure, XXE, broken access control, misconfiguration, XSS, insecure deserialization, known vulnerabilities, and insufficient logging. Each finding maps to its OWASP category and CWE ID.

TypeScript SDK

The SDK exposes the full scanning engine as a programmatic API. Run scans, filter results by severity, apply fixes, and integrate with custom workflows - all from TypeScript. Useful for building custom security gates, internal dashboards, or automated remediation pipelines.

Severity classification

Every finding is classified as Critical, High, Medium, or Low based on exploitability and impact. The classifier considers the vulnerability type, the application context, and whether the vulnerable path is reachable from user input.

Key differentiator

From detection to fix in one command

Traditional SAST tools stop at detection. They tell you line 47 has an SQL injection, and then you are on your own. Codex Security goes further: it generates a validated fix for each finding. Run codex-security scan --fix and the output includes both the vulnerability report and a code diff you can apply. The fix is not a generic recommendation - it is actual code, generated from understanding your specific codebase, and validated against the project's types. This collapses what used to be a detect-triage-research-fix cycle into a single step. The catch - and it is an important one - is that AI-generated fixes still need human review. But reviewing a proposed fix is faster than writing one from scratch.

The security problem

Security scanning has been around for decades. The tooling is mature. The problem is not detection - it is everything that happens after the alert fires.

Alert fatigue

Too many findings, too little context. A typical SAST scan on a medium codebase produces hundreds of findings. Most are false positives, informational, or low-severity. Developers learn to ignore the noise, and critical vulnerabilities get buried in a sea of warnings.

No fix, just a pointer. Traditional scanners say "SQL injection on line 47" and link to a generic remediation guide. The developer has to understand the vulnerability class, research the fix, adapt it to their codebase, and test it. This takes 30 minutes per finding at minimum.

Security expertise is scarce. Most teams do not have a dedicated security engineer. Application developers are expected to fix vulnerabilities they may not fully understand. The result: findings sit open for weeks, or get closed with band-aid fixes that miss the root cause.

Codex Security

AI-classified severity. Instead of dumping every pattern match, Codex Security uses model-based classification to surface only actionable findings. The severity score considers exploitability, reachability from user input, and actual impact - not just the vulnerability category.

Fix included. Each finding ships with a generated code diff. The developer's job shifts from "research and write a fix" to "review and approve a fix." This takes minutes instead of hours, and does not require deep security expertise.

Developer-friendly output. Findings include plain-language explanations of what the vulnerability is, why it matters, and how the proposed fix addresses it. The goal is education alongside remediation - developers learn security patterns by reviewing AI-generated fixes.

● The triage bottleneck

[CRITICAL] The cost of manual triage

A 2025 industry study found that the average time to triage a single SAST finding is 22 minutes. For a scan that produces 200 findings, that is 73 hours of developer time just to sort signal from noise - before a single line of code is fixed. Most teams triage fewer than 30% of findings. The rest accumulate as security debt.

[WARNING] The ignore reflex

Alert fatigue is real. When every commit triggers 50 scanner warnings and most are false positives, developers stop reading them. They become the "boy who cried wolf" of the CI pipeline. Critical vulnerabilities slip through not because the scanner missed them, but because the developer did not look at the report.

[INFO] The expertise gap

Fixing a broken-access-control vulnerability requires understanding authentication flows, session management, and authorization patterns. Fixing an insecure deserialization requires understanding serialization formats and gadget chains. Most application developers do not have this background. They need the fix handed to them - or at least a very specific starting point.

Scan your codebase

Install the CLI, run your first scan, review findings, and integrate into your CI pipeline. The first scan takes under a minute on most projects.

1

Install the package

# Install globally for CLI access
npm install -g @openai/codex-security

# Or add to your project as a dev dependency
npm install --save-dev @openai/codex-security

# Verify installation
codex-security --version
# @openai/codex-security v2.1.0

Requires Node 18+ and a valid OpenAI API key set as the OPENAI_API_KEY environment variable. The scanner sends code snippets to OpenAI's API for analysis - your code is processed under OpenAI's enterprise data policies.

2

Run your first scan

# Scan a directory
codex-security scan --path ./src

# Scan with fix generation
codex-security scan --path ./src --fix

# Scan specific files
codex-security scan --path ./src/auth.ts ./src/api/users.ts

# Filter by minimum severity
codex-security scan --path ./src --min-severity high

The scanner analyzes each file, traces data flows, and reports vulnerabilities with severity classifications. The --fix flag generates remediation diffs for each finding. Use --min-severity to focus on critical and high findings first.

3

Export results for CI/CD

# Output as SARIF for GitHub Advanced Security
codex-security scan --path ./src --format sarif --output results.sarif

# Output as JSON for custom processing
codex-security scan --path ./src --format json --output results.json

# Fail CI if critical/high findings exist
codex-security scan --path ./src --fail-on high

The --fail-on flag sets the exit code to 1 if findings at or above the specified severity are found - perfect for blocking merges in CI. SARIF output plugs directly into GitHub Code Scanning, Azure DevOps, and other platforms that consume the format.

4

Use the TypeScript SDK

import { scan, appliFix } from '@openai/codex-security';

// Programmatic scan
const results = await scan({
  path: './src',
  minSeverity: 'high',
  generateFixes: true,
});

// Filter and process findings
const critical = results.findings
  .filter(f => f.severity === 'critical');

for (const finding of critical) {
  console.log(finding.message);
  console.log(finding.fix.diff);
}

The SDK gives you full control over scanning, filtering, and fix application. Use it to build custom security gates, integrate with Slack notifications, or create internal dashboards that track vulnerability trends across your codebase.

5

Add to GitHub Actions

# .github/workflows/security.yml
name: Security Scan
on: [push, pull_request]
jobs:
  scan:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: 20
      - run: npm install -g @openai/codex-security
      - run: codex-security scan --path ./src
             --format sarif --output results.sarif
             --fail-on high
        env:
          OPENAI_API_KEY: ${{ secrets.OPENAI_API_KEY }}
      - uses: github/codeql-action/upload-sarif@v3
        with:
          sarif_file: results.sarif

This workflow runs on every push and pull request. Findings appear as GitHub Code Scanning alerts in the Security tab, with inline annotations on the PR diff. The pipeline fails if any high or critical findings are detected.

Where it fits

Codex Security targets the gap between "scanner found something" and "developer fixed it." Here is where teams are putting it to work - and where the broader ecosystem is watching.

Pre-commit checks

Catch issues before they land. Run codex-security scan --path ./src --fail-on high as a pre-commit hook or in a local dev script. Developers get immediate feedback on security issues before pushing code. The --fix flag generates remediation diffs they can apply on the spot - no context switching to a security dashboard.

CI/CD pipeline gate

Block unsafe merges automatically. The SARIF output plugs into GitHub Code Scanning, and the --fail-on flag turns the scanner into a merge gate. Critical or high-severity findings block the PR. The findings appear as inline annotations on the diff, so reviewers see exactly what is wrong and where.

Security audit automation

Baseline an entire codebase. Point the scanner at your full source tree and export a comprehensive SARIF report. Use the severity classifications to prioritize remediation - fix the criticals this sprint, the highs next sprint, the mediums when bandwidth allows. The generated fixes cut the remediation time per finding significantly.

Developer education

Learn by reviewing fixes. Every finding includes a plain-language explanation of the vulnerability and a generated code fix. Junior developers reviewing these fixes learn security patterns organically - what a parameterized query looks like, why you escape HTML output, how to handle secrets. The scanner doubles as a teaching tool.

In the Wild

  • OpenAI's security tooling push. Codex Security represents OpenAI's first dedicated entry into the developer security tooling space. The project launched in July 2026 alongside updates to the broader Codex CLI platform, signaling OpenAI's intention to compete not just in code generation but in code quality and security.
  • Comparisons to established SAST tools. The developer community has been actively comparing Codex Security to established static analysis tools like Snyk Code, Semgrep, and CodeQL. The consensus so far is that the AI-generated fixes are the key differentiator, while detection accuracy is still catching up to mature rule-based engines on certain vulnerability classes.
  • Enterprise interest. Several discussion threads on developer forums highlight interest from enterprise security teams, particularly around the SARIF output and CI/CD integration. The Apache-2.0 license makes enterprise adoption straightforward. However, the requirement to send code to OpenAI's API is a blocker for some regulated industries.
  • Early benchmarks. Independent testers have started publishing informal benchmark results comparing Codex Security's detection rates against OWASP Benchmark and known vulnerable applications. Results are promising but incomplete - the project is too young for rigorous, peer-reviewed evaluations. Take early accuracy claims with appropriate skepticism.

Watch out for

  • AI-generated fixes need human review. This cannot be stressed enough. The scanner generates proposed fixes, not verified ones. A generated fix might resolve the immediate vulnerability while introducing a logic bug, a performance regression, or a different security issue. Always review the diff before applying it.
  • False positive rate is still being calibrated. As a young tool, Codex Security's false positive rate has not been independently benchmarked at scale. Early community reports suggest it is better than naive pattern matchers but not yet at the level of mature tools like Semgrep with curated rule sets. Expect some noise in your results.
  • Requires OpenAI API access. Every scan sends code snippets to OpenAI's API for analysis. This has two implications: you need an OPENAI_API_KEY with sufficient quota, and your source code is transmitted to OpenAI's servers. Review OpenAI's data usage policies before scanning proprietary codebases. Organizations with strict data residency requirements may not be able to use this tool.
  • Cannot replace manual penetration testing. Static analysis - even AI-powered static analysis - is not a substitute for dynamic testing, threat modeling, or expert penetration testing. Codex Security finds code-level vulnerabilities. It does not test runtime behavior, infrastructure configuration, authentication flows under load, or business logic vulnerabilities that only emerge in context.
  • API cost at scale. Each scan consumes OpenAI API tokens proportional to the codebase size. Scanning a large monorepo on every commit can add up. Use --path to scope scans to changed files in CI, and run full-codebase scans on a scheduled basis rather than on every push.
