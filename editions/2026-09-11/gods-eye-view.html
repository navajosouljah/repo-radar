● What makes it different

WebGL 3D globe with real terrain

Not a flat map with pins. Gods Eye View renders a full 3D globe with elevation data, cloud cover, and day/night terminator - all in the browser using WebGL. Rotate, zoom, tilt. The visual fidelity rivals desktop GIS applications.

Real-time aircraft tracking via ADS-B

The air traffic layer pulls live ADS-B transponder data from open aggregator feeds. You can see commercial flights, their altitude, heading, and speed updating in near real-time - no FlightAware subscription needed.

Ship tracking via AIS feeds

The maritime layer ingests AIS vessel data - cargo ships, tankers, fishing fleets. Each vessel shows position, heading, speed, and vessel type. Watch global shipping lanes light up as thousands of vessels report in.

OpenStreetMap as the base layer

The underlying map data comes from OpenStreetMap, so every road, building footprint, and point of interest is community-maintained and freely available. No Google Maps API key, no usage-based billing.

Composable data layers

Toggle layers on and off independently - weather radar, satellite imagery, air traffic, vessel tracking, seismic events. Each layer is a separate data source that overlays cleanly on the globe. Add your own custom layers via the plugin system.

Open data philosophy, end to end

Every data feed is open source or openly licensed. No proprietary APIs behind the curtain. The project maintains a curated registry of data sources with their update frequencies, coverage areas, and terms of use.

Single best feature

One globe, every open data feed, zero vendor lock-in

The killer value of Gods Eye View is unification. Today, if you want to see air traffic you open one site, for ship tracking another, for weather a third, for satellite imagery a fourth. This project layers them all onto a single interactive globe - and because every data source is open, you can self-host the entire stack without a single API key from a commercial vendor. For journalists, researchers, and disaster responders, that changes what spatial awareness looks like.

The spatial data problem

The world produces an enormous amount of freely available geospatial data. The problem is not access - it is assembly. No single tool lets you see it all at once without paying enterprise GIS prices.

Before

Fragmented data sources. Aircraft positions come from ADS-B Exchange. Ship positions come from MarineTraffic or VesselFinder. Weather comes from NOAA. Satellite imagery from NASA Worldview. Each lives in a different web app with different controls, different projections, and no way to overlay them.

Expensive GIS software. Professional tools like ArcGIS or QGIS can combine these layers, but they carry steep licensing costs, require desktop installation, and demand GIS expertise. A journalist covering a shipping incident should not need a GIS certification to see what is happening.

Stale snapshots, not live feeds. Most open data visualization tools show static datasets - a CSV loaded onto a map. They do not maintain persistent connections to streaming data sources. By the time you see the data, the planes have moved, the ships have docked, and the storm has shifted.

Closed-source commercial trackers. FlightRadar24, MarineTraffic, and similar services do offer live tracking, but their free tiers are limited, their data is proprietary, and you cannot self-host, customize, or integrate them into your own workflows.

After

Unified live view. Gods Eye View composites all major open data feeds onto a single WebGL globe. Air traffic, maritime vessels, weather systems, and satellite imagery coexist on the same canvas with consistent controls and a shared coordinate system.

Browser-native, no install. The entire application runs in the browser. No GIS software, no desktop install, no license key. Clone the repo, run the dev server, and you have a spatial intelligence dashboard in your browser tab.

Persistent streaming connections. The application maintains WebSocket and polling connections to live data feeds. Aircraft and vessel positions update in near real-time. Weather layers refresh on their source cadence. The globe is never stale.

Fully open, fully forkable. Every component is open source. Every data feed is documented. If you need to add a custom layer - say, earthquake sensors or wildfire perimeters - the plugin architecture lets you wire in any GeoJSON or tile source without touching the core.

Get orbital

From zero to a spinning globe with live data in under five minutes. No API keys required for the default data sources - everything runs from open feeds.

1

Clone the repository

# Clone from GitHub
git clone https://github.com/bilawalsidhu/gods-eye-view.git
cd gods-eye-view

The repository includes all the WebGL rendering code, data layer adapters, and a development server. The codebase is pure JavaScript with no framework dependencies beyond Three.js for the WebGL globe.

2

Install dependencies and configure data sources

# Install Node.js dependencies
npm install

# Copy the example configuration
cp config.example.json config.json

# The default config points to free, open data feeds
# No API keys needed for:
#   - OpenStreetMap tiles
#   - ADS-B aircraft data (open aggregators)
#   - AIS vessel data (community feeds)
#   - NOAA weather overlays

The default configuration connects to freely available open data sources. If you want higher-resolution satellite imagery or faster update rates, you can add optional API keys for providers like Mapbox, Sentinel Hub, or commercial ADS-B feeds - but the base experience works without them.

3

Start the development server

# Start the dev server
npm run dev

# The application will open at http://localhost:3000
# The globe loads with default layers enabled:
#   - Base map (OpenStreetMap)
#   - Air traffic (ADS-B)
#   - Weather overlay (NOAA)

On first load, the globe initializes with your approximate location centered. Aircraft icons begin populating within seconds as the ADS-B feed connects. Use the layer panel on the right to toggle additional data sources on and off.

4

Explore the layer controls and customize

# Toggle layers in the browser UI or via config
# Available built-in layers:
#   air-traffic    - Live ADS-B aircraft positions
#   vessels        - AIS maritime vessel tracking
#   weather        - NOAA radar and satellite
#   satellite-img  - Earth observation imagery
#   seismic        - USGS earthquake events
#   day-night      - Solar terminator line

# Add a custom GeoJSON layer
npm run add-layer -- --name "my-layer" --source ./data/custom.geojson

Each layer can be independently toggled, filtered, and styled. Click any aircraft or vessel to see its metadata - callsign, altitude, speed, origin, destination. The layer panel also shows each source's update frequency and last-refreshed timestamp.

Mission briefs

Gods Eye View sits at the intersection of open data, spatial intelligence, and browser-based visualization. Here is where it finds its operators.

Investigative Journalism

Track movements without commercial subscriptions. Journalists investigating sanctions evasion, illegal fishing, or military logistics use open AIS and ADS-B data to track vessels and aircraft. Gods Eye View gives them a visual dashboard to monitor specific routes, flag unusual patterns, and overlay multiple data sources - all without the cost of a FlightRadar24 or MarineTraffic enterprise plan. The "dark fleet" tanker stories at major outlets relied on exactly this kind of open-source spatial analysis.

Disaster Response

Situational awareness when minutes matter. During hurricanes, earthquakes, or wildfires, responders need to see weather data, affected areas, transportation routes, and asset positions on a single map. Gods Eye View's composable layers let emergency teams overlay NOAA weather radar, USGS seismic data, and live aircraft positions simultaneously. Because it runs locally, it works even when commercial services are overloaded or offline.

Logistics Monitoring

Watch your supply chain move in real time. Shipping companies and freight brokers use AIS vessel data and ADS-B cargo flight data to monitor supply chains. Gods Eye View can display vessel positions along shipping lanes, highlight port congestion by visualizing vessel density, and overlay weather data that might affect delivery timelines. A custom layer with your own fleet GPS data completes the picture.

Education and Research

A teaching globe for spatial data literacy. Geography, environmental science, and data visualization courses use Gods Eye View as a hands-on lab tool. Students can see how ADS-B transponder data reveals flight path patterns, how AIS data maps global trade routes, and how weather systems move across the planet - all in an interactive, code-readable, open-source application they can modify and extend.

Watch out for

  • Data source reliability. Open data feeds are maintained by volunteers and community aggregators. ADS-B coverage has gaps over oceans and remote regions. AIS feeds from community receivers do not cover every port. When a feed goes down, the layer goes dark with no SLA to fall back on. You are dependent on the uptime of sources you do not control.
  • Bandwidth requirements. Streaming live positions for thousands of aircraft and vessels simultaneously is data-intensive. On a default configuration, expect 50-100 MB of data transfer per hour of active use. Mobile connections and metered plans will feel it. Consider filtering to a geographic bounding box if bandwidth is constrained.
  • Potential misuse concerns. The project's tagline - "spy satellite simulator" - is deliberately provocative, and the tool does make real-time tracking more accessible. While all data is already public, combining it into a polished UI lowers the effort needed to track specific aircraft or vessels. This has prompted discussion about whether the project should implement any access controls or use-case guidelines.
  • WebGL rendering performance. The 3D globe with multiple active data layers is GPU-intensive. Older machines, integrated graphics, and mobile devices may struggle with frame rates when all layers are enabled simultaneously. The project recommends a dedicated GPU and a modern browser. Safari on macOS has known rendering quirks with certain WebGL features.
  • Custom license. The repository uses a NOASSERTION license classification, meaning the licensing terms are non-standard. Review the actual license file in the repository before building anything commercial on top of it. This is not MIT or Apache-2.0 - read before you ship.
