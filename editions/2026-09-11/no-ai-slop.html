● Key features

Pattern-based detection

Ships with 20+ built-in regex patterns targeting the most common AI filler phrases. Each pattern is documented with examples of what it catches and why it is flagged.

Configurable sensitivity

Three sensitivity levels - low, medium, and high - let you control how aggressively patterns are applied. Low mode catches only the most egregious slop; high mode flags subtler patterns too.

Before/after diff output

The CLI shows a color-coded diff of every change it makes. You see exactly what was removed and can review before committing. No silent rewrites.

Custom pattern definitions

Define your own patterns in a YAML config file. If your organization has house style rules or additional phrases to flag, add them alongside the built-in set.

CLI and Python library

Run noaislop clean input.txt from the command line, or import noaislop in your Python code. Same engine, two interfaces.

Preserves meaning

Patterns are designed to remove filler without changing the core meaning of sentences. The tool strips hedging and padding, leaving the substantive claim intact.

Why it resonates

The anti-slop movement, automated

There is a growing cultural backlash against AI-generated filler text. Readers have learned to spot the patterns - "delve", "tapestry", "landscape", "it's worth noting" - and they immediately distrust content that uses them. This tool gives writers a concrete, automated way to clean up AI-assisted drafts before publishing. It turns a vague style instinct into a repeatable lint step.

The slop problem

AI language models have verbal tics. They overuse the same filler phrases, hedging language, and grandiose descriptors - and readers have noticed.

The reality

AI text has a fingerprint. Language models disproportionately favor certain phrases. "Delve", "tapestry", "landscape", "it's worth noting", "paradigm shift" - these words appear orders of magnitude more often in AI output than in human writing. Readers now scan for them as a trust signal.

Manual cleanup is tedious. Writers using AI assistance know they need to edit the output, but catching every instance of filler across a long document is slow and error-prone. It is the kind of repetitive task a machine should handle.

Content credibility is at stake. Blog posts, documentation, marketing copy, and emails that read like unedited ChatGPT output erode trust. Audiences are increasingly skeptical of anything that sounds "too AI."

The fix

Automated pattern detection. Run your text through noaislop and it highlights every instance of known AI filler. The patterns are based on empirical analysis of what language models overuse compared to human baselines.

Configurable strictness. Not every flagged phrase is wrong in every context. The sensitivity slider lets you choose how aggressive the cleanup should be - gentle for technical docs, strict for marketing copy.

Pipeline-ready. Drop it into your CI, your CMS publish hook, or your content review workflow. It is a Python library, so it integrates anywhere Python runs. Think of it as a linter for AI writing style.

"The word 'delve' appeared in 0.002% of human text but shows up in over 0.1% of AI-generated content - a 50x overrepresentation. Readers have learned to pattern-match on these signals." Observed frequency analysis of AI writing patterns

● What "slop" actually means

Hedging phrases

"It's worth noting", "it's important to remember", "one might argue" - qualifiers that pad sentences without adding information. They make writing feel non-committal.

Grandiose descriptors

"Revolutionary", "cutting-edge", "paradigm shift", "game-changing" - superlatives that AI sprinkles liberally but that humans use sparingly in serious writing.

Transition filler

"In today's landscape", "in the realm of", "when it comes to" - wordy transitions that could be replaced with nothing or a simple conjunction.

Purple prose markers

"Rich tapestry", "multifaceted approach", "nuanced understanding" - phrases that sound sophisticated but say little. They are the verbal equivalent of clip art.

Get started

Install from PyPI, clean your first file, and optionally configure custom patterns - all in under five minutes.

1

Install from PyPI

# Install the package
pip install no-ai-slop

# Verify installation
noaislop --version

Requires Python 3.9+. No external dependencies beyond the standard library and a few lightweight packages.

2

Clean a file from the CLI

# Basic cleanup with diff output
noaislop clean input.txt

# Write cleaned output to a new file
noaislop clean input.txt -o cleaned.txt

# Set sensitivity level
noaislop clean input.txt --sensitivity high

The CLI displays a color-coded diff showing every phrase it removed or replaced. Review the changes before accepting them.

3

Use as a Python library

from noaislop import clean, detect

# Clean text directly
text = "It's worth noting that this paradigm shift will delve into..."
cleaned = clean(text, sensitivity="medium")
print(cleaned)

# Or just detect without removing
matches = detect(text)
for m in matches:
    print(f"  Found '{m.phrase}' at position {m.start}")

The detect() function returns match objects with position, pattern name, and suggested replacement. Use it to build custom UIs or reporting.

4

Add custom patterns

# Create a .noaislop.yml config file
patterns:
  - name: corporate_jargon
    regex: "\\b(synergize|leverage|circle back)\\b"
    severity: medium
    description: "Corporate buzzwords"

  - name: filler_adverbs
    regex: "\\b(basically|essentially|fundamentally)\\b"
    severity: low
    description: "Filler adverbs that weaken sentences"

Place .noaislop.yml in your project root. Custom patterns are merged with the built-in set. You can also disable specific built-in patterns by name.

5

Integrate into your workflow

# Pre-commit hook example
# .pre-commit-config.yaml
repos:
  - repo: local
    hooks:
      - id: no-ai-slop
        name: Check for AI slop
        entry: noaislop check
        language: python
        types: [markdown, text]

# CI check (exits non-zero if slop found)
noaislop check docs/ --sensitivity medium --strict

The check subcommand exits with a non-zero code if any patterns are found, making it suitable for CI gates and pre-commit hooks.

Real-world uses

Where no-ai-slop fits into content workflows - and where the community is putting it to work.

Content Publishing

Pre-publish quality gate. Content teams using AI to draft blog posts, newsletters, and marketing copy run the output through noaislop before publishing. It catches the filler that a quick human read might miss, especially in longer pieces where fatigue sets in.

Email Cleanup

Sound like yourself. Professionals who use AI to draft emails run them through the tool to strip phrases that signal "this person didn't actually write this." Particularly useful for client-facing communication where authenticity matters.

Documentation

Technical writing quality gate. Teams generating documentation with AI assistance use noaislop as a lint step alongside their existing doc toolchain. Technical docs that say "delve into the API" lose credibility with developers.

Writing Education

Teaching tool. Writing instructors use the pattern list as a concrete reference for students. Instead of vague advice to "make it sound more natural," students can see exactly which phrases to avoid and why they are flagged.

In the Wild

  • Cultural momentum. The term "AI slop" has entered mainstream vocabulary, appearing in publications from The Atlantic to Wired. There is widespread frustration with the sameness of AI-generated text, and tools that address it are finding a receptive audience. The repo's rapid growth from zero to 8.3K stars in about two months reflects genuine demand.
  • Community pattern contributions. The repo's issue tracker shows active discussion about which patterns to include and at what severity level. Contributors are proposing language-specific pattern sets and debating edge cases - a sign of real engagement beyond passive starring.
  • Social media traction. Posts about the tool have circulated widely on developer-focused platforms, often accompanied by examples of before/after text that demonstrate the cleanup effect. The visual diff output makes for compelling screenshots.
  • Complementary ecosystem. Several browser extensions and writing tools have emerged with similar goals - detecting AI-generated content patterns. This repo is one of the more focused implementations, targeting removal rather than just detection.

Watch out for

  • False positives on human writing. Some flagged phrases are perfectly legitimate in certain contexts. A historian writing about a "rich tapestry of cultures" is using the phrase sincerely. The tool's pattern-matching approach has no way to distinguish intentional from accidental usage.
  • English-only. All built-in patterns target English-language filler. AI slop patterns in other languages - and they exist - are not covered. Custom patterns can partially address this, but the core heuristics assume English.
  • No semantic understanding. The tool uses regex pattern matching, not language models. It cannot judge whether a phrase is used meaningfully in context. It will flag "it's worth noting" in a sentence where that phrase genuinely adds emphasis, not just filler.
  • Aggressive modes may over-strip. At high sensitivity, the tool may remove phrases that are perfectly natural in human writing. The "medium" default is a reasonable starting point, but review the diff output carefully before blindly accepting all changes.
  • Young project. Created July 7, 2026 - about two months old as of this edition. The pattern set is still evolving, the API may change, and edge cases in the regex patterns may produce unexpected results. Pin your version in production.
