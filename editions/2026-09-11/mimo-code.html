Where models learn from agents

MiMo-Code is not just another coding assistant. It is a platform where the underlying language model and the coding agent that uses it improve each other in a continuous loop. The agent generates coding trajectories, the model learns from them, and the improved model makes the agent better.

• What makes it different

Co-evolutionary training loop

The agent runs coding tasks and records its successes and failures. These trajectories feed back into model training via reinforcement learning. The improved model then powers a better agent - creating an upward spiral of capability.

Models learn from agent experience

Traditional fine-tuning uses static datasets. MiMo-Code generates training data from real agent interactions - tool calls, error recovery, multi-step reasoning chains. The model sees what actually works in practice, not what a human annotator imagined would work.

Open weights + open agent code

Both components are open. The model weights are available for download and fine-tuning. The agent code is MIT-licensed TypeScript. You can run the entire pipeline - model, agent, and training loop - on your own infrastructure.

Strong coding benchmarks

MiMo-Code's co-evolved models show competitive results on standard coding benchmarks including HumanEval, MBPP, and SWE-bench. The co-evolutionary approach appears to improve practical coding ability more than standard instruction tuning alone.

Reinforcement learning from agent feedback

The training pipeline uses RL signals derived from agent outcomes - did the code compile, did tests pass, did the edit achieve its goal. This grounds the model's learning in verifiable results rather than human preferences alone.

Xiaomi's research backing

MiMo-Code comes from Xiaomi's AI research lab, which has been steadily releasing open models (MiMo-7B, MiMo-VL) throughout 2025-2026. This is not a weekend project - it has institutional support and a research roadmap.

Core Insight

The feedback loop is the product

Most coding AI projects improve either the model or the agent. MiMo-Code improves both simultaneously by connecting them in a feedback loop. The agent generates real-world coding trajectories - including failures, recoveries, and tool usage patterns - and feeds them back into model training. The key insight is that agent experience is training data. Every coding task the agent attempts, whether it succeeds or fails, teaches the model something about how code gets written in practice. This is fundamentally different from training on static code corpora or human-written instructions.

The evolution gap

Language models and coding agents are built and improved on separate timelines. Models are trained offline on static data. Agents adapt at runtime with prompts and tools. Nothing connects these two improvement cycles - until now.

Before

Models and agents evolve separately. Language models are trained on code corpora - GitHub repos, documentation, Stack Overflow. Agents are built on top of frozen models using prompt engineering, tool definitions, and scaffolding. The model never learns from the agent's experience.

Static training data. Models learn to code from existing code. But writing code is not the same as using tools, reading error messages, iterating on failing tests, or navigating a codebase. The distribution of training data does not match the distribution of agent work.

Agent improvements do not flow back. When a team builds a better coding agent - better prompts, better tool use, better error recovery - those improvements live in the agent scaffold. The underlying model does not benefit. Switch the agent framework and you lose all those gains.

After

Connected improvement loops. MiMo-Code wires the agent's experience directly into the model's training pipeline. Agent successes become positive training examples. Agent failures become learning opportunities. The model improves from real usage, not just static corpora.

Experience-grounded training data. Instead of training on code in isolation, the model learns from complete agent trajectories - the prompt, the plan, the tool calls, the error messages, the corrections, the final result. This teaches the model how coding actually works in practice.

Agent improvements compound. A better model makes a better agent. A better agent generates better training data. Better training data makes a better model. This virtuous cycle means improvements compound over time rather than plateauing.

• Why the gap exists

Training and inference are separate worlds

In most organizations, the team that trains models is separate from the team that builds agents. Different codebases, different tools, different deployment cycles. MiMo-Code bridges this by making the agent and the training pipeline part of the same system.

Reinforcement learning from agent outcomes is hard

Generating RL signals from coding tasks requires defining what success looks like - does the code compile, do tests pass, does the edit match intent. MiMo-Code's contribution is a pipeline that automates this reward signal generation from agent trajectories.

Most coding models are closed

You cannot run a co-evolution loop with a model you do not control. Closed-source models improve on their own schedule. Open weights are a prerequisite for this approach - and MiMo-Code provides them.

Get started

You can use MiMo-Code at two levels: run the pre-trained agents for coding assistance, or launch the full co-evolution pipeline to train your own improved models.

1

Clone and install dependencies

# Clone the repository
git clone https://github.com/XiaomiMiMo/MiMo-Code.git
cd MiMo-Code

# Install Node.js dependencies
npm install

# Install Python dependencies for training pipeline
pip install -r requirements.txt

MiMo-Code has two parts: the TypeScript agent (Node.js 18+) and the Python training pipeline (Python 3.10+, PyTorch 2.x). You need both if you want to run the co-evolution loop. For just using the pre-trained agent, Node.js is sufficient.

2

Configure the model backend

# Option A: Use the hosted MiMo model
export MIMO_API_KEY="your-api-key"
export MIMO_MODEL="mimo-code-7b-v2"

# Option B: Run locally with Ollama
ollama pull mimo-code:7b
export MIMO_BASE_URL="http://localhost:11434"

# Option C: Use any OpenAI-compatible endpoint
export MIMO_BASE_URL="http://your-server:8080/v1"
export MIMO_MODEL="your-model-name"

MiMo-Code supports multiple backends. The pre-trained mimo-code-7b model is the default, but you can point it at any model. The co-evolution pipeline requires a model you can fine-tune - so either a local model or an API that supports fine-tuning.

3

Run the pre-trained agent

# Start the coding agent in interactive mode
npm run agent

# Or run on a specific task
npm run agent -- --task "Add error handling to the auth module"

# Run with verbose logging to see the agent's reasoning
npm run agent -- --verbose --task "Fix the failing test in utils.test.ts"

The agent reads your codebase, plans its approach, executes edits, and verifies results. In verbose mode you can watch the full reasoning chain - helpful for understanding how the co-evolved model thinks about code differently.

4

Launch the co-evolution pipeline

# Prepare a benchmark suite of coding tasks
python scripts/prepare_tasks.py --source swebench --output tasks/

# Run agent trajectories on the task suite
python scripts/collect_trajectories.py \
  --tasks tasks/ \
  --model mimo-code-7b \
  --output trajectories/

# Train the model on collected trajectories
python scripts/train.py \
  --trajectories trajectories/ \
  --base-model mimo-code-7b \
  --output models/mimo-code-7b-v2 \
  --epochs 3 \
  --reward-model code-execution

This step requires significant compute. Collecting trajectories runs the agent on hundreds of coding tasks. Training requires GPU hardware - at minimum an A100 for the 7B model. This is the research-grade part of MiMo-Code. Most users will start with the pre-trained agent and only run the full pipeline if they need a custom-trained model.

5

Evaluate and iterate

# Run benchmarks on the new model
python scripts/evaluate.py \
  --model models/mimo-code-7b-v2 \
  --benchmark humaneval mbpp swebench

# Compare with the base model
python scripts/compare.py \
  --models mimo-code-7b models/mimo-code-7b-v2 \
  --output reports/comparison.md

The evaluation suite runs standard coding benchmarks and generates a comparison report. If the co-evolved model outperforms the base, you can start the next evolution cycle - collect new trajectories with the improved model, train again, and measure again.

Real-world use

MiMo-Code sits at the intersection of ML research and practical coding assistance. Here is where the project fits and who is paying attention.

ML Research

Model-agent interaction research. The co-evolution framework is a testbed for studying how language models and agents can improve each other. Researchers can experiment with different reward signals, trajectory collection strategies, and training schedules. The open codebase makes it possible to reproduce and extend the results without starting from scratch.

Custom Agent Training

Domain-specific coding agents. Enterprise teams with proprietary codebases can run the co-evolution loop on their own code. The agent learns the team's patterns, frameworks, and conventions. After a few cycles, the model produces code that matches the team's style more closely than a general-purpose model would.

Enterprise Customization

On-premise agent deployment. Organizations that cannot send code to external APIs can run MiMo-Code entirely on their own hardware. The open weights mean no vendor dependency. The training pipeline means the model improves from the organization's own usage - a self-improving internal tool.

Academic Study

Curriculum for AI and SE courses. The co-evolution concept bridges two active research areas - LLM training and software engineering agents. MiMo-Code provides a concrete, runnable implementation that students and researchers can study, modify, and learn from.

Benchmark Improvement

Pushing coding benchmarks forward. The co-evolutionary approach has shown improvements on HumanEval, MBPP, and SWE-bench compared to the same base model without co-evolution. Research teams can use this pipeline to explore whether the approach generalizes to other benchmarks and tasks.

In the Wild

  • ML research community interest. MiMo-Code has drawn attention from researchers working on agent-model interaction. The co-evolution concept - where agent experience feeds back into model training - is an active area of study, and MiMo-Code provides one of the first open, runnable implementations of this idea.
  • Xiaomi's growing open-source AI presence. This project is part of a broader pattern. Xiaomi has released multiple open models in 2025-2026 (MiMo-7B for reasoning, MiMo-VL for vision-language tasks) and MiMo-Code extends this to coding agents. The institutional commitment suggests continued development rather than a one-off release.
  • Fork activity suggests experimentation. With 1.3K forks in about three months, many of which appear to be research forks rather than deployment forks, the community is actively experimenting with modifications to the training pipeline, alternative reward signals, and different base models.
  • Note on maturity. Independent third-party evaluations and production deployment reports are still limited. The project is best understood as research-grade software with practical potential, not a polished product. Adoption evidence comes primarily from the repository's activity metrics and the research community's discussion, not from documented production use cases.

Watch out for

  • Significant compute requirements. The co-evolution pipeline requires serious GPU hardware. Collecting trajectories means running an agent on hundreds of coding tasks. Training even the 7B model needs at least an A100-class GPU. Running the full loop is a research-lab-scale operation, not a laptop task.
  • Research-stage maturity. MiMo-Code is a research project that ships code. The APIs may change, the documentation assumes ML fluency, and the training pipeline has rough edges. Expect to read source code, not just docs, when troubleshooting issues.
  • Xiaomi-centric documentation. Some documentation and code comments are in Chinese, and the setup guides assume familiarity with Xiaomi's model ecosystem. English documentation exists but may lag behind the Chinese version. Community translations are in progress.
  • Model sizes may not fit consumer hardware. The flagship mimo-code-7b model requires approximately 14GB of VRAM for inference and more for training. Quantized versions exist but with quality tradeoffs. Running the full co-evolution pipeline on consumer GPUs is not practical - you need datacenter-grade hardware or cloud instances.
  • Co-evolution results depend on task diversity. The quality of the co-evolved model depends heavily on the diversity and difficulty of the coding tasks used for trajectory collection. A narrow task set produces a narrow model. Curating a good task suite requires domain expertise and careful evaluation.
