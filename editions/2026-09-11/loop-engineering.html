The feedback loop, formalized

Loop engineering is the discipline of managing how AI agents iterate - retry, escalate, checkpoint, and roll back. This repo turns that discipline into a CLI, a pattern library, and a set of starter templates you can drop into any agent workflow.

● Core capabilities

CLI for feedback loops

The le CLI manages the full lifecycle of agent loops - start, pause, checkpoint, resume, and terminate. It tracks iteration counts, token usage, and elapsed time so you can see exactly what your agent is doing across each cycle.

Pattern library

Twelve battle-tested loop patterns out of the box: retry, escalate, checkpoint, rollback, fan-out, reduce, gate, timeout, backoff, approval, cascade, and tee. Each pattern is composable and ships with TypeScript types.

Starter templates

Four project scaffolds for common agent workflows: TDD loop (write tests, generate code, verify), review loop (generate, review, revise), migration loop (analyze, transform, validate), and doc loop (extract, draft, verify). Run le init --template tdd to get started.

Multi-agent support

Works with Claude Code, OpenAI Codex, and any agent that reads from stdin and writes to stdout. The integration layer is a thin adapter - add your own agent in about 20 lines of TypeScript.

Checkpoint and rollback

Every loop iteration can snapshot the working directory. If the agent breaks something, le rollback reverts to the last known-good state. Checkpoints are git-based - lightweight and diffable.

Telemetry dashboard

A local web dashboard (runs on localhost:3847) shows real-time loop progress: iteration count, token burn rate, success/fail ratio, and a timeline of agent actions. No data leaves your machine.

Single best feature

Composable loop patterns with typed contracts

The pattern library is where this repo earns its stars. Each pattern - retry, escalate, gate, and nine others - is a typed TypeScript function that wraps an agent call. You compose them like middleware: withRetry(withCheckpoint(withTimeout(agentCall, 30_000))). The types enforce correct nesting, so a gate pattern that requires human approval cannot be accidentally placed inside an unattended retry. This is not framework magic - it is plain functions with good types. You can read every pattern's source in under two minutes.

The iteration problem

AI coding agents are powerful, but they iterate blindly. Without structure around the feedback loop, agents fail silently, loop infinitely, or burn tokens solving the wrong problem. Loop engineering is the missing discipline.

// Without loop engineering

Silent failures. An agent hits an error, retries the same broken approach three times, and silently produces wrong output. You only find out when the code is already merged. There is no checkpoint, no escalation, no record of what the agent tried.

Infinite loops. The agent keeps "improving" code that was already correct, burning tokens on unnecessary iterations. Without a termination condition or iteration budget, a simple task can cost $20 in API calls before you notice.

No rollback. When an agent breaks a working file on iteration 7, you have no clean way to get back to the state at iteration 5. You end up diffing manually or restarting from scratch.

Reinventing the wheel. Every team builds its own retry logic, its own checkpoint system, its own "should I keep going?" heuristic. The same patterns get reimplemented - badly - across thousands of agent workflows.

// With loop engineering

Structured iteration. Every agent call goes through a typed pattern - retry with exponential backoff, escalate after N failures, checkpoint before destructive operations. The agent's behavior is predictable and observable.

Bounded loops. Iteration budgets, token limits, and timeout patterns prevent runaway loops. The gate pattern pauses for human approval at critical decision points. You set the boundaries once.

Git-based checkpoints. The checkpoint pattern snapshots the working directory at each iteration using lightweight git commits. Rolling back is one command: le rollback --to 5.

Shared pattern library. Twelve composable patterns cover the most common agent iteration scenarios. Import them, compose them, and move on to the actual problem your agent is solving.

● The failure modes

01 - The silent spiral

An agent generates code, runs tests, sees failures, and tries a different approach. But each new approach introduces new bugs. Without a rollback pattern, the agent cannot return to a previous working state. Without an escalation pattern, it never asks for help. The result: 15 iterations of increasingly broken code, a $12 API bill, and a pull request that does not compile.

02 - The token bonfire

A refactoring task that should take three iterations takes thirty because the agent keeps polishing code that already passes tests. There is no termination condition beyond "keep going until you feel done." Every unnecessary iteration costs tokens, time, and context window space that could be spent on actual work.

03 - The black box iteration

The agent ran for four minutes and produced a result. Was it the first attempt or the fourteenth? Did it hit errors along the way? Did it try three different approaches? Without telemetry, you have no idea how the agent arrived at its output - and no way to debug when it arrives at the wrong one.

Get the loop running

Install the CLI, scaffold a project from a starter template, configure your loop patterns, and start iterating with structure. The whole setup takes under five minutes.

1

Install the CLI

# Install globally
npm install -g loop-engineering

# Verify installation
le --version
# loop-engineering v1.4.2

The le CLI is a single Node.js binary. It requires Node 18+ and git (for checkpoint and rollback features). No other dependencies.

2

Scaffold a project

# Initialize with a starter template
le init --template tdd

# Available templates:
#   tdd      - Test-driven development loop
#   review   - Generate, review, revise cycle
#   migrate  - Analyze, transform, validate pipeline
#   doc      - Extract, draft, verify workflow

# Or start with a blank config
le init

The init command creates a loop.config.ts file in your project root. This file defines your loop patterns, iteration limits, and agent configuration. Each template comes with sensible defaults.

3

Configure loop patterns

// loop.config.ts
import { defineLoop, withRetry, withCheckpoint,
         withTimeout, withGate } from 'loop-engineering';

export default defineLoop({
  agent: 'claude-code',      // or 'codex', 'custom'
  maxIterations: 10,
  tokenBudget: 50_000,
  patterns: [
    withCheckpoint({ every: 2 }),  // snapshot every 2 iters
    withRetry({ maxRetries: 3, backoff: 'exponential' }),
    withTimeout({ ms: 120_000 }),  // 2 min per iteration
    withGate({ on: 'destructive' }), // pause before deletes
  ],
});

Patterns compose from outside in. In this example, the gate fires first (blocking destructive operations), then the timeout wraps each attempt, then retry handles transient failures, and checkpoint snapshots after each successful pair of iterations.

4

Run your agent loop

# Start the loop with a task prompt
le start "Refactor the auth module to use JWT tokens"

# Monitor progress in real time
le status

# View the telemetry dashboard
le dashboard

# Roll back to a specific iteration
le rollback --to 3

# Resume from a checkpoint
le resume

The le start command kicks off your configured agent with the specified task. The CLI manages iteration counting, pattern application, checkpoint creation, and telemetry collection automatically. Use le status to check progress without interrupting the loop.

5

Integrate with your agent

// Custom agent adapter (about 20 lines)
import { AgentAdapter } from 'loop-engineering';

export const myAgent: AgentAdapter = {
  name: 'my-custom-agent',
  execute: async (prompt, context) => {
    // Call your agent's API here
    const result = await callMyAgent(prompt);
    return {
      output: result.text,
      tokensUsed: result.usage.total,
      status: result.success ? 'ok' : 'error',
    };
  },
};

Built-in adapters exist for Claude Code and OpenAI Codex. For other agents, implement the AgentAdapter interface - it is a single execute function that takes a prompt and returns a result. Register your adapter in loop.config.ts and you are done.

Loop patterns in practice

Where loop engineering shines - and where the community is starting to apply structured iteration to real agent workflows.

Multi-step refactoring

The core use case. Large refactoring tasks - migrating from one ORM to another, converting a codebase from callbacks to async/await, or extracting a monolith into services - are natural fits for loop engineering. The checkpoint pattern snapshots after each file is migrated, and the rollback pattern lets the agent undo a bad transformation without losing prior progress. Teams report completing migrations that previously required manual babysitting of the agent.

Test-driven agent dev

The TDD loop template. Write failing tests first, then let the agent iterate until they pass. The tdd starter template configures a loop that runs tests after each iteration, uses the retry pattern on test failures, and terminates when all tests go green. If the agent gets stuck after the configured retry limit, the escalate pattern pauses and asks for human input before continuing.

Progressive code gen

Building features incrementally. Instead of asking an agent to generate an entire feature in one shot, loop engineering breaks the task into phases: scaffold, implement, test, refine. Each phase is a loop iteration with its own success criteria. The gate pattern pauses between phases for human review, and the cascade pattern feeds output from one phase as context to the next.

Automated review cycles

Self-reviewing agents. The review starter template sets up a loop where one agent generates code and a second agent (or the same agent with a different system prompt) reviews it. Findings feed back into the next generation iteration. The tee pattern runs both agents in parallel, and the reduce pattern merges their outputs into a final result.

> In the Wild

  • Growing community interest. The concept of "loop engineering" as a named discipline has been gaining traction in the AI agent community since mid-2026. Cobus Greyling's writing on the topic - particularly around structured iteration patterns for coding agents - has helped crystallize the conversation around what was previously ad-hoc retry logic.
  • Agent engineering discussions. Multiple threads on developer forums and social media have debated whether loop engineering is a genuinely new practice or a rebranding of existing control flow patterns. The consensus seems to be that the value is in the composable library and CLI tooling rather than any single pattern being novel.
  • Claude Code and Codex integration. The repo's first-class support for Claude Code and Codex has made it a natural fit for developers already using those agents. Several community posts describe using loop-engineering to add checkpoint and rollback to their existing Claude Code workflows.
  • Early adoption signals. With 11.2K stars in roughly three months since creation, the repo has clearly struck a chord - but independent case studies and production usage reports are still sparse. The project is in the "interesting idea, early tooling" phase. Evidence of large-scale production use is thin at this point.

> Watch out for

  • Masking prompt quality issues. Loop patterns like retry and escalate can paper over bad prompts. If your agent needs 8 retries to produce working code, the fix might be a better prompt - not a more sophisticated retry strategy. Loop engineering is not a substitute for good prompt engineering.
  • Overhead on simple tasks. Setting up a loop.config.ts, configuring patterns, and running the CLI adds friction to tasks that an agent can handle in one shot. For a quick "rename this variable" task, the loop engineering overhead is not worth it. The sweet spot is multi-step tasks that take 5+ iterations.
  • Pattern library learning curve. Twelve composable patterns with typed nesting rules means there is real cognitive overhead to getting started. The documentation covers each pattern individually, but the composition rules - which patterns can nest inside which - take time to internalize.
  • Young project, evolving API. Created June 9, 2026 - about three months old. The pattern API has already changed between v1.0 and v1.4, and breaking changes should be expected. Pin your version and check the changelog before upgrading.
  • Token cost amplification. Structured loops with checkpoints and retries do not reduce token usage - they can increase it. Every retry costs tokens, every checkpoint adds context. The tokenBudget config option helps set a ceiling, but be aware that loop engineering trades money for reliability.
