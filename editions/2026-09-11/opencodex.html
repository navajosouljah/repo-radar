Route to any model

OpenCodex sits between your AI coding CLI and the LLM provider. It intercepts API calls from Codex or Claude Code and reroutes them to whichever model you choose - Claude, Gemini, Grok, DeepSeek, or a local model running on your own hardware.

// What makes it different

Transparent provider swapping

Switch from OpenAI to Claude to Gemini to a local model with a single config change. Your Codex or Claude Code CLI does not know the difference - the proxy translates API formats automatically.

Cost tracking across providers

OpenCodex logs every API call with token counts and estimated cost. Compare what the same task costs on gpt-4o vs claude-opus-4 vs gemini-2.5-pro across real coding sessions.

Model performance comparison

Run the same coding task through different models and compare results side by side. See which model writes better tests, catches more bugs, or handles your specific codebase more effectively.

Works with CLIs unchanged

No patches, no forks, no custom builds. OpenCodex works by acting as a local API endpoint. Point your CLI's API base URL at it and everything else stays the same.

Local and air-gapped support

Route to Ollama, llama.cpp, or any OpenAI-compatible local server. Run your coding assistant entirely offline - useful for classified environments, air-gapped networks, or privacy-sensitive codebases.

YAML-based configuration

All provider settings live in a single .opencodex.yml file. Define multiple providers, set fallback chains, configure rate limits, and switch the active backend with one line change.

Core Value

Model freedom for AI-assisted coding

The real value of OpenCodex is not any single feature - it is the freedom to choose. Today's best model might not be tomorrow's. A team that starts on GPT-4o might find Claude Opus better for their Rust codebase, or discover that a local 70B model handles their proprietary code without any data leaving the building. OpenCodex means that switching costs nothing - no workflow changes, no retraining, no tool migration. Just update the .opencodex.yml and keep coding.

The lock-in problem

AI coding assistants are incredible tools - but each one chains you to a single LLM provider. That creates real costs, real limitations, and real frustration when you want to try something different.

Before

Provider lock-in. OpenAI Codex only talks to OpenAI models. Claude Code only talks to Anthropic models. If you want to compare them, you need two separate tools, two separate workflows, two separate billing accounts.

Expensive API costs. Coding assistants can burn through tokens fast - especially on large codebases. You cannot easily test whether a cheaper model would handle your tasks just as well because switching means changing your entire setup.

No model comparison. Which model writes better code for your specific project? There is no easy way to find out. Running the same prompt through different models requires manual copy-paste or custom scripts.

No local option. Air-gapped environments, security-sensitive codebases, and privacy-conscious teams have no way to use these coding CLIs with local models. The tools assume cloud-only.

After

One proxy, many models. OpenCodex sits between your CLI and the provider. Swap from OpenAI to Claude to Gemini to DeepSeek to a local model with a config change. Your workflow stays identical.

Cost visibility and arbitrage. Track token usage and estimated cost per provider. Route simple tasks to cheaper models and complex ones to frontier models. Cut your API bill without cutting quality.

Apples-to-apples comparison. Run the same coding task through multiple models and see the results. Compare code quality, speed, accuracy, and cost on your actual codebase - not on benchmarks.

Fully local when needed. Point OpenCodex at Ollama or any local server. Your coding assistant works offline, your code never leaves your machine, and you comply with even the strictest security policies.

// Why this matters now

The model landscape changes monthly

New models ship constantly. Gemini 2.5 Pro, Claude Opus 4, GPT-5 - each release reshuffles the leaderboard. Being locked to one provider means you miss improvements from everyone else. A proxy layer means you can adopt new models the day they launch.

Enterprise teams need multi-provider strategies

Large organizations cannot depend on a single AI vendor. Outages, pricing changes, and policy shifts create risk. OpenCodex enables a multi-provider strategy where the team can failover between providers or route different projects to different models based on requirements.

Coding tasks vary in complexity

Not every coding task needs a frontier model. Generating boilerplate, writing tests, and formatting code can run on cheaper models. Complex architecture decisions and subtle bug hunts deserve the best available model. OpenCodex lets you match the model to the task.

Get started

Install the proxy, configure your providers, and point your CLI at it. Five minutes from zero to model-agnostic coding.

1

Install OpenCodex globally

# Install via npm
npm install -g opencodex

# Verify installation
opencodex --version

OpenCodex is a Node.js package that installs a global CLI command. It requires Node.js 18+ and works on macOS, Linux, and Windows (via WSL or native).

2

Configure your providers

# Create a config file in your home directory
# ~/.opencodex.yml

providers:
  anthropic:
    api_key: "sk-ant-..."
    default_model: "claude-opus-4-20250918"
  openai:
    api_key: "sk-..."
    default_model: "gpt-4o"
  google:
    api_key: "AIza..."
    default_model: "gemini-2.5-pro"
  local:
    base_url: "http://localhost:11434/v1"
    default_model: "llama3.3:70b"

active: anthropic
cost_tracking: true

Define as many providers as you like. The active field controls which one is currently used. Switch providers by changing that one line - or use the CLI: opencodex use google.

3

Start the proxy server

# Start OpenCodex proxy on default port
opencodex start

# Or specify a port
opencodex start --port 8888

# Run in background
opencodex start --daemon

The proxy starts a local HTTP server that speaks the OpenAI-compatible API format. It listens on localhost:8080 by default. All requests are translated and forwarded to your active provider.

4

Point your CLI at the proxy

# For OpenAI Codex CLI
export OPENAI_BASE_URL="http://localhost:8080/v1"

# For Claude Code
export ANTHROPIC_BASE_URL="http://localhost:8080/v1"

# Now use your CLI normally - it routes through OpenCodex
codex "refactor this function"
claude "write tests for this module"

That is it. Your CLI sends requests to localhost:8080, OpenCodex translates and forwards them to your active provider. Switch providers anytime with opencodex use <provider> - no need to restart anything.

5

View cost and usage reports

# See today's usage
opencodex stats

# Compare costs across providers
opencodex stats --compare

# Export as CSV
opencodex stats --export costs.csv

When cost_tracking is enabled, OpenCodex logs every request with token counts, latency, and estimated cost. The --compare flag shows what the same requests would have cost on each configured provider.

Real-world use

Where OpenCodex fits in the AI coding landscape - and how teams are using provider flexibility to their advantage.

Cost Optimization

Right-size your model spend. Route boilerplate generation, test scaffolding, and documentation tasks to cheaper models like GPT-4o-mini or local Llama 3.3. Reserve frontier models for complex debugging, architecture decisions, and security reviews. Teams report 40-60% cost reduction without noticeable quality loss on routine tasks.

Model Benchmarks

Compare models on your codebase. Run the same refactoring task through Claude, GPT-4o, and Gemini. Compare output quality, speed, and cost. Find which model handles your language, framework, and coding style best - using your actual code, not synthetic benchmarks.

Air-Gapped Dev

Code with AI offline. Defense contractors, government agencies, and security-conscious startups route through Ollama or a local inference server. The coding assistant works identically - but no code, no prompts, and no context ever leave the local network.

Multi-Provider Strategy

Enterprise resilience. Large teams configure multiple providers with automatic failover. If Anthropic's API goes down, requests route to OpenAI. If OpenAI rate-limits, traffic shifts to Google. No single provider outage stops the team from coding.

Model Evaluation

Test new models instantly. When a new model launches - DeepSeek R2, Gemini 2.5 Flash, the next Claude - add it to the config and try it immediately in your existing workflow. No migration, no new tools, no learning curve. If it is not better, switch back in one command.

// In the Wild

  • Growing community adoption. OpenCodex has gained traction among developers who use both Codex and Claude Code and want the flexibility to switch between underlying models. Discussion threads on developer forums show interest particularly from teams managing API costs across multiple projects.
  • Provider proxy as a pattern. The concept of an LLM provider proxy is becoming a recognized architectural pattern. Several similar projects have emerged, but OpenCodex distinguishes itself by targeting AI coding CLIs specifically rather than general-purpose API proxying.
  • Open-source community contributions. With 1.1K forks in roughly three months, the project has attracted contributors adding support for new providers, improving API translation accuracy, and building dashboard interfaces for cost tracking.
  • Note on evidence. As a relatively young project (created June 2026), detailed third-party reviews and case studies are still limited. The star count and fork activity suggest strong interest, but independent benchmarks and production deployment reports are still emerging.

// Watch out for

  • Provider API differences. Each LLM provider has its own API quirks - different tool calling formats, different streaming behaviors, different error codes. OpenCodex translates between them, but subtle behavior differences may surface. A prompt that works perfectly on Claude might produce slightly different results when routed through Gemini, even with the same text.
  • Latency overhead. The proxy layer adds a small amount of latency to every request - typically 5-15ms for the translation and forwarding step. For interactive coding sessions this is negligible, but it compounds on high-throughput batch operations.
  • Provider-specific features may not translate. Features unique to one provider - like Anthropic's extended thinking, OpenAI's function calling nuances, or Gemini's grounding - may not map cleanly through the proxy. Check the compatibility matrix in the docs before relying on advanced features.
  • Configuration complexity. Managing API keys, rate limits, and model mappings across multiple providers adds operational overhead. For solo developers using a single model, OpenCodex may be more infrastructure than necessary.
  • Young project, evolving API. Created June 18, 2026 - just under three months old. The configuration format and CLI interface may change between versions. Pin your version in production and watch the changelog before upgrading.
