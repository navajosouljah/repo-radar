● What makes it different

browser.ts
Full browser environment

Each agent gets a real Chromium browser instance running in the sandbox. Navigate to pages, fill forms, click buttons, take screenshots, and extract content - all through a clean API. No Puppeteer setup, no browser installation.

filesystem.ts
Sandboxed file system

Agents get a writable file system within the sandbox. Read, write, and organize files without any risk to your host machine. Files persist for the session duration or across sessions in persistent mode.

isolation.ts
Network isolation by default

Each sandbox runs in its own isolated network namespace. The agent cannot reach your internal services, databases, or host network unless you explicitly open specific endpoints. Security is the default, not an afterthought.

workers.ts
Cloudflare Workers integration

Built on the Workers runtime, so you get global edge deployment, automatic scaling, and Cloudflare's infrastructure without managing servers. Spin up hundreds of sandboxes in parallel across 300+ cities.

lifecycle.ts
Ephemeral or persistent

Choose between ephemeral sandboxes that disappear after the task (great for one-off code execution) and persistent environments that maintain state between agent sessions (great for development workflows).

tools.ts
Built-in tool definitions

Ships with MCP-compatible tool definitions for browser use, file operations, code execution, and shell commands. Connect your agent and the tools are ready - no manual tool schema authoring needed.

Single Best Feature

A real computer for your agent, zero infrastructure

The defining value is that you get a full computing environment - browser, file system, network, shell - without provisioning a VM, container, or cloud instance. One API call and your agent has a machine. Another call and the machine is gone. The entire lifecycle is managed. You write agent logic, not infrastructure code. It is Functions-as-a-Service, but the "function" is an entire computer.

The sandbox problem

AI agents need to do things - run code, browse the web, manipulate files. But giving them access to your actual machine is asking for trouble. There is no standard way to give an agent a safe, isolated compute environment.

Before

Your machine is the sandbox. Most agent frameworks run code directly on the developer's machine. Your agent has access to your file system, your network, your credentials. A bad prompt injection and your ~/.ssh directory is on the internet.

DIY container management. Security-conscious teams spin up Docker containers for agent execution. But that means managing container images, handling networking, dealing with resource limits, and cleaning up after every run. It works, but it is a whole infrastructure project.

No browser without pain. Giving an agent a browser means installing Chromium, configuring Puppeteer or Playwright, handling display servers in headless environments, and dealing with memory leaks from zombie browser processes. For a "simple" web scraping task.

No standard for agent compute. Every agent framework solves sandboxing differently - or does not solve it at all. There is no shared abstraction for "give this agent a computer" that works across providers and frameworks.

After

Instant isolated environments. Call computer.spawn() and get a fully isolated sandbox in seconds. Browser, file system, network - all running on Cloudflare's edge, nowhere near your machine or your credentials.

Zero infrastructure management. No Docker files, no container orchestration, no VM provisioning. Cloudflare manages the compute, the isolation, the cleanup. You pay for what you use and nothing runs when your agent is idle.

Browser included. Every sandbox comes with a Chromium instance ready to go. Navigate, click, type, screenshot - through a clean API. No Puppeteer configuration, no display server headaches, no zombie processes.

Standard tool interface. Ships with MCP-compatible tool definitions that work with any agent framework. Whether you use Claude, GPT, or a custom agent, the tools plug in the same way.

Get started

Install the SDK, connect your Cloudflare account, and give your agent its first sandboxed computer. You will need a Cloudflare account with Workers enabled.

1

Install the SDK

# Install the Computer SDK
npm install @cloudflare/computer

# Or with yarn
yarn add @cloudflare/computer

# Or with pnpm
pnpm add @cloudflare/computer

Requires Node.js 18+. The package includes TypeScript types, the client SDK, and MCP tool definitions. No native dependencies.

2

Configure your Cloudflare account

# Log in to Cloudflare (if not already)
npx wrangler login

# Set your account ID as an environment variable
export CLOUDFLARE_ACCOUNT_ID="your-account-id"

# Or add it to your .env file
echo "CLOUDFLARE_ACCOUNT_ID=your-account-id" >> .env

You need a Cloudflare account with Workers enabled. The free tier includes a generous allocation of compute time for development. Production usage is billed based on sandbox duration and resource usage.

3

Spawn your first computer

// spawn-computer.ts
import { Computer } from "@cloudflare/computer";

const computer = new Computer({
  accountId: process.env.CLOUDFLARE_ACCOUNT_ID,
});

// Create an ephemeral sandbox
const session = await computer.spawn();

// Browse the web
const page = await session.browser.navigate("https://example.com");
console.log(await page.title());

// Write a file
await session.fs.writeFile("/tmp/hello.txt", "Hello from the sandbox!");

// Run a shell command
const result = await session.shell.exec("cat /tmp/hello.txt");
console.log(result.stdout);

// Clean up
await session.destroy();

The spawn() call creates an isolated environment in seconds. The session object gives you access to a browser, file system, and shell. Call destroy() when done - or use ephemeral mode and it cleans up automatically.

4

Connect to your agent

// Use the built-in MCP tools with your agent
import { Computer, getTools } from "@cloudflare/computer";

const computer = new Computer({
  accountId: process.env.CLOUDFLARE_ACCOUNT_ID,
});

// Get MCP-compatible tool definitions
const tools = getTools(computer);

// Pass tools to your agent framework
const response = await agent.run({
  prompt: "Go to news.ycombinator.com and summarize the top 5 stories",
  tools: tools,
});

// The agent can now browse, write files,
// and execute code in the sandbox

The getTools() function returns tool definitions compatible with MCP and most agent frameworks. Your agent gets browser, file system, and shell tools - all scoped to the sandbox.

Real-world compute

Where Cloudflare Computer fits in the agent infrastructure landscape - and the patterns emerging around sandboxed agent compute.

Safe Web Browsing

Agents that surf without risk. The most immediate use case is giving agents browser access without exposing your network. Agents can visit any URL, fill forms, extract data, and take screenshots - all inside the sandbox. A prompt injection on a malicious page cannot reach your local file system or credentials.

Code Execution

Run agent-generated code safely. When an agent writes code, you need to run it somewhere. The sandbox provides a full execution environment - install packages, compile code, run tests - without any risk to your machine. If the agent generates a rm -rf /, the sandbox eats it.

Automated Testing

Ephemeral test environments on demand. Spin up a fresh sandbox for each test run. Install dependencies, run the test suite, capture results, tear down. No test environment drift, no cleanup scripts, no shared state between runs. Each test gets a pristine machine.

Agent Dev & Debug

Watch your agent work. Persistent sandboxes let you connect to a running environment and observe what the agent is doing - inspect the browser state, read the file system, check shell history. Essential for debugging agent behavior without replaying entire conversations.

In the Wild

  • Cloudflare's agent infrastructure push. Computer is part of Cloudflare's broader entry into the agent infrastructure space, building on their Workers platform and edge network. The project positions Cloudflare as a provider of the "compute layer" for AI agents - a natural extension of their serverless platform.
  • Growing "agent compute" category. Computer enters a nascent but growing category alongside E2B, Modal, and Fly.io's agent sandboxing features. The differentiation is Cloudflare's global edge network and the integration with their existing Workers ecosystem - agents get compute in 300+ cities without additional configuration.
  • Developer community reception. The repository has attracted steady interest since its June 2026 launch, with GitHub Discussions showing active conversations around browser automation patterns, persistent sandbox use cases, and integration with various agent frameworks. Evidence of large production deployments is still limited this early.
  • MCP tool ecosystem. The built-in MCP tool definitions make Computer immediately usable with Claude and other MCP-compatible agents. Several community members have shared configurations for connecting Computer to Claude Code, though these remain informal guides rather than official integrations.

Watch out for

  • Requires a Cloudflare account. Unlike self-hosted alternatives, Computer runs on Cloudflare's infrastructure. That means signing up for their platform, agreeing to their terms, and depending on their uptime. If you need fully self-hosted agent sandboxing, this is not it.
  • Compute costs at scale. The free tier is generous for development, but production workloads that spawn hundreds of sandboxes per hour will incur meaningful costs. Sandbox duration, browser usage, and network egress all contribute to the bill. Model your expected usage before committing.
  • Cold start latency. Spawning a new sandbox is not instant. While Cloudflare has optimized the path, creating an isolated environment with a browser still takes seconds - potentially too slow for real-time interactive use cases where sub-second response is expected.
  • Browser automation complexity. Having a browser available is powerful, but web scraping and browser automation remain inherently fragile. Sites change layouts, CAPTCHAs appear, JavaScript-heavy pages load unpredictably. The sandbox solves the security problem, not the reliability problem of browser automation.
  • Young project, evolving API. Created June 2026 - three months old. The SDK surface is still evolving, documentation is growing, and best practices are being established by early adopters. Expect breaking changes and pin your dependency version.
