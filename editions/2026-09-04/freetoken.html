● What makes it different

Bandwidth-adaptive co-execution

FreeToken continuously maps computation across GPU, CPU, and system RAM based on what is actually available - not a fixed offloading strategy. It adapts in real time as resources shift.

Full-layer double-buffered prefill

Prefill streaming pipelines overlap weight transfer with compute, hiding memory bandwidth latency. The GPU never stalls waiting for the next layer's weights.

Global LRU expert caching

Hot experts stay resident in VRAM via a global LRU cache. Frequently activated experts skip the memory bus entirely - critical for interactive speeds on large MoE models.

FTW fast weight format

The custom FTW weight format optimizes on-disk and in-memory layout for MoE models. Supports MXFP4, NVFP4, FP8, and BF16 quantization with zero conversion overhead.

OpenAI and Anthropic API compatible

Serves /v1/chat/completions, /v1/responses, and /v1/messages. Point any client library at the local server - coding agents, chat UIs, and toolchains just work.

Consumer GPU range

Native support for NVIDIA RTX 30, 40, and 50 series. Run a 35B model on a laptop, a 284B model on a gaming desktop, and the 753B GLM-5.2 on a single workstation GPU.

Single best feature

290B+ models on a gaming PC at interactive speeds

The core breakthrough is making frontier-scale MoE models genuinely usable on hardware people already own. DeepSeek V4 Flash runs at 10-11 tokens/sec on a single RTX 3090 and 22-25 tokens/sec on an RTX 5090 - fast enough for real coding and conversation. FreeToken does not just fit the model in memory; it makes it interactive.

The local inference wall

MoE models like DeepSeek V4 have hundreds of billions of parameters - but most sit idle on any given forward pass. FreeToken exploits that sparsity to bring datacenter models to your desk.

Before

VRAM ceiling. A 290B model needs 100+ GB of VRAM if you load it the traditional way. Consumer GPUs top out at 16-24 GB. So you either rent a datacenter GPU or run a much smaller model.

CPU offloading is slow. Existing tools like llama.cpp and Ollama can offload layers to RAM, but the fixed strategy means generation crawls - often under 2 tokens/sec for large MoE models.

API dependency. The practical answer today is calling a cloud API. That means per-token costs, rate limits, data leaving your machine, and zero control over model availability.

After

Elastic resource mapping. FreeToken treats GPU, CPU, RAM, and PCIe as one pool. It loads only the experts needed for each token - typically 8-16 out of 256 - keeping the active set in VRAM.

Adaptive, not fixed. Instead of a static offload plan, FreeToken continuously adapts to available bandwidth. Double-buffered prefill and LRU caching keep the GPU fed without stalls.

Local API server. Point base_url at localhost and your existing OpenAI or Anthropic client code runs against a local model. No tokens billed, no data sent, no rate limits.

Get running

FreeToken runs on Linux and Windows with NVIDIA GPUs. Install via pip, download model weights, start the server, and point your client at localhost.

1

Install FreeToken

# Install via pip (Python 3.10+, CUDA 12.x)
pip install freetoken

# Or install from source for latest features
git clone https://github.com/FlashML-org/FreeToken.git
cd FreeToken && pip install -e .

Requires Python 3.10+ and an NVIDIA GPU with CUDA 12.x. Minimum 8 GB VRAM; more VRAM means more experts cached and faster generation.

2

Download model weights

# Download DeepSeek V4 Flash in FTW format
freetoken download deepseek-v4-flash --format ftw-mxfp4

# Other supported models:
# qwen3.6-35b, glm-5.2, minimax-moe
freetoken models list

FreeToken uses its own FTW weight format optimized for MoE serving. Downloads are large - budget 30-80 GB depending on the model and quantization level.

3

Start the server

# Launch FreeToken with default settings
freetoken serve deepseek-v4-flash

# Or specify host and port
freetoken serve deepseek-v4-flash --host 0.0.0.0 --port 8000

The server exposes OpenAI-compatible endpoints at /v1/chat/completions and /v1/responses, plus Anthropic-compatible endpoints at /v1/messages.

4

Connect your client

# Python - OpenAI client
from openai import OpenAI
client = OpenAI(base_url="http://localhost:8000/v1", api_key="none")
resp = client.chat.completions.create(
    model="deepseek-v4-flash",
    messages=[{"role": "user", "content": "Hello!"}]
)

# Or use curl
curl http://localhost:8000/v1/chat/completions \
  -d '{"model":"deepseek-v4-flash","messages":[{"role":"user","content":"Hi"}]}'

Any tool that speaks the OpenAI or Anthropic API works - Open WebUI, Continue, Aider, Claude Code (via Anthropic endpoint). Just change the base URL.

Watch out for

  • NVIDIA only (for now). FreeToken requires CUDA and NVIDIA GPUs. AMD support via ROCm and Apple Silicon via Metal are on the 2026 roadmap but not yet available. If you are on a Mac or AMD GPU, this is not your tool today.
  • Large downloads. Model weights in FTW format run 30-80 GB depending on model size and quantization. Budget disk space and download time accordingly.
  • RAM matters as much as VRAM. FreeToken uses system RAM as a bulk weight store. Running a 290B model on an 8 GB GPU works, but you need 64-128 GB of DDR4/DDR5 system RAM to hold the off-GPU experts. Consumer machines with 16-32 GB RAM will be limited to smaller models.
  • Young project. Created July 20, 2026 - about six weeks old. The architecture is research-backed (arXiv paper), but the codebase is evolving rapidly. Expect API changes and rough edges in edge cases.
