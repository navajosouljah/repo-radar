● What makes it different

Pure Rust, zero dependencies

No ML models, no system libraries, no network calls. The entire engine compiles to a single binary. This means it can run anywhere - including inside a Cloudflare Worker via WASM.

Byte-level format detection

AnyDoc reads the actual bytes - PDF headers, RTF open groups, OLE stream names, ZIP package mimetypes - instead of trusting file extensions. A .txt file that is secretly a .docx still converts correctly.

Unified Document model

Every format passes through the same internal Document model and GFM serializer. This guarantees consistent Markdown output regardless of input format - tables, headings, and lists map the same way.

4 language bindings

Use it from Rust natively, Node.js via npm, Python via pip, or the CLI via npx. All four share the same compiled Rust core - no performance penalty for the bindings.

Sub-5ms median performance

Benchmarked on 100 real-world documents across all 14 formats, AnyDoc achieves a 4.7ms median processing time. That is not a typo - milliseconds, not seconds.

Powers Firecrawl's /parse API

This is not a side project. AnyDoc is the production engine behind Firecrawl's hosted document parsing endpoint, processing millions of documents daily for paying customers.

Single best feature

LLM-ready Markdown without a network round-trip

The core value proposition is speed and locality. When you are building an RAG pipeline, agent workflow, or document ingestion system, sending every file to a cloud API adds latency, cost, and a privacy concern. AnyDoc converts locally in milliseconds - your data never leaves the machine. A pip install firecrawl-anydoc and one function call replaces an entire parsing microservice.

The parsing problem

Office documents are the dark matter of enterprise data. They are everywhere, they hold critical information, and they are annoyingly hard to convert into something an LLM can actually read.

Before

Tool sprawl. Pandoc for Word. LibreOffice for slides. Unstructured for PDFs. Mammoth for .docx. Each tool has its own install process, its own output quirks, its own failure modes. Your pipeline becomes a Frankenstein of converters.

Cloud-only parsing. Many modern document parsers require sending files to a hosted API. That means network latency, per-page pricing, and data leaving your infrastructure - a non-starter for regulated industries.

Inconsistent output. Different tools produce wildly different Markdown. Tables render differently, headings use different conventions, code blocks get mangled. Your downstream LLM sees garbage in, garbage out.

After

One tool, 14 formats. Drop in AnyDoc and it handles .docx, .pptx, .xlsx, .odt, .odp, .ods, .rtf, .epub, .csv, and text-layer PDFs through a single API call. One dependency, one output format.

Fully local, fully private. AnyDoc runs entirely on your machine. No API keys, no network calls, no data exfiltration risk. Ideal for healthcare, legal, and financial document pipelines.

Consistent GFM output. Every format flows through the same Document model and serializer. Tables are always GFM tables. Headings are always ATX headings. Your LLM gets predictable, clean input every time.

Get started

Pick your language and convert your first document in under a minute. No API keys, no Docker, no configuration files.

1

Install via your preferred package manager

# Node.js
npm install @firecrawl/anydoc

# Python
pip install firecrawl-anydoc

# Rust
cargo add anydoc

# CLI (no install needed)
npx @firecrawl/anydoc

Each binding wraps the same compiled Rust core. Node.js and Python ship pre-built native modules - no Rust toolchain required on your machine.

2

Convert a single file

# CLI
npx @firecrawl/anydoc convert report.docx

# Python
from anydoc import convert
md = convert("report.docx")
print(md)

The output is clean GitHub-Flavored Markdown. Tables, headings, lists, and inline formatting are all preserved.

3

Batch-convert a directory

# Convert every office file in a folder
npx @firecrawl/anydoc convert ./docs --out ./markdown

# Python - process multiple files
from pathlib import Path
from anydoc import convert

for f in Path("./docs").glob("*"):
    md = convert(str(f))
    Path(f"./markdown/{f.stem}.md").write_text(md)

AnyDoc auto-detects each file's format from its bytes. No need to specify --format flags or sort files by extension first.

4

Feed into your LLM or RAG pipeline

# Example: convert and chunk for RAG
from anydoc import convert

md = convert("quarterly_report.pptx")
chunks = md.split("\n## ")  # split on H2 headings

# Feed chunks to your embedding model
for chunk in chunks:
    embedding = embed(chunk)
    vector_store.upsert(embedding, chunk)

AnyDoc's consistent heading structure makes chunking predictable. Each slide in a .pptx becomes an H2, each sheet in an .xlsx becomes a section.

Real-world use

Where AnyDoc fits in the document processing landscape - and where the community is already putting it to work.

RAG Pipelines

Local document ingestion. Teams building retrieval-augmented generation systems use AnyDoc to convert mixed office documents into Markdown before chunking and embedding. The 4.7ms median means you can process thousands of files in seconds without a parsing bottleneck.

Agent Tooling

Give agents document eyes. AI agents that need to read uploaded files - expense reports, contracts, slide decks - use AnyDoc as a local tool call. No cloud API latency, no token-hungry screenshots. Just clean text the model can reason over.

Edge & WASM

Parse at the edge. Developers have compiled AnyDoc to WebAssembly and run it inside Cloudflare Workers. Document conversion happens at the CDN edge - no origin server needed. One developer reported processing .docx to Markdown entirely in-browser.

Compliance

Data never leaves the perimeter. Healthcare and legal teams use AnyDoc precisely because it has no network dependency. Patient records, legal briefs, and financial filings convert to Markdown without ever touching an external API.

Watch out for

  • No OCR support. AnyDoc only processes the text layer of PDFs. Scanned documents, image-heavy PDFs, and photographed pages will produce empty or minimal output. You will need Firecrawl's hosted API or a separate OCR tool for those.
  • No semantic extraction. AnyDoc gives you Markdown, not structured data. It will not extract invoice line items, form field values, or table headers as typed objects. You still need a downstream parser or LLM for that.
  • Complex layouts may simplify. Multi-column Word documents, heavily formatted spreadsheets, and slide decks with overlapping text boxes will convert to linear Markdown. Spatial layout information is lost.
  • Very young project. Created August 3, 2026 - barely one month old. The API surface may change, edge cases may lurk, and the ecosystem of third-party integrations is still forming. Pin your version.
