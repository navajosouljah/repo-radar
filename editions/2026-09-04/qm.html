● What makes it different

Per-person scoped workspaces

Each employee gets isolated memory, files, a keychain view, permissions, crons, web apps, and a durable sandbox. Teammates cannot leak into each other's context.

Multi-model, multi-harness

QM drives Pi, OpenCode, Codex, and Claude Code through the same core. Swap model providers without rewriting your deployment.

Slack and web native

Runs in Slack channels, group messages, and projects - plus a standalone web UI. Agents participate where teams already work.

Security postures

Three tiers - strict (human approval per tool call), auto (content screening), and dangerous - let you tune risk per scope and per team.

Agent-driven deployment

Rather than a 40-step runbook, QM hands the deployment itself to an agent that walks through infrastructure, credentials, and verification.

Battle-tested at YC

YC runs QM across accounting, legal, events, and engineering - including using QM to build QM itself. It is not a weekend project.

Single best feature

One company, many agents, one control plane

Most agents are designed as personal assistants - making one work for a whole company gets messy fast. QM solves the multiplayer problem: every person and every shared room gets its own scoped workspace with its own memory, files, and permissions, while the company retains a single control plane for security, auditing, and model selection. You get agent collaboration without agent chaos.

The multiplayer problem

AI agents today are single-player. Scaling an agent from one developer to a whole company means rebuilding isolation, permissions, and context from scratch. QM treats the company as the deployment unit.

Before

Personal agent, personal mess. Each employee sets up their own agent with their own API keys, their own memory, their own integrations. No shared context. No audit trail.

Slack gaps. Want an agent in your team channel? You stitch together a bot, a model API, some file storage, and a homegrown permissions layer. Every team reinvents this wheel.

No scope boundaries. One developer's agent can see another developer's secrets. Shared credentials get copy-pasted into prompts. There is no isolation model.

After

Scoped per person, shared per room. QM gives every person and every Slack channel/project its own isolated sandbox - memory, files, keychain, permissions, and crons - under one deploy.

Agent in Slack, day one. QM runs natively in Slack channels, group messages, and a web UI. No bot assembly required - just deploy and invite.

Security postures. Choose strict, auto, or dangerous per scope. The company controls what agents can do, and every action is auditable.

Get deployed

QM is self-hosted - you deploy it into your own cloud account. The CLI scaffolds the deployment repository, provisions infrastructure, and optionally wires up Slack.

1

Scaffold the deployment

# Create an org-owned deployment repository
npm exec --yes --package=@yc-software/qm@latest -- qm init .

# This scaffolds configs, provisions Postgres,
# and optionally wires up the Slack plugin

The qm init CLI creates the deployment repo, sets up Postgres for durable state, and walks you through Slack and web configuration.

2

Choose your cloud target

# Deploy to Fly.io (recommended for small teams)
qm deploy --target fly

# Or deploy to AWS
qm deploy --target aws

Currently Fly and AWS are supported. Each deployment runs in your own cloud account - there is no hosted version. Cost is cloud hosting plus model tokens.

3

Configure model providers

# QM supports multiple agent harnesses
# Claude Code, Pi, OpenCode, Codex
# Configure your preferred provider:
qm config set model-provider anthropic
qm config set api-key $ANTHROPIC_API_KEY

QM is model-agnostic. Pi, OpenCode, Codex, and Claude Code all drive the same core - your deployment is not locked to a single vendor.

4

Invite your team

# Add team members and assign security postures
qm team add --email team@company.com --posture auto

# Each person gets scoped memory, files, and permissions
# Collaborate in shared Slack channels or projects

Each person gets their own isolated workspace. They can work solo or collaborate with the agent in shared channels. Security postures (strict, auto, dangerous) are set per scope.

Real-world plays

QM is designed for startups and mid-sized companies with 10 to 500 people - any team that needs agents working across departments, not just in engineering.

Accounting
& Legal

Cross-functional agent ops. YC itself runs QM across accounting, legal, events, and engineering. The same agent harness handles invoice processing, contract review, event logistics, and code generation - each department scoped independently.

Slack-native
workflows

Agent in every channel. Drop QM into a Slack channel and the agent joins the conversation. Team members collaborate with the agent in real time - no context switching to a separate tool. Shared rooms maintain their own memory and file context.

Multi-model
strategy

Avoid vendor lock-in. Run Claude Code for code generation, Pi for internal docs, and OpenCode for infrastructure - all under one QM deployment. Swap providers without rewriting integrations or losing workspace state.

30-day
pilot

Bounded evaluation. QM is best deployed as a time-boxed pilot with a narrow workflow. Start with one team, one use case, and one security posture. Expand after proving value - the scoped workspace model makes gradual rollout natural.

Watch out for

  • Not turnkey SaaS. QM is self-hosted with no managed offering. You need at least one platform engineer to deploy, maintain, and troubleshoot. Cloud costs and model tokens are on you.
  • Young codebase. Created July 29, 2026 - barely five weeks old. Expect rough edges, breaking changes, and gaps in documentation. It is production-tested at YC but may not match your environment.
  • Security posture trust. The dangerous posture runs agent actions without human review. Use it only in sandboxed, low-risk scopes. The strict posture adds friction - find the right balance for your team.
  • Slack dependency. While QM has a web UI, the strongest integration is with Slack. If your team lives in Teams, Discord, or another platform, the Slack-native workflow advantage disappears.
