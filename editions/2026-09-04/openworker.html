● What makes it different

Results, not conversations

Ask OpenWorker to prepare a customer brief and it hands you a polished document on disk. Ask it to reschedule your afternoon and it actually moves the calendar entries. The output is finished work, not a chat transcript you have to act on yourself.

Model-agnostic architecture

Bring your own API key for OpenAI, Anthropic, Google, DeepSeek, Mistral, Grok, or run fully local with Ollama. Built on Andrew Ng's aisuite - a unified API layer across LLM providers.

Four-tier security model

Instead of approve-everything or trust-everything, OpenWorker sorts actions into four risk tiers: read local files, write files, execute code, call external services. You approve the tier once and the agent works within those guardrails.

25+ built-in connectors

GitHub, Slack, Jira, Notion, Linear, HubSpot, Outlook, Gmail, Google Calendar, and more. Each connector is a native integration - not a browser automation hack.

MCP server support

Point OpenWorker at any MCP server to extend its tool surface. If a tool exists as an MCP endpoint, OpenWorker can call it - no custom integration code needed.

Built-in security agents

After the initial launch, users discovered cybersecurity as a strong use case. OpenWorker now ships with built-in agents for code vulnerability scanning, supply chain injection detection, and cloud configuration auditing.

Single best feature

Local-first, model-agnostic agent that actually does the work

The core proposition is simple: instead of chatting about what to do, OpenWorker does it. It runs on your machine, uses whatever LLM you choose, and delivers finished artifacts - a drafted report, a sent Slack message, a reorganized calendar. The four-tier security model means it is not an uncontrolled script runner, but it is also not the "approve every keystroke" pattern that makes most agent tools unusable.

The last-mile problem

AI can reason, plan, and generate text. But getting from "the model said what to do" to "the work is actually done" still requires a human to copy, paste, click, and send. OpenWorker closes that gap.

Before

Chat transcripts, not deliverables. You ask an LLM to prepare a meeting brief. It gives you a wall of text in a chat window. You copy it, paste it into a doc, format it, and save it. The AI did the thinking. You did the work.

Model lock-in. Most agent tools are tied to a single model provider. Want to switch from GPT to Claude? Rewrite your prompts, retool your integrations, retest everything. Your agent workflow is vendor-captive.

All-or-nothing trust. Current agent tools either ask you to approve every single action (death by a thousand clicks) or run autonomously with no guardrails (terrifying). Neither is usable for real work.

After

Finished artifacts on disk. OpenWorker writes the document, saves the file, sends the message, updates the calendar. You get a finished deliverable, not instructions on how to make one.

Swap models freely. Built on aisuite, OpenWorker works with any major LLM provider or local model. Change your model in one config line - your tools, connectors, and workflows stay the same.

Tiered approval. Approve a risk level once, not every action. Reading files? Auto-approved. Sending a Slack message? Asks once, then proceeds for that category. Meaningful safety without the friction.

Get running

OpenWorker runs as a local desktop app with a Python backend and Tauri frontend. Clone, configure your model, and start handing off tasks.

1

Clone and install dependencies

# Clone the repository
git clone https://github.com/andrewyng/openworker.git
cd openworker

# Install Python dependencies
pip install -r requirements.txt

Requires Python 3.10+. The Tauri desktop app is optional - you can also use OpenWorker from the CLI.

2

Configure your model provider

# Set your API key for your preferred provider
export OPENAI_API_KEY="sk-..."
# or
export ANTHROPIC_API_KEY="sk-ant-..."
# or run fully local with Ollama
ollama pull llama3

OpenWorker supports OpenAI, Anthropic, Google, DeepSeek, Mistral, Grok, and any Ollama-hosted model. Configure in config.yaml or via environment variables.

3

Connect your tools

# Enable integrations in config.yaml
integrations:
  slack:
    token: "xoxb-..."
  github:
    token: "ghp_..."
  google_calendar:
    credentials: "./creds.json"

# Or connect any MCP server
mcp_servers:
  - url: "http://localhost:3000/mcp"

Each integration uses its own OAuth flow or API token. Enable only the ones you need - OpenWorker's security model respects the principle of least privilege.

4

Hand off your first task

# Launch OpenWorker
python -m openworker

# Or use the CLI directly
python -m openworker --task "Prepare a customer brief
for Acme Corp using our HubSpot data and save it
as a PDF on my desktop"

OpenWorker will plan the steps, request approval for each risk tier it needs, and deliver the finished result. Check the --interactive flag to watch it work step by step.

Real-world use

How teams and individuals are putting OpenWorker to work - from sales prep to incident response to executive calendar management.

Sales Prep

Pre-meeting customer briefs. A sales rep asks OpenWorker to pull the last 90 days of HubSpot interactions, summarize open deals, and produce a one-page brief before a call. The brief lands on disk as a formatted PDF - no copy-paste, no manual research.

Incident Response

Automated incident timelines. When a Slack alert fires, OpenWorker pulls the runbook, traces the failure across linked GitHub issues and deployment logs, and assembles a timeline document. The on-call engineer gets context, not a chat message saying "something broke."

Security Ops

Vulnerability triage. After the initial release, users discovered cybersecurity was a natural fit. OpenWorker's built-in security agents scan code for vulnerabilities, check dependencies for supply chain injections, and audit cloud configurations - all from a single task prompt.

Executive Assistant

Calendar and email management. Ask OpenWorker to untangle a double-booked week and it actually reschedules the meetings - sends the calendar updates, drafts the "sorry, need to reschedule" emails, and confirms the new slots. The calendar is fixed, not described.

Watch out for

  • Desktop-first, not cloud-native. OpenWorker runs on your laptop, not on a server. Sharing agent workflows across a team means everyone installs and configures their own instance. There is no hosted version or shared workspace.
  • Python-heavy setup. The codebase is roughly 32K lines of Python across 119 files. While the Tauri app provides a nice UI, the backend requires a Python environment with substantial dependencies. Expect some setup friction.
  • Integration quality varies. The 25+ connectors are first-party but not all equally mature. Core integrations like Slack and GitHub are solid. Newer ones like HubSpot and Linear may have rougher edges and less error handling.
  • Still in open beta. Created July 20, 2026 - about six weeks old. The API, config format, and plugin system are still evolving. Breaking changes between releases are likely. Pin your version if building on top of it.
