● What makes it stand out

Desktop-as-plugin architecture

The window, tray, terminal, updates, and work profiles all integrate as a DSH plugin. The shell uses the same Cordis composition mechanism as third-party plugins - it practices what it preaches.

Built-in Community Market

Plugin discovery, details, one-click installation, and management are all built in. Browse the DSH ecosystem without leaving the app - similar to a phone's app store experience.

Cordis-powered composition

Built on the Cordis framework - hot-reload, dynamic dispose (like Rust's Drop trait), and reversible effects. Plugins contribute services and typed events to a shared context.

Profile and workspace isolation

Sessions, plugins, workspaces, model settings, and configurations live outside the application directory. Multiple profiles, multiple workflows, zero cross-contamination.

Cross-platform native bindings

Runs on macOS, Windows, and Linux via Electron with platform-specific installers. Native tray integration, system notifications, and OS-level shortcuts on each platform.

Upstream plugin compatibility

Plugins compatible with the pinned upstream DSH version work out of the box. Desktop capabilities can be composed, replaced, and evolved without forking.

Single best feature

The shell eats its own dogfood

Most desktop wrappers are inert frames around a web view. DSH Desktop registers itself as a plugin and uses the same plugin composition mechanism as everything else. The window manager, the tray icon, the updater - each is a composable service that can be swapped or extended by the community. It is the only desktop client where the desktop itself follows the "everything is a plugin" rule.

The browser-tab problem

DeepSeek Harness runs as a local web service. Without a desktop client, you are stuck managing browser tabs, remembering to start the server, and losing plugin state across restarts.

Before

Manual server start. Every time you want to use DSH, you open a terminal, run the start command, wait for it to boot, then navigate to localhost in your browser. Easy to forget, easy to break.

Lost in browser tabs. Your DSH session competes with everything else in your browser. No dedicated window, no tray icon, no system-level integration. Close the wrong tab and your context is gone.

Plugin management friction. Installing and discovering plugins means hunting through GitHub repos, copying configuration files, and restarting the server. No marketplace, no one-click installs.

After

Auto-start, always ready. DSH Desktop starts the Harness runtime automatically and opens the full interface as soon as the local runtime is ready. Launch and go.

Native desktop experience. Dedicated window, system tray, notifications, keyboard shortcuts. Your DSH session is a first-class citizen on your desktop, not a browser tab you might accidentally close.

One-click plugin marketplace. Browse, search, install, and manage plugins from a built-in community market. No terminal commands, no config file editing.

Get running

Clone the repo, install dependencies, configure your DSH instance, and launch the desktop client. Requires Node.js 18+ and a working DSH installation.

1

Clone the repository

# Clone dsh-desktop
git clone https://github.com/anywhere-labs/dsh-desktop.git
cd dsh-desktop

The repo includes the Electron shell, the dsh-plugin-desktop plugin package, and platform-specific build configs.

2

Install dependencies

# Install Node.js dependencies
npm install

# Or use yarn if you prefer
yarn install

Requires Node.js 18+. Electron and platform-specific bindings are pulled automatically.

3

Configure your DSH instance

# Copy the example config
cp .env.example .env

# Edit to point at your DSH installation
# DSH_HOME defaults to ~/.dsh
# DSH_VERSION pins the upstream version

The config controls where DSH Desktop finds its Harness runtime, which upstream version to pin, and where profiles and plugin data are stored.

4

Launch the desktop client

# Development mode with hot-reload
npm run dev

# Or build for production
npm run build
npm run start

The app starts the bundled DSH Web UI locally, loads it in a hardened Electron window, and opens the Community Market on first launch.

Real-world use

How developers and teams are using DSH Desktop to manage their DeepSeek Harness workflows with native desktop integration.

Plugin
devs

Test plugins in a real desktop context. Plugin developers use DSH Desktop as their reference environment. The built-in market shows exactly how their plugin appears to end users - from discovery to install to daily use.

Multi-profile
teams

Isolated workspaces per project. Keep client-A's plugins, model configs, and sessions completely separate from client-B's. Switch profiles without restarting, and each workspace retains its own plugin set.

Always-on
agents

Tray-resident long-running tasks. Minimize to tray and let agents work in the background. System notifications fire when tasks complete or need attention - no need to keep a browser tab visible.

Upstream
tracking

Pin and upgrade safely. Pin to a specific DSH upstream version for stability, or track the latest alpha. The desktop client manages the version lifecycle so plugin compatibility is predictable.

Watch out for

  • Alpha-grade upstream. DSH Desktop pins to @deepseek-ai/dsh@0.1.2-alpha.4. The upstream Harness is still in developer preview. Expect breaking changes, missing features, and rough edges in the plugin API.
  • Electron resource cost. Wrapping a web UI in Electron adds significant memory and CPU overhead. If you are running large models locally, the extra resource consumption may compete with inference workloads.
  • Windows installer tracked as open issue. As of late August 2026, the Windows installer and macOS stability issues are actively tracked in the issue tracker. Linux is the most stable platform currently.
  • Plugin ecosystem maturity. The Community Market exists, but the ecosystem of desktop-specific plugins is still small. Most DSH plugins target the web interface; desktop-native capabilities like tray integration are less explored.
