● What makes it different

Agent as the product

The agent is not a chatbot bolted onto a contacts table. It runs on its own deployment, on its own schedule, against its own work queue. Close the browser and it keeps going.

Evidence-priced enrichment

No tool accepts a confidence score. Tools report what they observed - crm.signature-block, github.account-identity - and a ledger prices the evidence before anything writes to a record.

Zero-key inbox sync

Without any API keys the agent reads your own threads, meetings, and signature blocks through Gmail and Calendar sync. Free, private, and the best evidence there is.

Built on Eve

Uses Vercel's filesystem-first framework for durable agents. The agent leases work off a queue, decides what to look at next, books follow-ups, and stops when its budget runs out.

Turborepo + Bun monorepo

Clean TypeScript codebase with a Turborepo monorepo running on Bun. Deploy to Vercel or self-host on your own infrastructure with full Postgres backing.

Self-hosted, no per-seat bill

MIT licensed with no open core holdback. Your customer records, email-derived evidence, and agent reasoning stay on infrastructure you control. No per-seat pricing ever.

Single best feature

Nothing about a person is guessed

The rule the agent itself never breaks. Every enrichment field traces back to observable evidence - an email signature, a GitHub profile, a calendar invite. Strong evidence writes to the record. Weak evidence becomes a suggestion a human settles. You can audit exactly how every field was arrived at, which makes the CRM trustworthy enough to let an agent run unsupervised.

The data entry trap

Sales reps spend hours typing into CRM fields that go stale the moment they are entered. AI assistants help you query the mess but do nothing to prevent it. Comp AI CRM eliminates the mess at the source.

Before

Manual data entry. Reps copy-paste from emails, LinkedIn, and meeting notes into CRM fields. Half the fields stay blank. The other half drift out of date within weeks.

AI as a chatbot overlay. Bolt-on AI features let you ask "who at Acme is my champion?" but the answer is only as good as the stale data underneath.

Enrichment black boxes. Third-party enrichment tools guess job titles from probabilistic models. You cannot audit why a field says what it says, and corrections vanish on the next sync.

After

Autonomous enrichment. The agent reads your inbox, calendar, and signature blocks. Records fill themselves in from evidence you already have, with zero manual entry.

Auditable provenance. Every field traces to a specific observation - an email header, a GitHub commit, a meeting invite. The ledger shows exactly what was observed and how it was priced.

Agent-first pipeline. The agent books its own follow-ups, spends a research budget, and stops when the budget runs out. It runs on its own schedule - not yours.

Get running

Clone the repo, start Postgres, configure your environment, and deploy. The agent works with zero API keys out of the box - optional keys unlock web research and LinkedIn lookups.

1

Clone and install

# Clone the repository
git clone https://github.com/trycompai/crm.git
cd crm

# Install dependencies with Bun
bun install

Requires Bun and Docker installed on your system.

2

Start Postgres

# Spin up Postgres via Docker Compose
docker compose up -d

# Run database migrations
bun run db:migrate

Docker Compose starts a local Postgres instance. Migrations create the schema for contacts, companies, deals, and the evidence ledger.

3

Configure environment

# Copy the example env file
cp .env.example .env

# Required: set your database URL
# Optional: add Gmail, Calendar, research API keys
# The agent works with zero keys - inbox sync is free

Without keys, the agent uses Gmail and Calendar sync to read your threads, meetings, and signature blocks. Add optional keys for web research with citations and LinkedIn identity lookups.

4

Run the dev server

# Start the development server
bun run dev

# Open http://localhost:3000

The CRM UI launches at localhost:3000. The agent deployment runs separately on Eve, leasing work off its queue and enriching records on its own schedule.

Watch out for

  • Five weeks old. Created July 31, 2026 with v1.0.0 cut days later. The codebase is young and the contributor base is small. Expect rough edges and breaking changes.
  • No hosted option. Self-hosting is the only path. You need Bun, Docker, and Postgres. There is no managed cloud version to fall back on if ops is not your thing.
  • No multi-team permissions. Skip this if you need role-based access, team hierarchies, or a mature mobile app. Those features are not built yet.
  • Eve dependency. The agent runtime is built on Vercel's Eve framework, which is itself relatively new. If Eve changes direction, the agent layer is affected.
  • No third-party app marketplace. If your workflow depends on Zapier, Slack, or calendar integrations beyond Gmail/Calendar, those connectors do not exist yet.
