Skills

A curated box of 27 agent skills for Claude Code - from test-driven development to debugging to architecture reviews.

Install Matt Pocock's skills collection and your Claude Code agent gets 27 new abilities: /tdd writes tests first, /caveman debugs with print statements, /todoist turns a task into a checklist, and 24 more - each one a focused behavior the agent follows exactly.

How does it work?

Your problem

Your AI coding agent is powerful but generic. It doesn't know your team's workflow - whether you want tests first, how you debug, or how you hand off work.

You want Claude Code to always write the test before the code, but every time you forget to say so, it writes the code first.

When it kicks in

You install the skills collection - one command - and start using the new slash commands.

npx skills@latest add mattpocock/skills installs all 27 skills. Or pick one: npx skills@latest add mattpocock/skills/tdd.

You give it

A slash command followed by your normal prompt.

/tdd Add a retry mechanism to the API client - the agent writes a failing test first, then makes it pass.

It does

Each skill injects a specific workflow into the agent's thinking. The agent follows that workflow instead of its default behavior.

  1. /tdd: writes a failing test, then writes the code to make it pass, then refactors
  2. /caveman: debugs with print statements instead of reasoning about the bug - forces the agent to observe before concluding
  3. /todoist: breaks a task into a checkbox list and works through it step by step
  4. 18 user-invoked skills and 9 that activate automatically based on what you're doing

Deepak Bagada (CEO, SaaSNext) installed the collection across 5 engineering teams: /tdd eliminated missing test suites, /diagnose cut debugging time roughly in half, handoff docs cut task resumption from 90 minutes to 15.

You get

An agent that follows your team's workflows instead of guessing what you want.

  • Consistent workflowsEvery task follows the same pattern - tests first, debugging by observation, clear handoff documentation
  • Lower AI costsOne test showed 62% fewer tokens (the units AI charges are measured in) in debugging sessions using /caveman
  • Faster PRs20-40% faster time to a correct pull request in one week-long test

What changes for me?

Without it

  • Your agent improvises a workflow each time. Sometimes it writes tests first, sometimes it doesn't. Debugging is a guessing game.
  • You write custom CLAUDE.md rules for each behavior you want, and they're hard to share across projects or teams.

With it

  • 27 pre-built workflows you can invoke by name. /tdd for test-first, /caveman for print-debugging, /todoist for checklists.
  • Skills are shareable packages: install once, use across every project.

Should I?

Great if you...

  • You use Claude Code daily and want consistent, named workflows - test-first, print-debugging, task checklists - without writing custom rules
  • You lead a team and want everyone's agent to follow the same practices

Skip it if...

  • You don't use Claude Code or a compatible AI agent - the skills need a host
  • You prefer writing your own custom rules and want full control over every prompt

Instead, you could look at

  • ECC (Everything Claude Code)261 skills and 63 sub-agents - much larger collection but also a bigger commitment. Skills focuses on 27 high-quality, focused workflows.
  • Custom CLAUDE.md rulesWrite your own rules in CLAUDE.md. More work, but fully customized to your project. Skills saves that time with pre-built, tested workflows.

Watch out for

  • Made by Matt Pocock, known for TypeScript education. This is a personal project, not a company product. He maintains it actively, but it depends on one person.
  • Not all skills are equally useful. The DevTalk review found /tdd less useful for complex UI work, while /grill-with-docs and /caveman were strong.
  • The andrew.ooo review was AI-agent-operated. The 62% token reduction number comes from a blog that is human-supervised but AI-written - weight it accordingly.
  • Skills are Markdown files. They work by injecting instructions into the agent's context. No sandboxing, no isolation - they change how the agent thinks, which is the point but also the risk.
