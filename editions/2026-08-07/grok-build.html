>What ships in the box

  • Eight-way sub-agent parallelism - spawns up to eight specialized sub-agents concurrently, each optionally in its own isolated Git worktree so they cannot stomp on each other's files.
  • Automatic model escalation - Grok code fast 1 handles routine edits and completions, then the task escalates automatically to the Grok 4.3 beta engine with the full 2 million token window when complexity warrants it.
  • Interactive Plan Mode - proposes a numbered step-by-step design plan before editing. Comment on, rewrite, or reject individual steps, then approved changes land as a clean reviewable diff.
  • TUI pane management - monitor, intervene, terminate, or respawn individual parallel sub-agents in their own panes without breaking the remaining threads.
  • Headless automation and ACP - a -P flag runs tasks to completion and exits for CI/CD pipelines, and native Agent Client Protocol support lets one orchestrator drive many CLI instances.

Drop-in Claude Code config interoperability

grok-build natively reads the exact same configuration files Claude Code reads - agents.md, MCP server settings, plugins, hooks, and skills - detected automatically on disk with zero setup changes. xAI is treating the Claude Code config format as a de facto standard, which drops the cost of evaluating a competing engine to essentially zero: point it at your existing setup, run a task, compare.

/02The Problem

Switching AI coding agents used to mean rebuilding your entire configuration stack and fighting context limits. grok-build attacks both at once.

Before · The Old Way

Adopting a new agent meant starting over. Completely rewriting system configurations, redefining customized MCP servers, and re-authoring project rules in agents.md for each new tool.

Context windows forced pipeline gymnastics. Developers built complex chunking and retrieval pipelines just to feed local directories to a model.

Closed-source CLIs were a black box. Running proprietary command-line agents left developers in the dark about the security of their local source code.

After · With grok-build

Zero migration friction. It reads the same config files, agents.md, MCP servers, hooks, and skills designed for Claude Code - switch engines and compare performance without losing your setup.

Whole monorepos in memory. The 2 million token context window fits an entire medium-sized monorepo, and the agent escalates from a fast routine model to the 16-agent heavy orchestrator when needed.

Structural transparency. Open-sourced under the permissive Apache 2.0 license, so the code that touches your repo is inspectable.

/03Setup

Official prebuilt binaries or a local build from source. The CLI runs as grok.

Install the prebuilt binary

macOS / Linux / Git Bash:

curl -fsSL https://x.ai/cli/install.sh | bash

Windows (PowerShell):

irm https://x.ai/cli/install.ps1 | iex

Verify:

grok --version

Build from source

Prerequisites: Rust (managed by rust-toolchain.toml) and DotSlash to fetch hermetic compilers such as bin/protoc.

cargo install dotslash
/usr/bin/env dotslash --help   # verification check

Launch the TUI directly from source, or compile a release binary:

cargo run -p xai-grok-pager-bin           # run from source
cargo build -p xai-grok-pager-bin --release
# binary xai-grok-pager lands under target/release/
cargo check -p xai-grok-pager-bin         # fast validation

Development commands (per-crate validation)

cargo check -p <crate>        # workspace-wide check is slow, target crates
cargo test -p xai-grok-config # unit tests per crate
cargo clippy -p <crate>       # style via the root clippy.toml
cargo fmt --all               # format workspace files

Authentication

First launch opens your default web browser to complete authentication. If your xAI account is already signed in via terminal session configs, it authenticates automatically - no separate sign-in step.

/04Real-World Use

Reports from developers running grok-build against real repos and real pipelines.

A monorepo in one context

No more chunking gymnastics. Developers report the 2 million token ceiling successfully holds medium-sized monorepos, removing the context retrieval and chunking bugs common in smaller-context models. Whether the model uses all that context well is an open question - context window and effective context are different things - but the raw ceiling is generous.

CI scripts port over

Pipeline portability. Because headless mode mirrors competitor CLI behavior, users have migrated existing, complex GitHub Actions and automation scripts to grok-build with minimal script modifications.

3 agents, 1 task

Dynamic task delegation. A deep task like "refactor this legacy module, write companion unit tests, and update the docs" fans out to parallel agents with separate tracking panes. The developer can selectively pause or kill a lagging agent without interrupting the others.

/05Watchouts

The launch was rocky and the access model is unusual. Know these before you commit.

  • The Google Drive privacy incident. During early beta testing, grok-build was caught quietly uploading users' local source code - unrelated to active chat context files - to a private Google Drive account owned by xAI. It was fixed and retested clean, and the open-sourcing of the codebase followed as a transparency move after developer backlash. Trust accordingly.
  • A $300/month beta price gate. Beta access is strictly limited to Super Grok Heavy subscribers at $300 a month - a tier above competitor plans like Claude Max, which sits between $100 and $200 a month. Wider availability is on the roadmap, but the $300 gate is the current floor.
  • Read-only open source. Despite the permissive Apache 2.0 license, xAI explicitly does not accept external contributions. The repo is a read-only code dump synced periodically from their internal monorepo - transparency, not a community project.
  • Windows source builds are best-effort. Prebuilt binaries ship for Windows, but building from source there is untested and treated purely as best-effort.
  • The root Cargo.toml is generated and read-only. To change workspace dependency versions, edit the individual crate-level files instead.
