>What ships in the box

  • Isolated multi-provider engine - four auth modes (Official Login, Official + API hybrid, Pure API with custom Base URLs, and Aggregator Providers) with weight-based routing, request/session rotation, and automatic failover.
  • Plugin store and model whitelisting unlock - CDP script injection via renderer-inject.js bypasses tier checks so plugin market downloads work without an official paid account.
  • History Session Repair - switch API keys, change provider endpoints, or modify system files, and your active and historic chats survive instead of being cleared.
  • Paste formatting fix - intercepts rich-text paste (like a copy from Microsoft Word) and strips formatting so clean plain text lands in the composer instead of an accidental file attachment.
  • Upstream Worktree - deploys a target worktree straight from the upstream tracking branch, instead of native Codex's start-from-local-HEAD behavior.
  • Interface enhancements - automated localization, scroll position recovery, dynamic chat width controls, and stepwise next-action recommendations with configurable timeout rules.

An external control layer, not a patch

Codex++ boots the official app through its own launcher and injects enhancement scripts dynamically over the Chromium DevTools Protocol. It never alters the official app's native app.asar file and never writes patches into the installation directories. Your install stays factory-clean while the running app gains a whole new feature set.

::The Problem

The official CodexApp couples everything to one login: your sessions, your plugin access, and your API bill. Codex++ pulls those apart.

Before · Stock CodexApp

Switching endpoints nuked your sessions. Moving to a custom API endpoint or aggregator often meant losing every active conversational session.

The plugin store was pay-gated. Without an official, paid ChatGPT login, developers were completely locked out of the plugin store and built-in features.

Manual provider juggling. Managing multiple API providers, token histories, and directory trees by hand was tedious overhead on every project.

After · With Codex++

Login state and query path are split. Keep the official paid login and its plugin market access, while routing the actual token-heavy model requests to cost-effective custom API providers.

Sessions survive every switch. History Session Repair retains active and historic chats across API key swaps, endpoint changes, and system file edits.

One visual manager. Providers, routing weights, failover, and directory state all live in the Manager Tool instead of scattered config files.

::Setup

Prebuilt installers from GitHub Releases for Windows x64 and both macOS architectures. No Windows ARM support.

1

Download the installer

Grab the right package from the GitHub Releases page:

CodexPlusPlus-*-windows-x64-setup.exe   # Windows (x64 only)
CodexPlusPlus-*-macos-x64.dmg           # macOS Intel
CodexPlusPlus-*-macos-arm64.dmg         # macOS Apple Silicon

On Windows: double-click the installer, accept the license agreement, install to the default location.

2

macOS Gatekeeper override

If macOS blocks the unsigned binary with a "damaged / cannot open" warning, clear the quarantine flags:

sudo xattr -rd com.apple.quarantine /Applications/Codex++\ 管理工具.app
sudo xattr -rd com.apple.quarantine /Applications/Codex++.app
3

First-time configuration

  1. Installation drops two shortcuts: Codex++ (the silent launcher) and the Codex++ Manager Tool.
  2. Open the Manager Tool first to verify application directories, config files, and path states.
  3. Under the Providers panel, add custom API keys or pick a built-in preset like SiliconFlow or DeepSeek.
  4. Run the Provider Doctor diagnostic to test active model routing.
  5. Check the History Session Repair option to protect your chats.
  6. Close the manager and boot with the Codex++ silent launcher to start coding.
4

Building from source (optional)

Frontend validation:

cd apps/codex-plus-manager
npm ci
npm run check
npm run vite:build

Rust workspace compilation:

cd ../..
cargo fmt --all -- --check
cargo test
cargo build --release

::Watchouts

Codex++ lives by injecting into someone else's app. That power comes with sharp edges worth knowing before you commit a workflow to it.

  • Domestic multimodal API failures can destroy a chat. Domestic Chinese models like DeepSeek-V4-Pro have no native image recognition or file-upload support through this routing. Upload a screenshot or attachment into one of those sessions and the system throws a fatal error or an infinite loop, permanently breaking that chat history.
  • Brittle CDP hook dependencies. Codex++ injects scripts into CodexApp's rendering interfaces over Chromium DevTools. Any official app update that changes the internal page structure can break the injected modules until a compatibility patch ships.
  • API keys are stored locally - guard them. All active API keys are saved on disk. Never publish diagnostic screenshots, raw logs, or GitHub issues that contain those paths or credentials.
  • Aggregator mode-switching flaws. Flipping between Pure API and Official Hybrid modes can occasionally cause request failures. The maintainers explicitly warn: never manually copy auth.json files between the two validation states to work around errors.
