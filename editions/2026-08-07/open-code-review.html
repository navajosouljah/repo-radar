The feature set

Deterministic smart file bundling

Divide and conquer instead of one giant diff. Related files (like message_en.properties and message_zh.properties) get grouped into a single review unit, each running as a sub-agent with isolated context for concurrent, predictable scaling.

Rules from a real incident database

Dedicated detection rules for NPE, thread-safety hazards (race conditions, missing locks, shared state mutations), XSS, and SQL injection - derived from Alibaba's internal incident data, not a generic security checklist.

Four-layer rule priority chain

First match wins: CLI override flags, then project config in the repo, then global personal config, then embedded defaults. Granular include/exclude filtering - even force-reviewing test files that are excluded by default to save tokens.

Scenario-tuned prompts and toolset

Prompt templates optimized to cut token overhead, plus a distilled toolset built from analysis of large-scale production tool-call traces - noticeably more stable execution than a generic agent toolkit.

Local web UI via ocrui

A TypeScript-based local dashboard to browse, replay, and analyze past review sessions - filter findings by repo, severity, rule, or model, with no cloud upload.

Every workflow hook you need

Global CLI, delegation inside active Claude Code or Cursor sessions as portable skills, and direct CI/CD integration with GitHub Actions, GitLab CI, GitFlic, and Gerrit.

Single best feature

Deterministic comment positioning - position drift, eliminated

An independent positioning and reflection module calculates exact line placements programmatically instead of letting the model guess. LLMs are bad at precise counting; OCR simply never asks them to count. Every finding lands on the exact line in the exact file it is about.

// The Problem

General-purpose agents are talented reviewers with three chronic failure modes on large changesets.

Before · pure LLM reviewers

Incomplete coverage. On extensive pull requests, general-purpose agents cut corners - selectively reviewing some files while silently skipping others.

Position drift. LLMs struggle with precise counting, so they drift or hallucinate line numbers, placing otherwise valid feedback on completely wrong lines.

Unstable quality. Purely natural-language-driven skills are near impossible to debug - a subtle prompt tweak can make review quality fluctuate wildly.

After · the hybrid edge

Deterministic rails. Engineering logic handles what must not go wrong: precise file selection, smart bundling, fine-grained rule matching, and independent comment positioning.

The LLM does what it does best. Dynamic code analysis, scenario-tuned reviews, and codebase context retrieval - the judgment calls, not the counting.

Drift is gone by design. Exact line placements are computed programmatically, so findings never land on the wrong line.

The root cause: a purely language-driven setup lacks hard constraints. LLMs are excellent at dynamic reasoning but fundamentally the wrong tool for deterministic counting and routing. OCR splits the labor accordingly.

// Setup

One npm install, an interactive config, and you are reviewing. Requires Git 2.41 or newer for diff generation, code search, and repository operations.

1

Install globally

npm install -g @alibaba-group/open-code-review

Cross-platform binaries are also in the GitHub Releases tab - macOS, Linux, and Windows, on both x86_64 and ARM64.

2

Configure your LLM

ocr config provider   # guided provider selection + API key entry
ocr config model      # picks the active model, auto-tests connectivity

Or set environment variables like OCR_MODEL and OCR_API_KEY manually. Works with OpenAI, Anthropic, DashScope, DeepSeek, and MiniMax.

3

Run reviews

ocr review                                  # workspace mode: staged + unstaged + untracked
ocr review --from main --to feature-branch  # branch range, merge-base semantics
ocr review --commit abc123                  # single commit
ocr review --from main --to feature-branch --resume <session-id>
4

Scan, delegate, inspect

ocr scan --path internal/agent    # full-file audit, no Git history needed
ocr delegate preview              # your active coding agent runs the review
ocr delegate rule src/main.go src/handler.go
ocr session comments --severity critical,high --json <session-id>

Delegation mode uses your active agent's own LLM context - no OCR keys required.

5

Launch the local dashboard

ocrui

Starts the local session viewer - browse, replay, and analyze past reviews, filtered by repository, severity, rule, or model.

// Watchouts

The honest trade-offs. Most are deliberate design choices, but you should know them before adopting.

  • Deliberately lower recall. The pipeline prioritizes precision over noise to prevent alert fatigue - it may miss minor style issues or edge-case defects that a noisier, purely language-driven reviewer would flag.
  • Rule-engine rigidity. Quality depends on template-engine-based rule matching. If you want open-ended, free-flowing architectural critiques rather than structured, rule-conforming feedback, the framework will feel restrictive.
  • Local-first UI, no central rollup. Telemetry, session histories, and dashboards all run locally via ocrui. Enterprises wanting aggregated team-wide metrics or centralized reporting will need extra integration work.
  • Hard Git version floor. Requires Git 2.41 or newer. Legacy Git environments can fail on diff extraction and code search.
