Subscription recycling: run it on the AI plan you already pay for

OpenWiki lets teams bypass metered API keys entirely. It can reuse an active GitHub Copilot subscription through your GitHub CLI session, or sign in through a standard web-based ChatGPT Plus/Pro subscription and run on that plan instead. A documentation agent with no new bill attached.

Code Mode vs Personal Mode

Default Code Mode documents the current repo into openwiki/. Personal Mode (openwiki personal) ingests Notion, Slack, Gmail, X/Twitter, Web Search, and Hacker News into a personal wiki under ~/.openwiki/wiki/.

LangSmith runtime tracing

In Code Mode, the official LangSmith SDK connector enriches static docs with recent runtime traces - tool calls, outcomes, and latency - so the wiki reflects how the code actually behaves, not just what it says.

Self-healing Mermaid diagrams

Embedded flowcharts, lifecycles, and ER diagrams are validated after every run. Failed diagrams become plain text fences with a comment, and later --update cycles attempt a programmatic repair.

Interactive graph visualizer

openwiki visualize serves your wiki on a loopback address and opens an interactive node graph in the browser with a side-by-side Markdown reader.

The translation bottleneck

The most frequent reader of your repository is no longer a human. Feeding human-centric docs to coding agents guarantees processing errors - the format itself is the point of failure.

Before · the generality trap
  • Readmes, wikis, and diagrams are built exclusively for human engineers: tutorials, narrative, conversational pacing.
  • To an AI coding agent, that conversational padding is noise diluting strict logical constraints and precise file paths.
  • Fed standard docs, tools like Claude Code or Copilot get lost in the prose, grab wrong variables, and misinterpret the layout.
  • The model confidently outputs broken syntax that breaks the build the moment you hit run.
After · the OpenWiki way
  • Dual citizenship: a human narrative layer plus an invisible, automated machine layer in the background.
  • Deep agents parse the unstructured codebase - commit history, comments, and PRs included.
  • Raw data becomes a dense, interconnected knowledge graph exported into rigid root files: AGENTS.md and CLAUDE.md.
  • Agents read those files as memory: pure, unambiguous context that eliminates processing errors and hallucinations.
Why it matters

Static files rot the second a team pushes new commits

Maintaining a strict technical map by hand would take a developer hours of tedious updates every week. OpenWiki runs a self-healing automation loop instead: a GitHub Actions workflow parses new code on a schedule, restructures the agent instructions, and opens a pull request with fresh documentation.

Get it running

Runs on Node.js and requires Git 2.41 or newer for repo operations. One global install, then a wizard for whichever mode you want.

1Install the CLI

npm install -g openwiki
Windows note: install with a standard Node.js package manager like npm or pnpm. Installing with bun on Windows is heavily discouraged - bun can fall back to compiling the native better-sqlite3 dependency, which requires Visual Studio Build Tools with the Desktop development with C++ workload.

2Initialize Code Mode

The wizard walks you through selecting a model provider (defaulting to OpenAI with gpt-5.6-terra), entering credentials, and generating the initial docs under ./openwiki/.

openwiki --init

3Or initialize Personal Mode

openwiki personal --init

Then authenticate connectors and ingest your data:

openwiki auth notion          # local browser OAuth flow, tokens saved to ~/.openwiki/.env
openwiki ngrok start          # ngrok tunnel for the Slack OAuth callback
openwiki ingest all           # ingest all configured sources
openwiki ingest web-search    # one source (requires TAVILY_API_KEY)

4Explore the graph

openwiki visualize                                 # serves ./openwiki on port 4321
openwiki visualize openwiki --port 4400 --no-open  # custom directory and port

5Automate updates in CI

Copy the configured workflow file (openwiki-update.yml for GitHub Actions). It tracks the last committed hash, inspects merged commits, PR descriptions, and comments, and updates only changed concepts - then opens a PR with the fresh docs.

In production

What OpenWiki actually does day to day once it is wired into a repository.

Zero-cost runs when nothing changed

OpenWiki snapshots the output directory after each run. If no codebase changes are detected on subsequent runs, it records the metadata and executes no-op runs with zero token cost and no file churn.

Git-driven documentation lifecycles

The GitHub Actions workflow runs on your schedule - once a day by default, weekly for quiet repos, or every 4 to 6 hours for repos merging hundreds of commits daily. By tracking the last committed hash, it reads merged commits, PR descriptions, and comments and updates only the changed concepts to avoid churn.

Documenting the why, not just the what

Beyond file structures, OpenWiki reads git commits, history, and comments to extract high-level business logic and engineering decisions - so agents understand why features are structured the way they are before writing code against them.

Agent alignment with zero prompting

Once initialized, OpenWiki maintains AGENTS.md and CLAUDE.md automatically. Any coding agent scanning the repo instantly detects the instructions and references the wiki pages - no manual prompting or context injection required from the developer.

Portable by format

Output is formatted into the Google Open Knowledge Format (OKF v0.1), making the generated concepts, relationships, and logs fully portable to any other OKF-compliant tool.

Read before you install

Honest caveats from the README and community coverage. None are dealbreakers, but two involve defaults you should know about.

⚠ Watch out for

  • Telemetry is on by default. OpenWiki collects anonymous, aggregate usage data on execution (brain mode, command, outcome, provider). Opt out explicitly with export OPENWIKI_TELEMETRY_DISABLED=1 or export DO_NOT_TRACK=1.
  • The visualizer needs the internet. The server runs strictly on local loopback, but graph and diagram rendering libraries load from a public CDN - you cannot explore your node graph offline.
  • Windows compilation friction. Running via the Bun package manager on Windows can hit native compilation failures unless a full Visual Studio C++ build environment is configured. Use npm or pnpm instead.
  • Rigid contribution policy. Community PRs must be restricted to a single change; PRs bundling multiple unrelated enhancements are immediately rejected and closed.
