● The architecture

Graph of agents

A reconnaissance agent maps the application and endpoints, passes context to an exploitation agent that generates targeted payloads, and a validation agent executes and confirms the exploit. Collaboration, not a linear script.

Kali Linux Docker sandbox

All offensive utilities live inside a pre-built Kali container. Agents point attacks exclusively at the target from the sandbox boundary - live exploit payloads never touch your host.

Pro red-team toolkit

Ships with Caido for HTTP interception and request manipulation, Playwright for browser exploitation (XSS, CSRF, auth bypass), and Nuclei for vulnerability scanning.

strix view dashboard

A lightweight local server bound to 127.0.0.1 on a random port opens a private, tokened web interface: live agent graph, severity breakdowns, vulnerability details, and a steering portal to redirect agents mid-run. Everything reads from local disk - no cloud uploads.

Agent-ready skills

Run npx skills add usestrix/strix to inject four skills into Claude Code, Cursor, or Codex: penetration-testing, managed-pentesting, fix-security-vulnerabilities, and ci-security-scanning.

CI/CD fail-safes

In GitHub Actions, Strix runs automatically on pull requests and exits with a non-zero code when it uncovers a vulnerability - so insecure merges get blocked programmatically before production.

The problem it solves

Security tooling has forced a bad choice: slow expensive humans, or fast noisy scanners. Strix closes the loop between the two.

Before

Alert fatigue by design. Legacy vulnerability scanners lean on static signatures, pattern matching, and SAST - inundating security and dev teams with high volumes of false positives.

Priced out of real pentesting. Small teams without budget for manual human pentesting either ignore the risk or burn hours auditing static "what-if" warnings.

Slow and unscalable. Traditional manual penetration tests are slow, highly expensive, and scale poorly.

After

Agents that actually break in. Autonomous teams of specialized AI agents navigate the application, identify vectors, and execute real-world exploits dynamically.

Proof over speculation. Strix spins up a sandbox, attacks the system to prove the vulnerability exists, and generates a working proof-of-concept exploit.

The loop closes with a patch. A one-click autofix arrives as a ready-to-merge pull request - detection, exploitation, and remediation in a single run.

Set it up

Prerequisites: a Unix-like terminal, Python 3.12 or higher, a running Docker daemon, and an active LLM provider API key.

Step 1

Install

curl -sSL https://strix.ai/install | bash

The script retrieves the latest binaries, verifies your environment, and configures base directories.

Step 2

Attach a cognitive engine

Option A - metered API key:

export STRIX_LLM="openai/gpt-5.4"
export LLM_API_KEY="your-api-key"

Option B - existing ChatGPT Plus or Pro subscription (no metered API):

strix auth login chatgpt
export STRIX_LLM="chatgpt/gpt-5.4"
strix auth status   # verifies active sign-in

Strix saves your setup parameters to ~/.strix/cli-config.json so you never re-enter them.

Step 3

Run a scan

# Scan a local codebase
strix --target ./app-directory

# Quick scan of a live target you own
strix --target https://your-app.com --scan-mode quick

# Cap API spend for the run
strix --target https://your-app.com --max-budget-usd 5

# Directories over 1,024 MB: mount instead of streaming
strix --target ./app-directory --mount

# Authenticated grey-box testing
strix --target https://your-app.com --instruction "Perform authenticated testing using credentials: user:pass"

# Headless, non-interactive (CI jobs)
strix -n --target https://your-app.com

Run strix view at any time to open the local dashboard - live agent graph, severity breakdowns, and mid-run steering.

Watch out for

Honest limits from reviewers and the docs - know them before you point Strix at anything.

Watch out for

  • Legal boundary first. Strix executes active, real-world exploitation tools. Running it against any domain, API, or server where you do not hold explicit written permission is illegal in most jurisdictions. Only scan systems you own or are authorized to test.
  • Token costs add up. Agents run non-deterministic reasoning loops - a single quick scan on a frontier model (GPT-5.4, Claude Sonnet 4.6) typically costs $3-$5 in API tokens, and deep scans run significantly higher. Use --max-budget-usd.
  • Weak local model, weak findings. Ollama and LMStudio engines are supported, but reviewers report that local models materially degrade coverage. Top-tier proprietary models remain necessary for deep results.
  • Docker is mandatory. The Kali Linux sandbox requires a running Docker daemon - real operational overhead and setup friction on locked-down machines.
  • 1,024 MB streaming cap. Local directories over 1,024 MB fail the run unless you override with --mount.
  • Not a human replacement yet. Agents still struggle with highly complex custom business-logic flaws and long multi-stage attack chains. For critical, high-risk systems, keep the professional pentester.
