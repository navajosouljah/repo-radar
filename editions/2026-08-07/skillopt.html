The feature set

Strict bounded edit operations

The optimizer never rewrites files from scratch. It is constrained to bounded add, delete, and replace edits on the markdown text - preventing chaotic or destructive prompt degradation.

Validation gate + rejection buffer

Edits are scored on a held-out validation set the optimizer has never seen. Accepted only on strict improvement; rejected edits go to a buffer that stabilizes future epochs.

skillopt-sleep nightly self-evolution

A companion engine that runs offline training loops overnight - harvesting past interaction transcripts, replaying recurring errors, and consolidating verified skills behind a held-out safety gate.

Multi-backend, multi-harness

Optimizer and target models decouple across OpenAI, Azure OpenAI, Anthropic Claude, Qwen, and MiniMax, plus local models via vLLM. Harnesses include direct chat, Codex CLI, Claude Code CLI, Copilot, Devin, and OpenClaw.

Multi-objective slow updates

Epoch-wise meta-updates generate protected markdown blocks that preserve foundational learned rules, so later iterations cannot overwrite verified reasoning steps.

Gradio WebUI dashboard

A local interface to watch live training accuracy, track edit budget behavior, and supervise cumulative API token expenditure during a run.

Single best feature

The validation gate - edits must earn their place

Every proposed edit is tested on a held-out validation dataset and saved only if it strictly improves the score. That single discipline is what turns free-form prompt fiddling into a reproducible optimization process - and the paper's ablations show removing it stalls or destroys the run.

§ The Problem

Agent customization today forces a choice between two bad options. SkillOpt is the third path.

Before · the manual bottleneck

Fine-tuning is expensive and brittle. Weight-level tuning must be repeated from scratch for every new model release.

Hand-crafted prompts are tedious. The alternative is slow, manual prompt engineering with no measurement discipline.

Unstructured self-revision regresses. When skills are evolved by free-form self-editing, LLMs struggle to improve reliably over baseline and frequently introduce regressions.

After · the SkillOpt way

The skill document is the trainable state. A separate, highly capable optimizer LLM reads the target agent's task rollouts and proposes bounded text edits to the skill markdown.

Updates survive only if validated. Strict gating on unseen data means every accepted change is a measured improvement, not a hunch.

The artifact is just markdown. A compact, deployable file that runs against unchanged target models - zero inference-time token cost, zero extra model calls.

The core reframe: you do not touch model weights at all. You rewrite the skill files your agent already uses - and let a teacher model do it under strict, scientific constraints.

§ Setup

PyPI package, editable source install, or the full WebUI - then configure a teacher, a student, and a budget.

1

Standard install

pip install skillopt
2

Developer install (editable mode)

git clone https://github.com/microsoft/SkillOpt
cd SkillOpt
pip install -e .
3

Gradio WebUI dashboard

pip install -e ".[webui]"
python -m skillopt_webui.app

Add the --host 127.0.0.1 flag to restrict the dashboard to localhost only.

4

Run a training pipeline

  1. Export your OpenAI, Azure, or Anthropic API keys as environment variables.
  2. Configure the optimizer model (the teacher that evaluates and writes prompt edits, e.g. GPT-5.5) and the target model (the student agent executing tasks).
  3. Pick one of the six built-in benchmarks (e.g. searchqa or alfworld) or write a custom adapter using the benchmark contract.
  4. Set a strict data sample limit to avoid runaway API costs, plus your epoch budget and batch size.
  5. Run the train command - the output is your optimized best_skill.md file.

Zero-shot transferability. The compiled best_skill.md (typically 300 to 2,000 tokens) transfers across model scales - a skill optimized for a smaller model improves a larger model in the same family, and skills carry cleanly between the Codex and Claude Code harnesses.

§ Watchouts

Powerful, but delicate - the constraints that make it work are also the things you must not remove.

  • Runaway token costs. Iterative multi-turn rollouts, reflections, edits, and validation tests add up fast. A strict target data sample limit is mandatory, not optional, for keeping API bills manageable.
  • Ablation fragility. The paper's ablations show stability is delicate: remove the bounded edit restrictions, the rejection buffer, or the validation gate and optimization either stalls entirely or destructively overwrites the prompt.
  • Experimental features stay hidden. Advanced v0.2.0 capabilities - multi-objective modeling, offline replay, dream-rollout controls - remain highly experimental and are deliberately kept off the default CLI flags.
  • Prompt security is your job. Because the optimizer dynamically edits prompt files, output markdown could carry optimized prompt exploits. Pair it with a safety checker like Nvidia's open-source SkillSpector before production.
