● What makes it different

Accessibility-first analysis

Improve scans your components for WCAG violations - missing ARIA labels, keyboard navigation gaps, focus management issues, color contrast problems. It does not just flag them; it generates fixed components with the right attributes already added.

Performance optimizations

Identifies unnecessary re-renders, missing memoization, heavy bundle imports, and layout thrashing. The generated replacements use React best practices - proper memo boundaries, dynamic imports where beneficial, and CSS containment.

API-compatible output

Generated components maintain your existing props interface. Improve adds new optional props for new features but never breaks existing call sites. Your app keeps working while your components get better.

Explained diffs

Every change comes with a human-readable explanation - why the change was made, what standard it addresses, and what the user-facing impact is. Review the explanation, accept the diff, done.

shadcn/ui native

Built specifically for the shadcn/ui component model - understands the copy-paste pattern, Radix primitives, Tailwind styling, and the conventions that shadcn components follow. Not a generic code transformation tool.

CLI and CI integration

Run from the command line on individual components or entire directories. Integrate into CI to get improvement suggestions on every pull request that touches UI components.

Single best feature

It writes the fix, not just the warning

Linters tell you what is wrong. Improve tells you what is wrong and hands you a corrected component. The difference between "missing aria-label on line 47" and a complete, tested replacement component with the aria-label already in place is the difference between a warning you close and a fix you ship. The explanations make code review meaningful instead of a rubber stamp.

The component quality problem

UI components accumulate technical debt silently. Accessibility gaps, performance issues, and missing features pile up because fixing them means rewriting components by hand.

Before

Accessibility is an afterthought. Components ship without proper ARIA attributes, keyboard navigation, or screen reader support. Fixing it later means touching every component manually - so it never happens.

Performance regressions creep in. Components re-render unnecessarily, load heavy dependencies synchronously, and trigger layout recalculations. Profiling finds the issues but fixing them requires deep React knowledge.

Best practices evolve. What was correct last year has new patterns now. Components written six months ago may miss new Radix primitive features, better Tailwind patterns, or updated WCAG guidelines.

After

Automated accessibility fixes. Improve generates components with correct ARIA roles, keyboard handlers, focus management, and screen reader text. Each fix references the specific WCAG criterion it addresses.

Optimized by default. Generated components include proper memoization, code splitting boundaries, and render optimization. The performance fixes come with the accessibility fixes - you do not pick one.

Current best practices applied. Improve stays current with shadcn/ui conventions, Radix updates, and React patterns. Running it periodically keeps your components aligned with the latest standards.

Set up improve

Add AI-powered component improvements to your shadcn/ui project in minutes.

1

Install the CLI

npm install -g @shadcn/improve

# Or use npx for one-off runs
npx @shadcn/improve analyze ./src/components

Improve works as a CLI tool. It reads your component files, analyzes them, and outputs improved versions alongside explanations.

2

Analyze a component

# Analyze a single component
improve analyze ./src/components/ui/button.tsx

# Analyze all components in a directory
improve analyze ./src/components/ui/

# Output includes:
#   - Current issues found
#   - Generated improved component
#   - Change explanations

The analysis runs locally using your configured AI provider. Each component gets a report with issues found and a ready-to-use replacement.

3

Apply improvements

# Review and apply changes
improve apply ./src/components/ui/button.tsx

# Apply all improvements in a directory
improve apply ./src/components/ui/ --all

# Dry run to preview changes
improve apply --dry-run ./src/components/ui/

Apply writes the improved component in place, preserving your file structure. Use dry run to preview changes before committing.

Where improve fits

Component quality is a spectrum, not a checkbox. Improve helps teams move along it continuously.

Accessibility Compliance

Meet WCAG standards without an audit. Run improve on your component library before an accessibility review. It catches the mechanical issues - missing labels, broken tab order, absent focus indicators - so your human reviewer can focus on UX patterns and user flows.

Design System Maintenance

Keep your component library current. Run improve quarterly on your full component set. It applies updated patterns from shadcn/ui, catches components that have drifted from conventions, and surfaces newly available Radix primitives.

PR Review Automation

Catch component regressions in CI. Add improve to your CI pipeline to flag accessibility and performance regressions in pull requests. The explained diffs make review comments actionable instead of vague.

Onboarding New Developers

Teach best practices through code. When a new developer writes a component, improve shows them exactly what to change and why. The explanations reference specific standards and patterns - it is like a senior reviewer that never gets tired.

Watch out for

  • AI model dependency. Analysis quality depends on the underlying AI model. Less capable models may miss subtle issues or generate incorrect fixes. Always review generated components before applying.
  • shadcn/ui specific. Improve is built for the shadcn/ui component model. It will not work well with Material UI, Chakra, Ant Design, or other component libraries that use different patterns.
  • Not a replacement for human review. Improve catches mechanical issues - accessibility attributes, performance patterns, API consistency. It does not evaluate design decisions, user experience flows, or business logic in components.
  • Generated code needs testing. Improved components should pass through your existing test suite. While improve tries to maintain API compatibility, edge cases in complex components may need manual adjustment.
