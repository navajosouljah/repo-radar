● What makes it different

Custom video DSL

Hypit defines a domain-specific language for video production. Describe edits declaratively - cuts, transitions, overlays, text, audio swaps - and the compiler turns your spec into an FFmpeg pipeline.

AI agent decomposition

Give hypit a reference video and it reverse-engineers the edit using vision models: shot boundaries, text overlays, audio segments, B-roll timing. Then it generates a plan to replicate the structure with your content.

Multi-variant batch production

The pipeline generates multiple variants in a single run - different hooks, different CTAs, different aspect ratios, different languages. One shoot, many outputs.

Plugin system for effects

Extensible via a plugin architecture for face swap, voice cloning, background removal, caption generation, and music scoring. Bring your own models or use the built-in integrations.

Monorepo with compiler core

The project ships as a TypeScript monorepo with the DSL compiler, plugin system, CLI, and reference implementations. Fork it, extend it, self-host it.

Built on FFmpeg

Under the hood, everything compiles down to FFmpeg commands. No proprietary video engine. If FFmpeg can do it, hypit can script it - and it handles the complexity of multi-pass rendering for you.

Single best feature

A programming language for video editing

The core innovation is the DSL. Instead of clicking through a timeline editor or writing raw FFmpeg commands, you describe your video edit in a declarative language that AI agents can read, write, and modify. This makes video editing composable, version-controllable, and automatable. An agent can generate a hypit script, another agent can review it, and the compiler handles the rendering. Video production becomes software engineering.

The content volume problem

Social media demands volume. Creating one video is a creative act. Creating 100 variants for A/B testing, localization, and platform optimization is a production nightmare.

Before

Manual editing does not scale. Every variant requires a human editor to open a project, swap assets, re-render, and export. Ten variants takes a day. A hundred takes a week.

Templates are too rigid. Template-based video tools let you swap text and images, but they cannot adapt the edit structure - timing, transitions, shot composition - to different content. The output looks templated.

No version control for video. Video project files are binary blobs. You cannot diff them, review them, or merge them. Collaboration happens through screen shares and Slack messages, not pull requests.

After

Declarative video specs. Write the edit once as a hypit script. Generate variants by parameterizing the inputs - different hooks, CTAs, voiceovers, aspect ratios. The compiler handles rendering.

Agent-assisted decomposition. Give hypit a reference video and it reverse-engineers the edit into a script. Modify the script to suit your brand, then batch-render variants.

Version-controlled, reviewable edits. Hypit scripts are text files. Diff them in git, review them in PRs, automate them in CI. Video production gets the same tooling as software development.

Get started

From zero to a working setup in minutes.

1

Install the CLI

npm install -g @hypit/cli

# Or clone the monorepo
git clone https://github.com/hypit-ai/hypit.git
cd hypit && npm install

The CLI requires Node.js 18+ and FFmpeg installed on your system. GPU recommended for AI-powered features like face swap and voice cloning.

2

Decompose a reference video

# Analyze a reference video
hypit decompose ./reference.mp4 --output ./spec.hyp

# The decomposer identifies:
#   - Shot boundaries and transitions
#   - Text overlays and captions
#   - Audio segments (speech, music, SFX)
#   - B-roll vs hero shots

The decomposition step uses vision and audio models to reverse-engineer the edit structure into a hypit script. Review and modify the script before rendering.

3

Render variants

# Render a single variant
hypit render ./spec.hyp --output ./output.mp4

# Batch render with parameter variations
hypit batch ./spec.hyp \
  --hooks hooks.csv \
  --voices en,es,fr \
  --ratios 16:9,9:16,1:1 \
  --output ./variants/

Batch rendering generates all combinations of your parameters. Each variant gets its own FFmpeg pipeline, parallelized across available cores.

Real-world scenarios

Where this project earns its place in your stack.

Content Team Scaling

Ship 100 variants without 100 editors. Content teams at growth-stage companies need volume for A/B testing across platforms. Hypit lets one producer define the edit structure, then batch-render variants with different hooks, CTAs, and aspect ratios. Test which opening hook gets the best retention, at scale.

Localization Pipeline

Same video, every language. Swap the voiceover, regenerate captions, adjust text overlays - all parameterized in the hypit script. A single reference video becomes a localized variant for every target market.

UGC-Style Ad Production

Authentic-looking content at agency scale. The decomposer can analyze trending UGC-style videos and extract their edit patterns - quick cuts, text overlays, reaction shots. Apply those patterns to product footage for content that feels native to the platform.

Internal Video Automation

Recurring reports and updates. Weekly product update videos, sales enablement clips, onboarding walkthroughs - any video that follows a repeatable structure can be templated as a hypit script and regenerated with fresh data.

Watch out for

  • Custom license terms. The repository's license is listed as NOASSERTION. Before using hypit in a commercial product, read the actual LICENSE file carefully. This is not a standard open-source license.
  • AI model dependencies. The full feature set (face swap, voice cloning, auto-decomposition) requires AI models that may have their own licensing terms and compute requirements. The DSL compiler itself is lightweight, but the AI features need GPU.
  • FFmpeg complexity surface. While hypit abstracts FFmpeg, complex edits can produce FFmpeg command chains that are hard to debug when they fail. Understanding FFmpeg basics helps when things go wrong.
  • Ethical considerations. Video cloning and face swapping tools have obvious misuse potential. The project's framing around "cloning viral videos" is provocative. Consider the ethical and legal implications of your use case.
