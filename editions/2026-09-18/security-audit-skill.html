● What makes it different

Multi-phase scanning architecture

The skill runs a discovery phase to map attack surface, a deep-dive phase to probe each vector, and a verification phase that independently confirms every finding. Three passes, one command.

Independent verification of every finding

Each vulnerability is re-tested from scratch by a separate verification pass. If the verifier cannot reproduce the issue, it gets dropped. This dramatically reduces false positives that plague traditional static analysis.

Machine-readable JSON output

Findings come out as structured JSON with severity, category, file location, and remediation guidance. Pipe them into CI dashboards, Jira tickets, or downstream agents for automated fixing.

Cloudflare's security pedigree

Built by the team that secures one of the internet's largest networks. The skill encodes Cloudflare's internal audit methodology - the same patterns their security engineers use on production infrastructure.

Drop-in agent skill

Install it as a skill in Claude Code, Codex, or any compatible harness. No external services, no API keys, no SaaS dependency. The skill runs entirely through your agent's existing capabilities.

OWASP coverage out of the box

Default scan profiles cover OWASP Top 10, common injection vectors, auth bypass patterns, and secrets exposure. Custom profiles let you add domain-specific checks for your stack.

Single best feature

Verified findings only - no alert fatigue

The killer differentiator is the independent verification phase. Most security scanners blast you with hundreds of potential issues, most of which are false positives. This skill only reports findings that a separate verification pass confirmed are real. When it says you have a vulnerability, you have a vulnerability. That changes the signal-to-noise ratio from "ignore the scanner" to "fix what it found."

The security scanning problem

Security tooling is stuck between two poles: expensive commercial scanners that overwhelm you with false positives, and manual audits that are too slow and expensive to run on every PR.

Before

Alert fatigue from static analysis. Traditional SAST tools flag hundreds of potential issues per scan. Most are false positives. Teams learn to ignore the scanner, which means real vulnerabilities get buried in noise.

Manual audits are a bottleneck. A proper security review by a human expert takes days and costs thousands. You cannot run one on every pull request. Security reviews become a gate that slows shipping.

Point-in-time snapshots. Most security scans run in CI and give you a snapshot at merge time. They do not catch vulnerabilities introduced between scans, and they do not verify that flagged issues are actually exploitable.

After

Verified findings only. The multi-phase architecture scans, verifies, and reports only confirmed vulnerabilities. If the verification phase cannot reproduce it, it does not make the report.

Agent-native, runs on every PR. Because it runs as a skill inside your existing coding agent, you can trigger it on every pull request without adding infrastructure. The agent is already there - now it also audits.

Actionable, structured output. JSON findings with severity, location, and remediation. Feed them to another agent to auto-fix, pipe them to your issue tracker, or review them in your terminal.

Install the skill

Add multi-phase security auditing to your coding agent in under two minutes. No external services, no API keys - just a skill your agent loads.

1

Clone the skill into your project

# Add the skill to your project's .claude/skills directory
git clone https://github.com/cloudflare/security-audit-skill.git \
  .claude/skills/security-audit

# Or install via the skill registry if your harness supports it
claude skill install cloudflare/security-audit-skill

The skill is a self-contained directory with a SKILL.md manifest that your coding agent reads. It works with Claude Code, Codex, and any harness that supports the skills protocol.

2

Run a security audit

# Ask your agent to run the audit
"Run a security audit on this codebase"

# Or target specific directories
"Run a security audit on src/auth and src/api"

# The skill handles the multi-phase process automatically
# Phase 1: Discovery - maps the attack surface
# Phase 2: Deep dive - probes each vector
# Phase 3: Verification - confirms each finding

The audit runs entirely through your agent. No external API calls, no cloud services. The skill provides the methodology; your agent provides the reasoning and code analysis.

3

Review and act on findings

# Findings are output as structured JSON
# Each finding includes:
#   - severity (critical/high/medium/low)
#   - category (injection, auth, secrets, etc.)
#   - file and line number
#   - description and remediation
#   - verification status (confirmed/plausible)

# Ask the agent to fix confirmed findings
"Fix all confirmed high-severity findings"

Because findings are machine-readable, you can chain the audit into your CI pipeline - run the skill, parse the JSON, fail the build if critical issues are confirmed, and optionally auto-fix with the same agent.

Threat briefs

Security-audit-skill sits at the intersection of AI-assisted development and application security. Here is where it earns its place in the stack.

PR-Level Security Gate

Catch vulnerabilities before they merge. Add the skill to your pre-merge workflow and every pull request gets a multi-phase security review. Unlike traditional SAST that floods you with warnings, the verification phase means developers only see confirmed issues. The signal-to-noise ratio makes developers actually read the findings instead of clicking "dismiss all."

Startup Security Posture

Enterprise-grade audits without the enterprise budget. Early-stage teams cannot afford $50K annual contracts with commercial security vendors. This skill gives them Cloudflare-grade methodology for the cost of their existing coding agent subscription. Run it weekly on the full codebase, or on every PR - the marginal cost is near zero.

Compliance Evidence

Machine-readable proof for SOC 2 and ISO audits. The structured JSON output with timestamps, severity classifications, and remediation status creates an auditable trail. Feed it into your compliance dashboard to show auditors that every code change gets a security review.

Agent-to-Agent Fixing

Scan and fix in one loop. Run the security audit, pipe confirmed findings to a second agent pass that implements fixes, then re-run the audit to verify the fixes hold. The machine-readable output makes this loop trivial to automate - no human parsing required between scan and fix.

  • Growing adoption in agent skill ecosystems. With 644 forks in three months, the skill is seeing significant downstream experimentation. Contributors have adapted the methodology for language-specific scanning profiles - Python web apps, Node.js APIs, and Go microservices.
  • Developer security discourse. The project has sparked discussion about whether AI-driven security scanning can replace traditional SAST tools. The consensus so far: the verification phase is genuinely novel, but the depth of analysis depends on the underlying model's capability.
  • Evidence is still emerging. As a relatively new project from a major infrastructure company, most coverage focuses on the announcement and methodology. Detailed case studies with production results are not yet widely published - check back as adoption matures.

Watch out for

  • Model capability ceiling. The skill is only as good as the coding agent running it. A less capable model will miss subtle vulnerabilities that a stronger model would catch. The verification phase helps, but it cannot verify what the discovery phase never found.
  • Not a replacement for human review. Complex business logic vulnerabilities, architectural flaws, and threat modeling require human expertise. This skill excels at pattern-matching known vulnerability classes, not at reasoning about novel attack surfaces.
  • Token cost on large codebases. Multi-phase scanning means the agent reads the codebase multiple times. On large projects, this can consume significant tokens. Scope your audits to changed files or high-risk directories to manage costs.
  • JavaScript-only skill manifest. The skill itself is written in JavaScript. While it can audit codebases in any language, extending the skill's own logic requires JavaScript knowledge.
