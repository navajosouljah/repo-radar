Your ChatGPT Pro, inside Codex

codex-chatgpt-web is a browser-based bridge that exposes your ChatGPT Web session as a local API endpoint. Point Codex at it, and your ChatGPT subscription becomes the model backend - with full context windows, tool use, streaming, and image support. Zero API quota consumed.

● What makes it different

Browser bridge architecture

A Playwright-driven browser session maintains your authenticated ChatGPT Web session and exposes it as a local OpenAI-compatible API. Codex connects to localhost and gets full model access through your existing subscription.

Zero API quota consumption

Because requests go through the web interface, not the API, no API credits are consumed. If you have a ChatGPT Pro subscription, you get Pro-tier model access for your coding agent at no additional cost.

Full feature parity

The bridge supports context, tools, streaming, and images - the same capabilities as the native API. Codex does not know or care that the backend is a web session instead of an API endpoint.

Streaming responses

Responses stream token-by-token through the bridge, so Codex sees output in real time. No waiting for the full response to complete before the agent can start processing.

Image input support

The bridge handles image uploads through the web interface, enabling vision capabilities in Codex without API-level vision access. Screenshot your UI, paste it, and your coding agent sees it.

Quick setup

Install, authenticate once via the browser popup, and point Codex at localhost. Under five minutes from clone to a working coding agent powered by your ChatGPT subscription.

Single best feature

Unlimited coding agent, no API bill

The value proposition is straightforward: if you already pay for ChatGPT Pro, codex-chatgpt-web lets you use that subscription to power Codex without any additional API spend. For developers who want a capable coding agent but do not want to manage API budgets, this is the path of least resistance. The model is the same, the capabilities are the same, but the billing is your existing flat-rate subscription.

The API cost problem

AI coding agents are powerful but expensive. API usage adds up fast when your agent reads, reasons about, and writes code across an entire codebase.

Before

API costs scale with usage. Every token your coding agent processes costs money. Large codebases, long sessions, and iterative debugging can burn through hundreds of dollars in API credits per month.

Subscription and API are separate worlds. Your ChatGPT Pro subscription gives you unlimited web access to the same models, but coding agents cannot use the web interface. You pay twice - once for chat, once for the agent.

Budget anxiety limits agent use. When every prompt has a dollar cost, developers self-censor. They avoid running the agent on large files, skip iterative debugging loops, and manually do work the agent could handle - all to control costs.

After

Flat-rate coding agent. Your existing ChatGPT subscription powers the coding agent. No per-token billing, no surprise invoices, no budget anxiety. Use the agent as much as you want.

Same model, same capabilities. ChatGPT Pro gives access to the same frontier models available through the API. The bridge provides full feature parity - context, tools, streaming, images.

Trivial setup. Clone, authenticate once, point Codex at localhost. No API key management, no billing dashboard, no usage monitoring. Just a working coding agent.

Get started

From zero to a working setup in minutes.

1

Clone and install

git clone https://github.com/miuuyy/codex-chatgpt-web.git
cd codex-chatgpt-web
npm install

Requires Node.js 18+. The project uses Playwright to drive a browser session, which it will install automatically.

2

Authenticate

npm run auth

# A browser window opens
# Log in to ChatGPT with your account
# The session is saved locally

You authenticate once. The bridge saves your session locally and reuses it. If the session expires, re-run the auth step.

3

Start the bridge and connect Codex

# Start the local API server
npm start

# In another terminal, point Codex at the bridge
export OPENAI_BASE_URL=http://localhost:3100/v1
codex

The bridge runs on localhost:3100 by default. Codex connects to it as if it were the OpenAI API. All requests route through your ChatGPT Web session.

In the Wild

  • Strong community signal. 9.3K stars and 762 forks in under two months, with active discussions (55 open issues, GitHub Discussions enabled). The project addresses a clear pain point for Codex users.
  • Active development. Daily commits through September 2026, with topics spanning ChatGPT, Codex, Playwright, and MCP integration. The maintainer is responsive to issues and feature requests.
  • Part of a broader trend. Multiple projects in this space (opencodex, codex-with-chatgpt) are bridging commercial web interfaces to coding agent harnesses. The demand for flat-rate agent access is real.
  • Production case studies are limited. Most discussion is around setup and configuration rather than long-term production use. The bridge's reliability over extended sessions is an open question in the community.

Watch out for

  • Terms of service gray area. Automating the ChatGPT web interface may or may not be permitted by OpenAI's terms of service. The project operates in a gray area. Review the terms before relying on it for production work.
  • Session stability. Browser-based bridges can break when OpenAI updates the ChatGPT web interface. Expect occasional maintenance when the UI changes. The project's active development helps, but interruptions are possible.
  • Rate limiting. ChatGPT Web has its own rate limits, especially for Pro users during peak hours. Your coding agent may hit these limits during intensive sessions, causing delays or temporary blocks.
  • No guaranteed uptime. Unlike the API, the web interface has no SLA. Outages, maintenance windows, and A/B tests on the UI can all affect the bridge's reliability.
