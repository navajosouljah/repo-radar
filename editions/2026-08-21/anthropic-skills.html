● What makes it different

Cross-platform by design

A single SKILL.md file works in Claude Code, Cursor, Gemini CLI, Codex CLI, and GitHub Copilot. Write once, use everywhere - no per-tool custom instructions.

Creative, technical, and enterprise

Skills span art, music, and design through testing, MCP server generation, and enterprise branding and document workflows. The breadth is deliberate.

skill-creator meta-skill

A skill that creates other skills. Includes an eval and testing framework so you can validate new skills systematically before deploying them.

Org-wide deployment

Enterprise teams can deploy skills across their entire organization. Shipped December 2025, this turns institutional knowledge into portable agent instructions.

Frontmatter trigger conditions

Each SKILL.md includes structured frontmatter that tells agents when to activate it. Skills fire automatically based on task context - no manual invocation needed.

De facto standard

The SKILL.md format has been adopted beyond Claude. Community-built generators, curated directories, and academic analysis all treat it as the reference format for agent instructions.

Single best feature

The SKILL.md format itself

The biggest contribution is not any individual skill - it is the format. SKILL.md has become a de facto standard for encoding domain expertise as portable agent instructions. One file works across 70+ agents, and the community has built generators, directories, and tooling around the spec. The format outlived its origin as a Claude-only feature.

The problem it solves

Before skills, every AI coding tool required its own custom instructions format. No reuse, no sharing, no way to encode domain expertise portably.

Before

Separate instructions per tool. Every AI agent had its own format for custom instructions. Moving from Claude to Cursor to Copilot meant rewriting everything from scratch.

No reusable format. Domain expertise lived in ad-hoc prompts, scattered docs, and tribal knowledge. No structured way to package and share it.

No cross-tool sharing. A team that built great workflows in one tool could not port them to another. Expertise was locked to a specific agent.

After

One format, 70+ agents. A single SKILL.md file works across Claude Code, Cursor, Gemini CLI, Codex CLI, and GitHub Copilot. Write it once.

Portable domain expertise. Encode what your team knows - code review standards, document templates, security checklists - as structured instructions any agent can load.

Org-wide deployment. Enterprise teams deploy skills across their organization. New team members get institutional expertise on day one, in whatever agent they prefer.

Set it up

Browse the repo, pick skills, drop them into your agent's skills directory. Trigger conditions handle the rest.

1

Browse and pick skills

# Browse the repo on GitHub
https://github.com/anthropics/skills

# Or use the skills CLI to search
claude skills search "code review"

The repo is organized by category - creative, technical, enterprise. Pick skills that match your workflow. The skills CLI lets you search and install directly.

2

Copy SKILL.md files to your skills directory

# Copy a skill to your local skills directory
cp code-review/SKILL.md ~/.claude/skills/code-review.md

# Or for project-scoped skills
cp code-review/SKILL.md .claude/skills/code-review.md

Skills live in .claude/skills/ at user or project level. Project-scoped skills travel with the repo so the whole team gets them.

3

Skills activate automatically

# No manual invocation needed
# Skills fire based on trigger conditions in their frontmatter

# Example trigger in a SKILL.md:
# triggers:
#   - pattern: "review.*code"
#   - file_type: "*.py"

Each SKILL.md includes trigger conditions in its frontmatter. When your task matches, the skill loads automatically. No need to remember slash commands.

Watch out for

  • Trigger unreliability. Weak or vague trigger conditions mean skills sometimes do not activate when expected. Well-written triggers are critical - the skill-creator eval helps validate them, but many community skills ship with poor triggers.
  • Model update fragility. Skills that work on one model version can break after updates. The instructions are tuned to specific model behaviors, and those behaviors shift between releases.
  • Testing gap. Before the skill-creator eval shipped, there was no systematic way to validate skill quality. Many older skills in the ecosystem were never tested against a structured eval.
  • Skill churn. The deprecated-skills HN thread suggests many community skills have short shelf lives. The format is stable, but the content inside individual skills can become outdated quickly.
