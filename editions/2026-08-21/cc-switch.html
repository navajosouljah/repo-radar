● What makes it different

Hot-switch between providers

Swap from Claude Code to Codex to Grok Build without restarting terminals or re-configuring anything. One click, new provider, same workflow.

Built-in speed test

Compare provider response times side-by-side before committing to a session. See which model is fastest for your current task type.

Visual MCP configuration

Manage MCP server configs through a GUI instead of hand-editing JSON. See all your servers, toggle them on/off, and configure parameters visually.

Bidirectional MCP sync

Changes to MCP server configs in one agent app automatically propagate to the others. No more maintaining six separate config files.

Multi-provider failover

When one provider is rate-limited or down, CC Switch automatically routes to a backup. Circuit-breaker logic prevents cascading failures.

Tauri 2 native performance

Built on Tauri 2 with a Rust backend and React frontend. The entire app ships at roughly 10MB - a fraction of Electron-based alternatives.

Single best feature

One-click provider switching

The core value is seamless context-preserving provider switches. You can start a task with Claude Code, hit a rate limit, and hot-switch to Codex or Grok Build without losing your place. No terminal restarts, no re-configuring API keys, no manual JSON edits. The switch happens in the app and the new provider picks up where the last one left off.

The problem it solves

AI coding agents each live in their own silo - separate configs, separate API key management, separate terminals. Switching between them means manual JSON editing and context loss.

Before

Config sprawl. Each AI coding tool has its own config format, API key storage, and MCP server definitions. Keeping six tools in sync means editing six different JSON files by hand.

Context-breaking switches. Swapping providers means closing one terminal, opening another, and re-establishing context. You lose your working state every time.

No visibility into performance. Which provider is fastest right now? Which is rate-limited? You have no way to compare without running separate tests in separate terminals.

After

One config, all tools. CC Switch manages API keys and MCP servers through a single visual interface. Changes sync bidirectionally across all connected agent apps.

Seamless switching. Hot-switch providers with one click. No terminal restarts, no context loss, no manual reconfiguration.

Built-in benchmarking. Speed test your providers before starting a session. See response times and availability at a glance, with automatic failover when one goes down.

Set it up

Download the desktop app or build from source. Connect your existing agent installations and start switching.

1

Download or build from source

# Option A: Download from the official site
# Visit ccswitch.io for macOS, Windows, and Linux builds

# Option B: Build from source
git clone https://github.com/farion1231/cc-switch.git
cd cc-switch
npm install
cargo tauri build

Building from source requires the Rust toolchain and Node.js. The Tauri CLI handles bundling the Rust backend with the React frontend.

2

Connect your agent installations

# Launch CC Switch - it auto-detects installed agents
# Supported agents:
#   Claude Code, Codex, OpenCode,
#   OpenClaw, Grok Build, Hermes Agent

CC Switch scans for existing agent installations and imports their configurations. You can also manually point it at agent binaries if auto-detection misses them.

3

Configure keys and MCP servers

# Use the visual interface to:
# - Add/manage provider API keys
# - Configure MCP servers across all tools
# - Set failover priorities
# - Run provider speed tests

All configuration happens through the GUI. Changes to MCP servers sync bidirectionally - edit in CC Switch or in the agent's own config, and both stay in sync.

Real-world use

How teams and individual developers are using CC Switch to manage their AI coding tool sprawl.

Cost
optimization

Provider switching for budget control. Use cheaper models for simple tasks like boilerplate generation, then switch to Claude or GPT for complex architecture decisions. CC Switch makes the swap instant - no need to reconfigure anything between tasks.

MCP
management

Centralized MCP server configs. Instead of maintaining separate MCP configurations for each coding agent, CC Switch provides a single visual interface. Add a new MCP server once and it propagates to all connected tools automatically.

Failover
routing

Automatic fallback on rate limits. When one provider hits a rate limit or goes down, CC Switch routes to the next available provider. The circuit-breaker logic prevents repeated calls to a failing endpoint.

Watch out for

  • CORS security vulnerability (Issue #1841). The local proxy used allow_origin(Any), which let any website silently use your API keys via a 1-click attack. Fixed in later versions, but the incident reveals the security surface area of routing all provider keys through one app.
  • Scope creep. CC Switch started as a simple config switcher but grew into a local proxy with format translation, failover routing, and circuit-breaker logic. The Medium piece above argues this complexity was not asked for and adds fragility.
  • No team features. CC Switch is a single-user tool with no shared state, team config propagation, or organizational management. Enterprise teams needing shared configurations will hit a wall.
  • Rapid release cadence. One patch release included 59 commits, raising stability concerns. The pace of change can make it hard to trust production stability on any given version.
  • Minimal community presence. Despite 128K stars, no Reddit or YouTube coverage was found. The gap between star count and observable community activity is worth noting.
