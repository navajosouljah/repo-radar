◆ What makes it different

Multi-source aggregation

Pulls from news APIs (NewsAPI, GDELT), social media (Twitter/X firehose, Reddit), government feeds (USGS earthquakes, CDC health alerts, NWS weather), and dark web monitors into one unified feed.

Interactive threat map

Real-time geographic visualization of events on an interactive map. Filter by category (conflict, natural disaster, health, cyber, economic), severity, and region.

Anomaly detection

ML-based anomaly detection flags unusual spikes in event frequency or geographic clustering - catching emerging situations before they hit mainstream news.

Custom alert pipelines

Define custom alert rules: "notify me when earthquake > 6.0 within 500km of Tokyo" or "flag any mention of specific keywords in government feeds." Supports webhook, email, and Slack notifications.

Historical playback

Scrub through historical event data to study how situations developed over time. Useful for post-incident analysis and pattern recognition.

Self-hosted privacy

All processing happens on your infrastructure. No data leaves your servers - critical for analysts working with sensitive intelligence requirements.

Single best feature

The feeds you cannot get elsewhere

The real value is not the dashboard itself but the aggregation layer. Worldmonitor normalizes data from 50+ sources into a common event schema with geolocation, severity scoring, and cross-referencing. Building this integration layer from scratch would take months - worldmonitor gives you the plumbing.

The problem it solves

Global situational awareness used to require Palantir-tier budgets. Individual analysts, journalists, and researchers had to manually monitor dozens of feeds across different formats and platforms.

Before

Tab overload. Analysts monitoring global events had 20+ browser tabs open - one per news source, one per government feed, one per social platform. Critical signals buried in noise.

No cross-referencing. An earthquake in one feed, an infrastructure alert in another, and social media chatter in a third - connecting them required manual correlation and institutional knowledge.

Enterprise-only tools. Platforms like Palantir, Recorded Future, and Dataminr provide this aggregation but cost six figures annually and require enterprise contracts.

After

Single pane of glass. One dashboard, 50+ sources, real-time. Filter by category, region, or severity. The tab problem is solved.

Automatic correlation. Events are geolocated and cross-referenced automatically. An earthquake triggers a check for related infrastructure alerts and social media reports in the same region.

Free and self-hosted. AGPL-licensed, runs on a single server. The Palantir-tier workflow at the cost of your own compute.

Deploy worldmonitor

Self-host the dashboard on your own infrastructure for full data sovereignty.

1

Clone and configure

git clone https://github.com/koala73/worldmonitor.git
cd worldmonitor
cp .env.example .env

# Add your API keys for data sources
# Required: at least one news API key
# Optional: Twitter/X, USGS, NWS, CDC feeds (free)

Most government feeds (USGS, NWS, CDC) are free and keyless. News APIs and social media require API keys.

2

Start the stack

# Docker Compose handles the full stack
docker compose up -d

# Stack includes:
# - Ingestion workers (Node.js)
# - Event database (PostgreSQL + PostGIS)
# - ML anomaly detection (Python)
# - Dashboard frontend (React + Mapbox)

The full stack runs on a single machine with 4GB+ RAM. Production deployments should separate the ingestion workers.

3

Configure alerts

# Access the dashboard at http://localhost:3000
# Navigate to Settings > Alert Pipelines

# Example alert rule (YAML config):
# - name: "Pacific Ring Earthquakes"
#   source: usgs
#   filter: magnitude > 5.5
#   region: pacific_ring
#   notify: [slack, email]

Alert rules are defined in YAML and hot-reloaded. Start with a few high-signal rules and tune from there.

In the Wild

  • "Open-source Palantir" framing. Multiple tech publications have described worldmonitor as "the open-source Palantir for individuals," which has driven significant interest from the OSINT community. Search "worldmonitor open source palantir" for coverage.
  • DarkWebInformer coverage. Security-focused accounts have highlighted worldmonitor's dark web monitoring capabilities, noting its ability to aggregate Tor-based feeds alongside clearnet sources. @DarkWebInformer
  • YouTube deployment tutorials. Several YouTube creators have published self-hosting walkthroughs, with the most detailed covering the full Docker Compose stack and alert configuration.
  • Thin deep usage evidence. Despite 83K stars, deep usage reports from production deployments are limited. Most public discussion focuses on the concept rather than operational experience.

Watch out for

  • API cost accumulation. While worldmonitor itself is free, the data source APIs are not. A full-featured deployment with premium news feeds and social media access can accumulate significant monthly API costs.
  • Data freshness varies. Government feeds update in near-real-time, but news and social media feeds depend on API rate limits. Expect 1-15 minute delays depending on the source.
  • AGPL license implications. AGPL requires sharing modifications if you deploy worldmonitor as a service. Enterprise teams should verify compliance with legal before internal deployment.
  • Thin community support. The project is primarily maintained by a single developer. Issue response times are inconsistent and documentation gaps exist for advanced configurations.
