● What makes it different

Skill anatomy breakdown

Dissects what makes a skill effective: trigger conditions, context requirements, output formats, and guardrails. Goes beyond "write a system prompt" to structured, testable instructions.

Anti-pattern catalog

Documents the most common mistakes in skill design: over-specification, context bloat, missing error paths, and skills that fight the model's natural behavior.

Real-world examples

Includes complete, working skill files from production agent setups - not toy examples but patterns used in actual development workflows.

Framework-agnostic

Patterns apply whether you are writing SKILL.md files for Claude Code, custom GPT instructions, Cursor rules, or any agent framework that accepts natural language configuration.

Progressive complexity

Organized from simple one-purpose skills to complex multi-step workflows, letting you start small and scale up as your needs grow.

Testing strategies

Covers how to evaluate whether a skill actually improves agent behavior - the part most skill guides skip entirely.

Single best feature

From prompt engineering to skill engineering

The guide reframes the conversation from "write better prompts" to "design better skills" - treating agent instructions as software with structure, testing, and maintenance. This mental model shift is what practitioners cite as the biggest takeaway.

The problem it solves

Everyone writes agent instructions. Almost nobody writes them well. The gap between a working prompt and an effective skill costs teams hours of debugging and inconsistent results.

Before

Ad-hoc prompts. Agent instructions written on the fly, never tested, duplicated across projects. When they break, nobody knows why.

Context overload. Skills stuffed with every possible instruction, blowing context windows and confusing models. "Just add more detail" as the default debugging strategy.

No feedback loop. No way to measure whether a skill change actually improved agent behavior. Changes made by feel, regressions caught by accident.

After

Structured skill files. Each skill has a defined anatomy: trigger, context, output format, guardrails. Testable, version-controlled, reviewable.

Minimal effective context. Skills scoped to the smallest instruction set that produces correct behavior. The guide teaches what to leave out.

Measurable quality. Testing strategies that let you evaluate skill effectiveness before deploying - catch regressions before they reach users.

Get started

Read the guide, then apply the patterns to your own agent setup.

1

Read the guide

# Clone for offline reading
git clone https://github.com/addyosmani/agent-skills.git
cd agent-skills

# Or read directly on GitHub
# The README.md is the primary document

The guide is a single comprehensive Markdown document. Start with the skill anatomy section and work through the examples.

2

Audit your existing skills

# Find your existing agent skill files
find . -name "SKILL.md" -o -name ".cursorrules" -o -name "CLAUDE.md"

# Check each one against the anti-pattern catalog
# Common issues: over-specification, missing guardrails, no exit conditions

Apply the anti-pattern checklist to your current skills. Most teams find 2-3 issues per skill file.

3

Rewrite one skill using the framework

# Structure your skill with the recommended anatomy:
# 1. Trigger - when should this skill activate?
# 2. Context - what does the agent need to know?
# 3. Output - what format should the result take?
# 4. Guardrails - what should the agent never do?
# 5. Exit - when is the skill complete?

Start with your most-used skill. Apply the full anatomy, test it, then expand to others.

Real-world use

How teams are applying agent-skills patterns to improve their development workflows.

50+ patterns

Skill template library. Teams are extracting the patterns into reusable templates for their organizations - pre-structured skill files with the anatomy already laid out, reducing the time from "I need a new skill" to a working first draft.

Code review

Review checklist for skills. Engineering teams use the anti-pattern catalog as a PR review checklist for skill file changes - the same way they review code, but for agent instructions.

Onboarding

New-hire agent training. Companies use agent-skills as required reading for engineers joining teams that use AI agents - establishing a shared vocabulary and quality bar for skill authoring.

Watch out for

  • Markdown, not code. This is a guide, not a framework or library. If you are looking for an installable tool that manages skills, this is not it.
  • Opinionated patterns. The guide reflects Osmani's experience at Google Chrome. Some patterns may not translate directly to smaller teams or different agent frameworks.
  • Fast-moving space. Agent skill formats are evolving rapidly. SKILL.md, .cursorrules, and other formats are still changing - patterns that work today may need updating.
  • No automated tooling. The testing strategies are manual. There is no linter or CI integration for validating skills against the recommended patterns.
