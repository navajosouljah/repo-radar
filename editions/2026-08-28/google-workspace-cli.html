● What makes it different

Dynamically built from Discovery Service

The CLI does not hardcode Google APIs. It reads Google's Discovery Service to generate commands, so when Google launches a new API or updates an existing one, the CLI automatically picks it up.

Unified surface for 8+ services

Drive, Gmail, Calendar, Sheets, Docs, Chat, Admin, and more - all accessible through a single, consistent command-line interface. No more juggling gcloud, gsutil, and custom scripts.

AI agent skills included

Ships with built-in agent skills that integrate with Claude Code and other agent harnesses. Your AI assistant can manage your Google Workspace directly.

Written in Rust

A Rust binary for a Google tool is notable. The choice brings fast startup, low memory usage, and a single binary with no runtime dependencies - ideal for CI/CD and automation pipelines.

Official Google project

Published under the googleworkspace org on GitHub. This is not a community wrapper - it is an official Google-maintained tool with the support and API access that implies.

Scriptable and pipeable

Designed for automation. Output is structured (JSON by default), commands are composable, and the tool plays well with shell scripts, cron jobs, and CI/CD pipelines.

Single best feature

Auto-updating API coverage via Discovery Service

The "dynamically built from Discovery Service" approach is the key differentiator. Traditional API clients go stale as the upstream API evolves. This CLI regenerates its command surface from Google's canonical API descriptions, meaning it never falls behind. When Google adds a new Sheets feature or a new Chat endpoint, the CLI supports it without a code change or release.

The fragmentation it fixes

Google Workspace has dozens of separate APIs. Automating workflows means juggling multiple SDKs, auth flows, and command-line tools. This CLI unifies them all and adds AI agent integration.

Before

API sprawl. Drive, Gmail, Calendar, Sheets - each has its own REST API, its own client library, its own auth quirks. Automating across them means writing glue code for every integration.

Stale client libraries. Google ships API updates frequently. Third-party wrappers and even official SDKs lag behind, leaving developers without access to new features until someone ships an update.

No agent integration. If your AI coding assistant needs to check your calendar or pull a file from Drive, it has to shell out to multiple tools or use raw API calls.

After

One tool. A single CLI handles Drive uploads, Gmail queries, Calendar events, Sheets data, and more. Consistent syntax, consistent auth, consistent output format.

Always current. The Discovery Service integration means the CLI always reflects Google's latest API surface. No waiting for library updates.

Agent-ready. Built-in skills let Claude Code and other agents interact with Google Workspace directly. Ask your agent to check your calendar - it just works.

Get started

Install the Rust binary, authenticate with your Google account, and start automating. Agent skills integrate with Claude Code and other harnesses automatically.

1

Install the CLI

# Install via cargo
cargo install google-workspace-cli

# Or download a prebuilt binary from GitHub releases
# Available for macOS, Linux, and Windows

Requires Rust 1.75+ for source install, or download the prebuilt binary for zero-dependency setup.

2

Authenticate

# Authenticate with your Google account
gw auth login

# For service accounts (CI/CD, automation)
gw auth service-account --key-file credentials.json

Standard OAuth flow for personal accounts, service account support for automation. Credentials are stored securely in your system keychain.

3

Start automating

# List recent Drive files
gw drive list --limit 10

# Search Gmail
gw gmail search "from:team@company.com is:unread"

# Create a Calendar event
gw calendar create "Sprint Review" \
  --date 2026-09-01 --time 14:00

# Read Sheets data as JSON
gw sheets get SPREADSHEET_ID "Sheet1!A1:D10"

Every Google Workspace service uses the same CLI pattern: gw [service] [action] [args]. Output is JSON by default, making it easy to pipe into jq or other tools.

Watch out for

  • Creator was fired from Google. The developer behind this project was let go from Google. The repo remains under the googleworkspace org, but the project's future governance is uncertain. Watch for a potential fork or maintenance handoff.
  • Enterprise OAuth restrictions. Corporate Google Workspace accounts may have admin policies that restrict OAuth scopes or service account usage. Check with your IT team before deploying.
  • Discovery Service surface is massive. The auto-generated command surface spans hundreds of endpoints. Expect a steep learning curve for the full breadth of capabilities.
  • Agent skills are a newer addition. The AI agent integration is more recent than the core CLI. Expect rough edges with complex multi-step workflows spanning multiple Google services.
