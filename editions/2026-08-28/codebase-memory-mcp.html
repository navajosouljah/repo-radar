Best feature

99% fewer tokens, same understanding

AI coding agents waste most of their token budget re-reading files they have already seen. codebase-memory-mcp indexes your code once, then serves precise answers - the function signature, its callers, its dependencies - instead of dumping entire files into context. Your agent gets the same understanding at a fraction of the cost. On large codebases, this is the difference between affordable and unusable.

The problem it solves

AI coding agents are stateless. Every session, they re-read your entire codebase. Every question, they consume thousands of tokens on files they already parsed yesterday.

Before

Token-hungry agents. Every question requires reading entire files. A simple "where is this function called?" can consume 10K+ tokens as the agent greps through your codebase.

No memory between sessions. Close your terminal, lose all context. Next session, the agent starts from scratch - re-reading, re-parsing, re-understanding the same code.

Cross-file blindness. Most agents understand one file at a time. Tracing a call chain across modules, understanding inheritance hierarchies, or finding all implementations of an interface requires manual guidance.

After

Persistent code memory. Index once, query forever. The knowledge graph persists between sessions. Your agent remembers your codebase structure from day one.

Precise, token-efficient answers. "Find all callers of processOrder()" returns exactly the call sites - not the entire files containing them. 99% fewer tokens for the same answer.

Full graph traversal. Follow imports, call chains, type hierarchies, and module dependencies across your entire codebase. The graph knows relationships the agent would take thousands of tokens to discover.

Set it up

Download one binary, configure your MCP client, and index. No build step, no dependencies, no containers.

1

Download the binary

# Download for your platform (Linux, macOS, Windows)
curl -L https://github.com/DeusData/codebase-memory-mcp/releases/latest/download/codebase-memory-mcp-linux-amd64 -o codebase-memory-mcp
chmod +x codebase-memory-mcp

Single static binary. No runtime dependencies, no package manager, no build tools. Download and run.

2

Configure your MCP client

# Add to Claude Code MCP config (~/.claude/settings.json)
{
  "mcpServers": {
    "codebase-memory": {
      "command": "./codebase-memory-mcp",
      "args": ["--project", "/path/to/your/repo"]
    }
  }
}

Works with Claude Code, Cursor, Codex, and any other MCP-compatible client. Check the docs for client-specific configuration.

3

Index and query

# First run indexes the codebase automatically
# Subsequent runs use the persistent index
# Your agent now has access to code intelligence tools:
# - find_symbol, find_callers, find_references
# - get_dependencies, get_file_structure

Initial indexing takes milliseconds for average repos. The index persists on disk - subsequent sessions start instantly.

Watch out for

  • C codebase limits contributions. The project is written in C, which limits the pool of potential contributors. Most AI-tooling developers work in Python or TypeScript. Bug reports may outnumber pull requests.
  • Dynamic languages are harder. The knowledge graph works best with statically-typed languages where symbols and calls are explicit. Python's duck typing, Ruby's metaprogramming, and JavaScript's dynamic dispatch can produce incomplete or misleading graphs.
  • MCP protocol is still maturing. The Model Context Protocol is evolving quickly. MCP server implementations may need updates as the protocol specification changes. Check compatibility with your specific client version.
  • Large monorepos need testing. "Average repo in milliseconds" is a strong claim. Monorepos with millions of lines may have different indexing and query characteristics. Benchmark on your actual codebase before committing.
