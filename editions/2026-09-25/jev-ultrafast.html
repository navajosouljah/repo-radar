jev-ultrafast

A browser-clicking AI that picks from a numbered list instead of writing paragraphs about what it sees, so it finishes in seconds instead of minutes.

Give it a goal and a starting webpage - "search Google Flights from Zurich to London" - and it clicks, types and scrolls its way there itself, finishing a real search in about 7 seconds for well under half a cent.

How does it work?

Your problem

Software that needs an AI to click through a website usually does it the slow way: take a picture of the page, ask an AI to write out what it sees and plans to do, then act on that paragraph.

jev-ultrafast's own before-and-after test needed 1,092 back-and-forth calls to the browser doing it that way, for one flight search.

When it kicks in

You run it as a one-line command with a goal and a starting page, or a script kicks it off whenever a job needs a browser.

python -m jev_ultrafast --url "https://www.google.com/travel/flights" --goal "Search for a one-way flight from Zurich to London next Friday"

You give it

A web address to start on, and your goal written in plain English.

URL: google.com/travel/flights. Goal: "Search for a one-way flight from Zurich to London next Friday."

It does

It turns the page into a numbered list of clickable things and lets TypeSafe's Jev decision AI pick the action and the number, over and over, until it's done.

  1. Reads the current page into a numbered list of buttons, links and boxes instead of taking a picture of it
  2. Sends that list plus your goal to Jev in one request; Jev picks both the action (click, type, scroll, wait or done) and which numbered item
  3. Only when it needs to type something, like a date, does a separate everyday AI write the actual words
  4. Repeats on the new page until the goal is met, or it flags itself as stuck

The Google Flights run took 17 of these decisions and 101 total browser calls to finish, instead of 1,092.

You get

A finished task, timed and priced.

  • A completed real task, not a demo trickA genuine Zurich-to-London Google Flights search, done in 7.1 seconds
  • Far fewer round trips to the browser101 browser calls instead of 1,092 for the same job - 91% fewer, and the run itself was 25% faster (9.45s down to 7.09s median)
  • A tiny bill for the whole runAbout $0.004: the equivalent of roughly 90,000 words read in at TypeSafe's $0.042-per-million price, plus $0.00006 for the two bits of text it had to type - the reply itself is free

What changes for me?

Without it

  • Screenshot every step, then wait on a vision AI to write out its reasoning before it clicks anything.
  • 1,092 back-and-forth calls to the browser for one flight search, by jev-ultrafast's own measurement of the old way.
  • Every single step bills you for a full image-reading AI call, even for a plain click.

With it

  • Reads the page as a numbered list instead of a picture; one request decides the click.
  • 101 browser calls for the same search - 91% fewer - finished in 7.1 seconds instead of 9.45.
  • About $0.004 for the whole run, because the only AI that gets paid per word is reading a short list, not a picture.

How hard is it to try?

Effort

5 minutesAbout an hourNeeds a developer
  1. Watch it work first: its website shows the real Zurich-to-London flight search finishing in 7.1 seconds. Nothing to install.
  2. To run it yourself, a developer clones the repo, runs its setup command, adds a TypeSafe API key and a text-AI key, then points it at any website with a goal written in plain English.
  3. Add the --inspector flag, documented on the GitHub page, to see every choice it makes as it makes it - useful for checking it on your own sites before trusting it with something real.

What it takes on your computer

Space on disk
About 1 MB for jev-ultrafast and the Browser Harness library it runs on combined (Browser Harness alone is 236 KB). There's no AI model to download - decisions run through TypeSafe's hosted Jev service, not on your machine.
Memory while it runs
No data found for an exact number. It doesn't load any AI model itself, so it should need little beyond what its small Python process and your already-open Chrome use.
Runs on
Mac, Windows or Linux, with Python 3.12 or newer and Chrome already installed - it connects to your own browser rather than downloading one. No graphics card needed: every decision happens through hosted APIs, not on your machine.
Source: jev-ultrafast README (setup) and the browser-harness package page on PyPI

Should I?

Great if you...

  • You're building software that needs an AI to click through websites fast and cheap, and you're fine depending on TypeSafe's paid Jev service
  • Your tasks are simple, repeatable browser jobs on ordinary pages: searches, form fills, price checks

Skip it if...

  • You need it to get through a real checkout, a "prove you're human" picture puzzle, or a page with more than about 250 clickable things - it goes blind past that point
  • You don't want a tool driving your everyday, signed-in Chrome and sending page content to TypeSafe and a second AI
  • You want something with no ongoing per-use cost - this bills you a small amount every time it runs

Instead, you could look at

  • agent-browserVercel's free, open browser-automation tool for AI agents: a fast command-line tool rather than a full decision-making agent, and it doesn't depend on a paid decision AI to pick each click.
  • TypeSafe JevThe paid decision AI jev-ultrafast is built on. Using it directly means writing your own browser-control code instead of getting jev-ultrafast's ready-made loop.

Is it safe?

PASSED
  • Security advisories: 0GitHub's advisory list, checked Sep 27
  • Searches for CVEs, vulnerabilities, malware and scams0 results read, including the national CVE database: nothing found
  • Are the stars earned?20.8K stars, 1 contributors, 3 commits. Flag: 20752 stars on 1 contributor(s); 20752 stars on only 3 commit(s)

Company code drop from Browser Use (1 contributor, 3 commits); findarepo's star check says it looks organic. Flag named on the page. Sep 27 review of a Hacker News claim that its browser component leaks data to PostHog: browser-harness 0.1.13 (which it installs) uploads the full task script (up to 20,000 characters) and the end of the output to PostHog from its own command line tool, on by default, not mentioned in its README; jev-ultrafast only uses the library parts (admin.ensure_daemon, helpers.cdp), which contain no analytics code, so its own runs send nothing there. Named as a watch-out on the page, with the off switch.

Watch out for

  • It drives your everyday, signed-in Chrome with no approval step. It sends the page's text and field values to TypeSafe, and to a second AI provider for anything it has to type, and it can act on every site you're already logged into. A safety review put it plainly: nothing stops it before a purchase or a form submission except how carefully you word the goal. Use a separate Chrome profile with nothing important in it.
  • It installs Browser Use's browser-harness, whose own command reports your tasks by default. jev-ultrafast itself doesn't use that command (we checked its code). But if you or your AI agent ever run browser-harness directly, it sends the whole task script and the end of its output to Browser Use's analytics service (PostHog), switched on by default and not mentioned in its README. Turn it off once with browser-harness telemetry disable.
  • The 7.1-second demo never finished a real booking. It typed the cities, picked a date, and stopped once the flight list appeared. By the README's own account this is one task tested three times, not a general reliability check, and real checkout pages add security steps like "prove you're human" screens that stop it cold.
  • It goes blind past a page's first 250 clickable things, and can't see picture-based human checks at all. On a busy screen, like a dashboard with 350 buttons and fields, anything past the 250th is invisible to it.
  • Depends entirely on TypeSafe's paid, closed Jev service, and it's brand new. If TypeSafe's pricing changes or the service goes down, the automation stops. Created September 16, 2026, still at version 0.1.0 - expect breaking changes.

Who's using it, and for what?

It's 9 days old (created September 16, 2026), so most of what's out there is people testing, explaining or picking apart the README's own benchmark rather than shipping something with it. The clearest independent build so far is below.

  1. 1.6-3.0x faster

    A developer building agent tools (GitHub user danielnc)

    Packaged jev-ultrafast's same one-call decision loop as a tool other coding agents (Claude, Cursor, Codex) can call mid-task to hand off a browser step, publishing it as the separate project "jev-browse" with its own MCP server (a standard way other AI agents can plug into it directly) and a public release.

    In the author's own benchmark, an agent calling this tool finished the same jobs 1.6 to 3.0 times faster and 2.1 to 5.3 times cheaper than having the agent drive the browser directly itself, with the same success rate.

    danielnc/jev-browse README, Sep 24
