Each page becomes a numbered list of elements. One Jev API call picks both the operation and the target. A separate small model types text only when needed. Choose, don't generate

Most browser agents take a screenshot, send it to a vision model, wait for a paragraph of reasoning, parse the action, and repeat. Jev-ultrafast skips the screenshot entirely. It reads the page into a structured action table and lets TypeSafe's Jev model pick the right action and element in a single API round trip.

● What makes it different

Dynamic indexed action space

Every page observation is converted into a numbered element table - buttons, links, inputs, dropdowns, each with an index. Jev picks the operation (click, type, scroll, wait) AND the element index in a single request. No screenshots, no bounding boxes, no coordinate math.

One round trip per step

Traditional agents need multiple LLM calls per step: understand the page, decide the action, generate parameters. Jev-ultrafast collapses this to one Jev API call. The action and its target come back together, eliminating round-trip latency.

Text generation only when typing

A separate small LLM is invoked only for TYPE_TEXT actions - when the agent needs to fill a form field or search box. All other actions are pure selection from the indexed table. This cuts token usage by an order of magnitude.

Real benchmark, not a demo

The headline 7.1-second result is a real Google Flights search from Zurich to London at 1x playback speed, including actual page loads and network waits. The timer starts after the first page observation. Independently verified, not cherry-picked.

Built on Browser Use

Jev-ultrafast inherits Browser Use's battle-tested browser control layer - session management, cookie handling, proxy support, and error recovery. It replaces only the decision-making layer, keeping the reliable infrastructure underneath.

Local inspector interface

A built-in inspector UI lets you watch the agent in real time - see the action table it constructed, the action it chose, and why. Essential for debugging and understanding agent behavior on your specific workflows.

Single best feature

The economics of choosing over generating

The fundamental insight is that browser actions are a closed set. On any given page, there are a finite number of things you can do: click this button, type in that field, scroll down. You do not need a large language model to generate a novel action - you need a fast decision model to pick from a list. Jev-ultrafast proves this thesis: at $0.042 per million input tokens with free outputs, a full multi-step web task costs less than half a cent. That price point makes browser automation viable for high-volume use cases that were previously cost-prohibitive.

Why browser agents are too slow

The current generation of browser agents works, but it is too slow and too expensive for anything beyond demos. The bottleneck is not the browser - it is the decision loop.

Before

Screenshot, reason, act, repeat. Typical browser agents take a screenshot of the page, send it to a vision LLM (GPT-4o, Claude), wait 2-5 seconds for a reasoning response, parse the action from natural language, execute it, and take another screenshot. A 10-step task takes 30-50 seconds.

1,092 browser protocol calls per task. The screenshot-based approach generates enormous amounts of browser protocol chatter - capturing renders, encoding images, coordinating viewport state. Most of this bandwidth is wasted on pixels the model barely uses.

Dollars per task, not cents. Each step burns a vision model call with a full-resolution screenshot. A 10-step task on GPT-4o can cost $0.50-$2.00. At that price, automated web tasks are a novelty, not a tool.

After

Read the table, pick the action. Jev-ultrafast reads the page DOM into a structured element table - no screenshots needed. Jev picks the action and target in one call that returns in milliseconds. A 10-step task completes in under 10 seconds.

101 browser protocol calls. Without screenshots, browser protocol usage drops by 91%. The agent communicates with the browser only for DOM reads and action execution - nothing wasted on rendering and image encoding.

Under half a cent per task. At Jev's pricing of $0.042 per million input tokens with free outputs, the Google Flights benchmark costs roughly $0.004. That is 100-500x cheaper than vision-model approaches. Browser automation at this price scales to production volumes.

Set up jev-ultrafast

From clone to your first automated web task in under five minutes.

1

Clone and install

git clone https://github.com/browser-use/jev-ultrafast.git
cd jev-ultrafast

# Install dependencies (Python 3.12+)
pip install -e .

# Install browser driver
playwright install chromium

Jev-ultrafast requires Python 3.12+ and a Chromium browser managed by Playwright. You will also need a Jev API key from TypeSafe for the decision model.

2

Configure API keys

# Set your Jev API key
export JEV_API_KEY="your-jev-api-key"

# Optional: set a text model for TYPE_TEXT actions
export OPENAI_API_KEY="your-openai-key"

# Or use a local text model
export TEXT_MODEL="local:llama3"

The Jev API key is required for action selection. A separate text model is needed only for steps that require typing - you can use OpenAI, Anthropic, or a local model. Most tasks have few typing steps, so the text model cost is minimal.

3

Run your first task

# Run the Google Flights benchmark
python -m jev_ultrafast \
  --url "https://www.google.com/travel/flights" \
  --goal "Search for a one-way flight from Zurich to London next Friday"

# Open the local inspector to watch the agent
python -m jev_ultrafast \
  --url "https://news.ycombinator.com" \
  --goal "Find the top story and open it" \
  --inspector

The --inspector flag opens a local web UI where you can see the element table, the agent's action choices, and step-by-step execution. Use it to debug and understand how the agent navigates your target pages.

Where jev-ultrafast fits

Fast, cheap browser automation unlocks use cases that were previously impractical.

Price Monitoring

Check thousands of product pages per hour. At under $0.01 per task, you can monitor competitor pricing across hundreds of SKUs multiple times per day. The speed means you can react to price changes in near real-time rather than on a daily batch schedule.

Form Filling

Automate repetitive web forms at scale. Insurance quotes, job applications, government filings - any workflow that involves filling forms across multiple sites. The structured action space handles dropdowns, date pickers, and multi-step forms reliably.

QA and Testing

Natural language test scripts. Describe what a user should do in plain English and let the agent execute it. "Log in, navigate to settings, change the display name, and verify the change appears on the profile page." Faster to write than Selenium, more robust to UI changes.

Data Collection

Scrape sites that resist traditional scrapers. Sites with heavy JavaScript rendering, login walls, or dynamic loading are hard to scrape with requests and BeautifulSoup. A browser agent navigates them like a human would - clicking through pagination, expanding collapsed sections, handling cookie banners - at a cost that scales.

Watch out for

  • Jev is a closed API. The speed comes from TypeSafe's Jev model, which is a paid API service. Your agent depends on TypeSafe's uptime, pricing, and continued availability. If Jev's pricing changes or the service goes down, your automation stops.
  • The benchmark is narrow. The 7.1-second Google Flights result is real but specific. Complex multi-page workflows with authentication, CAPTCHAs, or unusual UI patterns will take longer and may not work at all. Test on your actual target sites before committing.
  • Nine days old. Created September 16, 2026. The API surface, configuration format, and supported actions are all subject to change. Pin your dependency and expect breaking changes in the coming weeks.
  • Ethical and legal considerations. Automated browser agents that navigate sites as users raise questions about terms of service compliance, rate limiting, and data scraping legality. Ensure your use case complies with each target site's terms before deploying at scale.
