fast-jev-compaction

A Claude Code add-on that makes room in a long chat by deleting old tool calls instead of summarizing them, so what it keeps never changes a word.

When your Claude Code session gets too full, it asks TypeSafe's Jev decision AI which old file reads and command outputs are safe to throw away, deletes only those, and leaves everything you and Claude actually typed exactly as written.

How does it work?

Your problem

Claude Code's normal way of making room in a long session is to have an AI write a shorter summary of the old parts - and summaries quietly drop exact file paths, error messages and rules you stated once.

The maker's own words: "a file path, exact error, constraint, or command can disappear even when it matters later."

When it kicks in

It kicks in on its own once your session gets close to full (60% by default), or whenever you run /compact yourself.

Its own setting for this, compactAtPercent, is set to 60 out of the box.

You give it

Your whole session so far: every message, plus every tool call (a file read, a terminal command) and its result.

Old results aren't hidden, just shortened to a note first, like "ok, 4213 chars (omitted)", so the decision is made with the full conversation in view.

It does

It pairs up every tool call with its result, then asks Jev two quick questions about each older one: should we still know this happened, and do we still need its exact result?

  1. Leaves your very first message and your most recent messages alone, untouched
  2. Sends everything else to Jev and asks, for each tool call: keep it, and keep its full result?
  3. Deletes anything Jev says is safe to drop, and shortens (rather than fully deletes) results it says are only half-needed

One real, public example: a session dropped from nearly 1,000,000 down to 86,000 on Claude Code's own context-used count, in about one second.

You get

More room to keep working, and a plain note telling you what happened.

  • A session with real room left, not a rewritten oneThe viral example: nearly 1,000,000 down to 86,000 on the context-used count, in about a second
  • Everything kept reads exactly as it happenedThe README's own promise: nothing kept "is ever rewritten or summarized"
  • A plain on-screen note of what it did"fast-jev-compaction: kept N/M messages, no summary" when it works, or "fallback to built-in summary" on a short session it can't shrink enough

What changes for me?

Without it

  • The normal way trims a long session by having an AI write a shorter summary - and a summary can quietly drop an exact file path, error message or rule you stated once.
  • Once something is gone from a summary, there's no way to check whether it mattered.

With it

  • Nothing kept is ever rewritten - the maker's own words are that it "never rewrites anything."
  • Every deletion carries Jev's own confidence number attached, so what got cut (and how sure the AI was) can be checked.
  • In one real, public example, a session went from nearly 1,000,000 down to 86,000 on the context-used count, in about a second.

How hard is it to try?

Effort

5 minutesAbout an hourNeeds a developer
  1. Read the plugin setup notes first - this turns on an early-access Claude Code feature, it isn't a one-click install.
  2. Turn on Claude Code's function hooks and add a TypeSafe API key in your settings, then install it from the GitHub repo with claude plugin marketplace add tamaratran/fast-jev-compaction followed by claude plugin install fast-jev-compaction@fast-jev-compaction.
  3. Restart Claude Code (or run /reload-plugins) and keep working as normal - next time your session fills up, or you run /compact, watch for its on-screen message telling you what it kept.

Should I?

Great if you...

  • You run long Claude Code sessions and have watched Claude forget a file path or an exact error from earlier in the same conversation
  • You're comfortable turning on an early-access Claude Code feature and adding a TypeSafe API key

Skip it if...

  • Your sessions are mostly back-and-forth conversation rather than file reads and command output - this only trims tool calls, so it won't free up much room
  • You don't want your session's tool-call history leaving your machine, even in shortened form
  • You'd rather wait until this is out of early access

Instead, you could look at

  • Claude Code's built-in /compactThe plain summary-based compaction already built into Claude Code. Free and needs nothing extra to turn on, but more likely to lose an exact detail from earlier in the session.

Watch out for

  • Every compaction sends your tool-call history to TypeSafe's servers. The maker's own words: Jev is shown "the whole conversation so far" (with tool results shortened to a note first, not left out). If a session touches anything sensitive, that leaves your machine every time this runs.
  • It only helps sessions heavy on tool calls. By design it never removes or shortens the words you or Claude actually typed - only tool calls and their results. A long session that's mostly conversation won't shrink much.
  • It rides on another early-access feature. Claude Code's "function hooks" are themselves opt-in and can change between releases; the plugin's own type definitions are pinned to Claude Code 2.1.274 and need regenerating after an upgrade.
  • Brand new, with one big public demo so far. Created September 17, 2026. The viral 1-million-to-86,000 result is real, but it's one person's one session, not an average you should expect.
