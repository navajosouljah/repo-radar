● How memory works

Automatic lifecycle hooks

Hooks into session start and end events. No manual triggering - the agent's activities are captured and compressed without any user interaction.

3-layer retrieval pattern

Compact index for quick scans, timeline context for session flow, and full details on demand. Token-efficient by design.

Natural language search

Query project history with plain language via mem-search. Find what the agent did three sessions ago without scrolling through logs.

Web viewer UI

A real-time memory stream visualization in the browser. See what the agent remembers and how memories connect.

Privacy controls

Wrap sensitive content in private tags to exclude it from memory. The agent forgets what you tell it to forget.

Cross-agent compatibility

Works with Claude Code, OpenCode, Codex, Gemini, Copilot, and more. Memory persists regardless of which agent you use.

Single best feature

Zero-friction session continuity

Install once with npx claude-mem install, then forget about it. The system hooks into session lifecycle events, captures activities, compresses them, and injects relevant context into future sessions - all automatically. The agent picks up where it left off without you re-explaining anything.

The problem it solves

AI agents lose all context when sessions end. Claude-mem makes context persistent.

Before

Session amnesia. Every new session starts from zero. The agent does not know what it did yesterday, what files it edited, or what decisions were made.

Manual re-explanation. Developers spend the first 10-15 minutes of each session re-explaining project context, recent changes, and current goals.

Duplicate work. Without memory, agents re-explore solved problems, re-read files they already processed, and re-derive conclusions they already reached.

After

Automatic context injection. Relevant past observations are injected at session start. The agent knows what it did last time and picks up where it left off.

Zero manual overhead. No commands to run, no memory files to maintain. Lifecycle hooks handle everything.

Token-efficient retrieval. The 3-layer pattern means the agent pulls only what is relevant, not the entire memory database.

Watch out for

  • First-party competition. Anthropic now ships native agent memory. The category claude-mem pioneered may be absorbed by platform features.
  • SQLite scaling. Memory is stored in local SQLite. Very long-running projects with thousands of sessions may see performance degradation.
  • Token overhead. Memory injection at session start consumes context window tokens. On small tasks, the memory context may be larger than the task itself.
  • Optional cloud sync. The cmem.ai cloud sync is optional but introduces a third-party data dependency if enabled.
