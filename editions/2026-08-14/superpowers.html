● What makes it different

Brainstorming via Socratic questioning

Before any code is written, the agent challenges your assumptions through structured questioning - forcing clarity on what you actually need to build.

Test-Driven Development enforcement

RED-GREEN-REFACTOR cycles are mandatory, not optional. The agent writes tests first, implements to pass them, then refactors - every time.

Subagent-driven development

Implementation delegates to subagents working in isolated git worktrees, with a two-stage review checking both spec compliance and code quality.

Plans broken into 2-5 minute tasks

Every implementation plan specifies exact file paths, verification steps, and task durations small enough that context drift becomes impossible.

14+ platform compatibility

Works across Claude Code, Cursor, OpenAI Codex, GitHub Copilot, Gemini CLI, Devin, and more - same methodology, any agent.

YAGNI and DRY as mandatory law

The methodology enforces these principles at the workflow level, not just as suggestions. Over-engineering triggers a design review loop.

Single best feature

Multi-hour autonomous development sessions

The five-phase discipline keeps agents on track long enough to work autonomously for hours at a time without drifting from the plan. Users report running entire feature implementations end-to-end while the agent handles brainstorm, plan, code, test, and review - without manual intervention.

The problem it solves

Coding agents jump straight to implementation. Superpowers forces them to think first.

Before

Agents code before thinking. Without structure, coding agents immediately attempt implementation - often building the wrong thing for 40 minutes before you notice.

No plan survives contact with code. Even when you provide requirements, agents drift from the plan within minutes, adding features nobody asked for.

Review is an afterthought. Code ships without systematic verification, testing, or spec compliance checks.

After

Clarify before coding. Socratic brainstorming surfaces edge cases and requirements gaps before a single line is written.

Plans that stick. Implementation plans are broken into 2-5 minute tasks with exact file paths, making drift structurally impossible.

Two-stage review on every PR. Subagents review for spec compliance first, code quality second - every implementation, every time.

Set it up

Install via the plugin marketplace for your agent of choice, or clone directly.

Install for your platform

# Claude Code
/plugin install superpowers@claude-plugins-official

# Cursor
/add-plugin superpowers

# Gemini CLI
gemini extensions install https://github.com/obra/superpowers

# Execute the plan

Watch out for

  • Overhead on small tasks. The five-phase methodology adds real friction on trivial changes. Not every bug fix needs a brainstorming session.
  • Shell-based implementation. The core is Shell scripts, which limits extensibility compared to TypeScript or Python-based skill systems.
  • TDD enforcement is non-negotiable. If your workflow does not include testing, Superpowers will fight you at every step.
