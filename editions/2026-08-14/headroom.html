● The compression stack

SmartCrusher for JSON

Structure-aware compression that removes redundancy from JSON payloads while preserving all semantically important content. 60-95% reduction on typical tool outputs.

AST-aware CodeCompressor

Compresses code files using abstract syntax tree analysis. Strips comments, whitespace, and redundant structure while preserving all meaningful code.

Kompress-v2-base model

A compression model trained on agentic traces. Understands what LLMs actually need from tool output and strips the rest.

Four deployment modes

Python/TypeScript library, drop-in HTTP proxy, agent wrapper (headroom wrap claude), or MCP server. Pick the integration that fits your stack.

Reversible compression (CCR)

Content-addressable recovery stores originals locally with configurable TTL. The LLM can pull back uncompressed data on demand.

Failure learning

headroom learn mines failed sessions and writes corrections to agent-specific markdown files - the agent gets smarter about what to compress next time.

Single best feature

Drop-in proxy, zero code changes

Run headroom wrap claude and every tool output, log, and file read is compressed before reaching the LLM. No code changes, no configuration files, no workflow disruption. The proxy intercepts API calls transparently and the agent never knows the difference - it just gets the same answers with fewer tokens.

The problem it solves

Tool-heavy agent runs burn through context windows and API budgets. Headroom compresses the problem away.

Before

Context window exhaustion. Agents processing 100+ KB of tool outputs, logs, and RAG results hit context limits and lose track of the task.

Expensive API calls. Every token sent to the LLM costs money. Verbose tool outputs inflate costs on high-volume agent workflows.

Redundant information. Tool outputs contain massive amounts of structural redundancy, boilerplate, and formatting that the LLM does not need.

After

Compressed context. Tool outputs are compressed before reaching the LLM. The model sees only semantically important content.

Lower costs. 20% fewer tokens for coding agents, 60-95% for JSON-heavy workflows. Real savings on real bills.

Reversible on demand. If the LLM needs the original, CCR retrieves it from local storage. Nothing is permanently lost.

Set it up

Install via uv or pip. Then wrap your agent or run the proxy.

1

Install

# Python (recommended)
uv tool install --python 3.13 "headroom-ai[all]"

# Or via pip
pip install "headroom-ai[all]"

# TypeScript SDK
npm install headroom-ai

Installs the library, CLI, proxy, and MCP server.

2

Wrap your agent

# Wrap Claude Code
headroom wrap claude

# Deploy as standalone proxy
headroom deploy

# Health check
headroom doctor

The wrapper intercepts API calls transparently. No code changes needed.

Watch out for

  • 95% is the ceiling, not the floor. The headline number comes from JSON-heavy workloads. General coding agent savings are closer to 20%.
  • Retrieval latency. The headroom_retrieve mechanism (pulling back originals) adds latency when the LLM needs uncompressed data.
  • Model dependency. Kompress-v2-base is trained on agentic traces. Performance on non-agent workloads may be lower.
  • Cost-optimization positioning. Multiple guides frame Headroom specifically as a hack for Claude Code usage caps rather than a general-purpose tool.
