//The Problem

Vibe coding ran on developer memory and self-review. Both fail at scale.

Before // Status Quo

Every session started from a clean slate. Vibe coding relied on developer memory, so agents forgot past architectural decisions the moment a session ended.

Agents reviewed their own code in the same session. That self-review blind spot missed security vulnerabilities - cross-site scripting bugs shipped directly to production.

The Monday morning tax. Developers burned 10-15 minutes at the start of each week re-explaining project context that the agent had already been told.

After // With ECC

A full harness, not a blank agent. 67 specialized subagents, 281 skills, continuous learning, and automated hooks equip the agent before the first prompt lands.

Independent review by design. Fresh-context specialist subagents review code the working agent wrote - dedicated security reviewers have caught critical vulnerabilities like un-whitelisted OAuth redirect URLs before production.

Session-start hooks rebuild context automatically. The 10-15 minute re-explanation penalty is eliminated - the harness remembers so you do not have to.

//Setup

Pick your harness. ECC installs into Claude Code, Codex, Gemini, and a long tail of other agents.

Claude Code

Install as a plugin from inside a session:

/plugin marketplace add https://github.com/affaan-m/ECC
/plugin install ecc@ecc

To add rule packs, clone the repo and copy the rule folders you want:

git clone https://github.com/affaan-m/ECC.git
mkdir -p ~/.claude/rules/ecc
cp -R rules/common ~/.claude/rules/ecc/

Marketplaces and enabled plugins can also be specified declaratively in ~/.claude/settings.json.

ChatGPT / Codex (CLI and Desktop)

Clone, install, and sync into Codex:

git clone https://github.com/affaan-m/ECC.git && cd ECC && npm install && bash scripts/sync-ecc-to-codex.sh

Or register via the Codex plugin marketplace:

codex plugin marketplace add affaan-m/ECC

Gemini

Clone the repo, then run the installer with the Gemini target:

git clone https://github.com/affaan-m/ECC.git && cd ECC
./install.sh --profile minimal --target gemini

Others (Cursor, OpenCode, Zed, Antigravity, Qwen, Kimi, Hermes)

Same installer, different target:

./install.sh --profile minimal --target cursor
./install.sh --profile minimal --target opencode
./install.sh --profile minimal --target kimi

For Cursor, isolate its memory from Claude Code:

export ECC_AGENT_DATA_HOME="$HOME/.cursor/ecc"

Configuration & API keys

Set strictness via the ECC_HOOK_PROFILE environment variable - minimal, standard, or strict.

API keys: ECC works through your harness's provider - no separate key needed. Self-hosting Kimi models or using Itō GPU compute requires configuring ECC_ITO_CLI_EXECUTABLE and injecting ITO_API_KEY.

  • Strict modes slow you down on purpose. GateGuard and strict safety modes intentionally trade execution speed for correctness, which can feel restrictive during rapid prototyping.
  • Do not mix install paths. Layering the Claude Code plugin with manual installation scripts duplicates skills, commands, and hooks.
  • Context bloat is real. Maintaining more than 80 active tools or 10 MCP servers severely bloats the context window, shrinking usable working memory from 200k down to roughly 70k tokens.
