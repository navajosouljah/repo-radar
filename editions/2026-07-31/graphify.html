What makes it different

  • Local tree-sitter AST parsing across 36 languages - structure is extracted deterministically on your machine, not guessed by a model.
  • Multimodal indexing - code, docs, PDFs, images, and audio/video all land in one graph.
  • Confidence-tagged edges - every relationship is labeled EXTRACTED or INFERRED, so you always know what is fact and what is a model's guess.
  • Leiden community detection - the graph self-organizes into architectural neighborhoods you can query.
Single best feature

Local deterministic AST parsing

Graphify maps cross-file dependencies and multimodal assets into a queryable knowledge graph without vector stores or API token costs. The structural layer of your codebase becomes persistent memory - built once, queried forever, at zero LLM spend.

The problem it solves

Text matching was never structural understanding. Graphify replaces both grep-blindness and brute-force context stuffing with a real graph of how your project fits together.

Before - the broken status quo
  • Text-matching tools like grep have no structural awareness - cross-file calls, imports, and architectural dependencies stay invisible.
  • Sending raw source files to LLMs for every query consumed up to 71.5× more tokens than necessary.
  • No persistent structural memory - every session re-derives the same architecture from scratch.
After - with graphify
  • Tree-sitter AST parsing runs locally and maps the entire codebase into a single queryable knowledge graph.
  • Docs, PDFs, images, and videos are indexed alongside code - one graph for the whole project, not just the source tree.
  • Structure is extracted deterministically, so cross-file calls, imports, and dependency chains become first-class queryable edges.

The shift is from searching text to querying structure. Instead of paying an LLM to re-read your repository on every question, the graph answers structural questions directly - and confidence-tagged edges keep extracted facts cleanly separated from inferred ones.

Setup

One package install, one skill registration, and a platform flag for your agent of choice. Local code parsing needs no API keys at all.

1

Install the package

Note the double-y package name:

uv tool install graphifyy
# or
pipx install graphifyy

Optional extras are available for richer extraction:

uv tool install "graphifyy[pdf]"
uv tool install "graphifyy[office]"
uv tool install "graphifyy[all]"
2

Register the skill

graphify install
# or scope it to the current project only:
graphify install --project
3

Wire up your agent

Claude Code

graphify claude install

ChatGPT / Codex

graphify install --platform codex

Requires multi_agent = true under [features] in ~/.codex/config.toml.

Gemini CLI

graphify install --platform gemini

Others - Cursor, OpenCode, Copilot, Trae, Kimi, Antigravity, Pi

# Cursor gets a dedicated command (creates .cursor/rules/graphify.mdc):
graphify cursor install

# Everything else uses the platform flag:
graphify install --platform <platform_name>
4

API keys - only if you go multimodal

Local AST code parsing requires no API keys. Headless extraction of docs, PDFs, or images requires environment variables such as OPENAI_API_KEY, ANTHROPIC_API_KEY, GEMINI_API_KEY, DEEPSEEK_API_KEY, MOONSHOT_API_KEY, or Azure/Bedrock credentials.

Use cases

Where the graph earns its keep: complex, multi-file codebases where dependencies span dozens of files and the docs live somewhere else entirely.

Tracing architecture in complex codebases

Developers working on multi-file projects such as FastAPI and nanoGPT use graphify to trace architectural dependencies and cross-file imports, and to connect code to documentation, PDFs, images, and videos - all through one queryable graph.

Cutting the token bill on every structural question

On a 52-file corpus, querying the graph saves 71.5× tokens per query compared to feeding raw source files into an LLM context window - and pure code parsing costs 0 LLM credits because extraction is local tree-sitter AST work.

Memory benchmarks, not vibes

Graphify scored 0.497 recall@10 on the LOCOMO benchmark (mem0 scored 0.048 on the same test) and 76% QA accuracy on LongMemEval-S.

In the wild

Mir Mursalin Ankur wired a self-updating knowledge graph: a PreToolUse hook refreshes the graph on every human edit, git commit, or agent edit, with an Obsidian vault as persistent memory (dev.to). Engr Mejba Ahmed ran it on three real codebases and found 5-10x token reduction on pure-code repos - flagging that the viral 71.5x figure leans on multimodal content inflating the baseline (writeup). Kevin Kinnett's verdict is honestly mixed: "the structural insights were interesting," but the workflow felt rough enough that he didn't keep reaching for it daily (review). Level Up Coding independently stress-tested the "70x cheaper" claim - the real number depends on what you index (analysis).

⚠ Watch out for

  • Indexing time: initial graph indexing takes 1 to 5 minutes on repositories with 150+ files.
  • Multimodal costs tokens: non-code extraction (PDFs, docs, images, videos) requires LLM token expenditure - only code parsing is free.
  • Static analysis limits: it cannot trace dynamic runtime behavior, dynamic imports, or event-emitter callbacks.
  • Scale ceilings: repositories over 500 files must be scoped to subfolders, and generated HTML graphs with more than 5,000 nodes fail to render comfortably in web browsers.
