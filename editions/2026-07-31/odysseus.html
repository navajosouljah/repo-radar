One dashboard, the whole fleet

Odysseus unifies what commercial platforms scatter across tabs and subscriptions:

  • Chat + autonomous agents with local and cloud models side by side
  • Compare mode - run models head-to-head before committing to expensive cloud API calls
  • Cookbook - hardware-aware model management for downloading and running local models
  • Deep Research - autonomous multi-step web research synthesized into structured, visual markdown reports
  • Documents, email (IMAP/SMTP), calendar, notes, and a local image canvas - all in the same control room
Single best feature

The Deep Research engine

Autonomously performs multi-step web research across dozens of sources and synthesizes the findings into structured, visual markdown reports - in reviewer testing, generating multi-source reports in 20 seconds to 1 minute across 14-32 web sources.

The problem it solves

Between cloud lock-in on one shore and fragmented local tooling on the other, there was no unified home port for self-hosted AI work. Odysseus is that port.

Before - the broken status quo
  • Commercial AI platforms lock users into paid cloud subscriptions and mine private user data.
  • Workflows scatter across separate web tabs for research, email, and coding.
  • Pure local setups without a unified workspace layer often prove too weak or fragmented for complex tasks.
After - with Odysseus
  • A free, self-hosted, local-first workspace - your data stays on your hardware.
  • Chat, autonomous agents, model management, document editing, and deep research unified under one dashboard.
  • Local models and cloud APIs coexist in the same control room, so you choose the tradeoff per task instead of per platform.

The framing matters: this is not another chat wrapper. It is a control room - the layer that makes a self-hosted rig feel like a coherent workspace instead of a pile of terminals and browser tabs.

Setup

Odysseus is a self-hosted workspace, so setup is about deployment and model connections rather than per-editor plugins. Docker is the recommended route; models - local or cloud - are wired up inside the app.

Docker Recommended

$ git clone https://github.com/odysseus-dev/odysseus.git
$ cd odysseus
$ cp .env.example .env
$ docker compose up -d --build

Open http://localhost:7000 - the initial admin password prints in the Docker logs.

Native bare-metal (macOS / Linux)

$ git clone https://github.com/odysseus-dev/odysseus.git
$ cd odysseus
$ python3 -m venv venv && source venv/bin/activate
$ pip install -r requirements.txt   # or: python setup.py
$ python launcher.py

Make sure tmux is installed before launching.

Connecting models and providers

Local models - Ollama and the Cookbook

Connect Ollama by pointing Odysseus to http://localhost:11434, or download models directly through the built-in, hardware-aware Cookbook.

Cloud models - OpenAI, DeepSeek, OpenRouter

Add cloud model API keys (OpenAI, DeepSeek, OpenRouter) under the Models/API settings inside the dashboard. This is also how ChatGPT-class and Gemini-class capability reaches the workspace - via whichever provider keys you configure.

Web and Deep Research

Add a Brave Search API key under Settings to enable web search and the Deep Research engine.

⚠ Watch out for

  • Bare-metal friction: native setup involves tmux dependencies, Python virtual environment conflicts, and PATH issues. Docker is the smoother path.
  • Consumer hardware is slow: local model execution on an M1 Max runs around 3.6 tokens/sec and is prone to crashes.
  • Weak coding agent: coding agent performance was rated 5/10 in reviewer testing.
  • False confidence: agents can claim tasks or MCP tool calls are "done" when no file edits or execution actually occurred - verify the artifacts.
  • Alpha-grade edges: image canvas editing and background removal tools remain buggy and alpha-grade.
