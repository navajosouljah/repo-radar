How it behaves in your codebase

When ponytail defers an abstraction, it says so: it injects <!-- ponytail: ... --> comments explaining what it deliberately did not build, so the restraint is documented instead of silent.

Single best feature

The 7-rung "lazy senior dev" decision ladder

Every task descends the ladder before any code is written - forcing agents to use standard libraries and native HTML/CSS platform features, like <input type="date"> instead of a 400-line custom date picker.

  1. Does it already exist?
  2. Is it already in the codebase?
  3. Is it in the standard library?
  4. Is it a native platform feature?
  5. Is it in an installed dependency?
  6. Is there a one-liner?
  7. Write the minimum that works.

The problem it solves

Coding agents are eager juniors. Ponytail makes them behave like the senior who has seen this feature built - and deleted - a dozen times.

Before
  • Agents habitually over-engineer: heavy third-party UI libraries, wrappers, and unnecessary abstractions for basic tasks like date pickers or modal dialogs.
  • Codebases bloat with hundreds of redundant lines where simple native elements would suffice.
  • Every "small feature" arrives with its own dependency tree.
After
  • Every request runs through the 7-step decision ladder first: standard libraries, native platform features, and existing dependencies before new code.
  • The agent writes the minimum that works - and leaves a ponytail: comment where it deferred an abstraction.
  • Less code to review, less code to maintain, less code to delete later.

The philosophy is YAGNI, enforced mechanically. Build the flexible abstraction now. Reach for what already exists, and only then write something new.

Setup

No API keys required. Install as a plugin in your agent of choice, optionally tune the intensity, done.

▸Claude Code

/plugin marketplace add DietrichGebert/ponytail
/plugin install ponytail@ponytail

▸ChatGPT / Codex CLI

codex plugin marketplace add DietrichGebert/ponytail
codex plugin add ponytail@ponytail

▸Gemini CLI / Antigravity

gemini extensions install https://github.com/DietrichGebert/ponytail
# or, on Antigravity:
agy plugin install https://github.com/DietrichGebert/ponytail

▸Others

Copilot CLI:

copilot plugin marketplace add DietrichGebert/ponytail
copilot plugin install ponytail@ponytail

OpenCode - add to your opencode.json:

{ "plugin": ["@dietrichgebert/ponytail"] }

Hermes / OpenClaw / Swival / Devin - host-specific commands, e.g.:

hermes plugins install DietrichGebert/ponytail --enable
# or
clawhub install ponytail

Instruction-only editors (Cursor, Windsurf, Cline, Copilot Chat, Kiro, Qoder): copy rule files from the repo - e.g. .cursor/rules/, .clinerules/, or AGENTS.md - into your project.

Configuration

No API keys needed. Set the intensity mode - lite, full, ultra, or off - via the PONYTAIL_DEFAULT_MODE environment variable or ~/.config/ponytail/config.json.

Use cases

Where restraint pays, where it costs, and what honest testing actually showed.

Enforcing YAGNI on real projects

Ponytail was tested on open-source repositories like tiangolo's full-stack-fastapi-template and evaluated by reviewers including Renato Dinis and Better Stack. Developers use it to enforce YAGNI principles and stop coding agents from over-engineering simple features.

The benchmark numbers

Across the agentic benchmark runs: ~54% less code on average (up to 94% on overbuilt UI elements like date and color pickers), ~22% fewer tokens, ~20% lower cost, and ~27% faster execution - with a 100% safety pass rate.

The admin dashboard that shrank 78%

In Renato Dinis's tests, an admin dashboard implementation went from 464 lines to 101 lines - 78% less code - and completed in 27s vs 2m 4s without the plugin.

WATCH OUT FOR

  • It is not always faster or cheaper. In Renato Dinis's real-world tests, ponytail took longer on authentication (2m vs 32s) and rate limiting (1m 30s vs 17s) while consuming more output and cache tokens.
  • Reasoning-model tax: terse reasoning models (like GPT-5.5) that spend thinking tokens deliberating the decision ladder can increase overall latency and cost.
  • The prompt-only alternative: technical reviewers noted that a simple system prompt ("follow YAGNI principles and one-liner solutions") yields nearly identical code reductions without needing the plugin at all.
