Transparent pre-execution hook auto-rewriting

rtk init -g wires rtk into your agent's pre-execution hooks so raw terminal output - git status, test runners, package managers - gets intercepted and passed to the LLM as ultra-compact summaries. No manual commands, no altered agent prompts. Your agent just quietly stops drowning in noise.

unique capabilities
  • Single Rust binary - one CLI proxy, no runtime, no daemon farm.

  • Built-in rtk gain analytics dashboard - see exactly how many tokens you did not spend.
  • Tee failure logging - full raw output is preserved on failures so compression never hides a broken build from you.

# what was broken, and what rtk does about it

the broken status quo

Standard development commands - git status, npm install, cargo test - dump hundreds of lines of noisy, redundant output straight into the AI's context window. Every passing test, every progress bar, every unchanged file listing lands in the model's working memory.

That working memory bloat rapidly consumes input tokens and exhausts session context limits. The agent forgets what it was doing not because the task was hard, but because a test suite printed 400 lines of green checkmarks.

before: raw pipe
Every cargo test run floods the context with full suite output
git status and npm install print noise the model never needed

Context limits hit early, sessions compact, momentum dies
after: rtk proxy
rtk intercepts the output before it reaches the LLM
Passing test suites collapse, logs get summarized
The same session costs 23,900 tokens - 80% savings
Sub-10ms overhead: the human never feels it, the model never sees the noise
how it solves it

rtk is a single Rust CLI proxy that sits between your shell and your agent. It intercepts terminal command outputs and compresses them - collapsing passing test suites, summarizing logs - before they hit the LLM context. The agent gets a compact, faithful summary; the raw output stays available locally when you need it.

# install the binary, then wire it into your agent of choice

step 1 · install the binary

# Homebrew (macOS)

$ brew install rtk

# Linux / macOS install script (installs to ~/.local/bin)

$ curl -fsSL https://raw.githubusercontent.com/rtk-ai/rtk/refs/heads/master/install.sh | sh

# Cargo (note: install via git - see "Watch out for" on the crates.io name collision)

$ cargo install --git https://github.com/rtk-ai/rtk

# Windows: extract the zip into your PATH

# rtk-x86_64-pc-windows-msvc.zip → any directory on your PATH
step 2 · wire it into your AI tool

Claude Code

# also covers GitHub Copilot - the default global init target

$ rtk init -g

ChatGPT / Codex

$ rtk init -g --codex

Gemini CLI

$ rtk init -g --gemini

Others (Cursor, Windsurf, Cline, Kilo, Hermes, Droid, Kimi)

$ rtk init -g --agent <agent_name>
# e.g. rtk init -g --agent cursor
step 3 · configuration (optional)

Config lives at ~/.config/rtk/config.toml (on macOS: ~/Library/Application Support/rtk/config.toml). Use it to set excluded commands and tee failure logging.

No API keys required. rtk runs strictly as a local Rust CLI proxy - nothing leaves your machine.

# who runs it, what it saved them, and where it bites

who uses it

Created by Patrick Szymkowiak and core maintainers, rtk is used as a proxy in front of the everyday command stream: git status, cargo test, npm test, pytest, aws, kubectl - intercepted before they reach the context windows of Claude Code, Gemini CLI, Codex, Cursor, and other agent harnesses.

measured outcomes
  • 60-90% fewer bash output tokens on common dev commands, with sub-10ms overhead per command.
  • 80% session savings: a typical 30-minute Claude Code session drops from 118,000 tokens to 23,900 tokens.
  • 76% token savings in FuturMinds' tests across 10 commands - 6.8K tokens saved in a single short run.
  • rtk gain analytics quantify the delta per session, so the savings are measured, not vibes.
field reports
  • FlorianBruniaux (HN): 15 days of rtk gain - 7,081 commands intercepted, 83.6% average input saved, 96%+ on peak implementation days. thread
  • LivioGama (HN): one week, 637 commands, 79.3% saved - "numbers speak for themselves."
  • JetBrains counter-benchmark: 86 SkillsBench tasks, 425 billed trials - rtk measured +7.6% MORE expensive at low reasoning effort (p=0.004), flat at high effort. Root cause: Read/Grep bypass the Bash hook, capping what rtk can touch. JetBrains
  • Adoption pressure: Kilo Code users filed a feature request for rtk-style filtering built in natively, citing the r/ClaudeAI "89% saved" post. discussion
⚠ watch out for
  • Filtering is lossy. Aggressive log compression risks dropping critical error details or tracebacks exactly when you need them most - during complex debugging.
  • Savings apply to bash output tokens only. System prompts, conversation history, and model generation tokens are untouched, so the headline percentage dilutes across your overall LLM bill.
  • Built-in tools bypass the hook. Claude Code's Read, Grep, and Glob do not go through the Bash hook and are not auto-compressed unless run as raw shell commands or explicit rtk calls.
  • crates.io name collision. "rtk" collides with "Rust Type Kit" on crates.io - install via the git/cargo flags shown in Setup, not cargo install rtk.
