■ What makes it different

Each bot gets its own computer

Not a shared sandbox. Every coworker runs in its own isolated container with a real browser, its own file system, and only the tools you explicitly grant. No ambient access to things it should not touch.

AG-UI protocol, framework agnostic

A bot is any endpoint speaking AG-UI, the open interaction protocol maintained by CopilotKit. Agents built with LangGraph, Mastra, CrewAI, Pydantic AI, or Google ADK all arrive the same way.

Full action transparency

Every action is decided before it happens and recorded after. Developers see exactly what the agent plans to do, approve or reject it, and review a complete audit trail.

Self-hosted, your data stays home

Docker Compose brings up the stack. Your data lives in your own PostgreSQL. No SaaS dependency, no data leaving your infrastructure. You pick the model provider.

Bot-to-bot handoff

Coworkers can hand tasks off to each other, route untagged messages on their own, and run on a schedule. Multi-agent orchestration without a central controller.

Knowledge source connectors

Bots can answer from Google Drive and Notion - connecting to your existing knowledge bases rather than requiring you to re-upload documents into yet another tool.

Best Feature

Isolation that actually works

The killer differentiator is not the AI - it is the sandboxing. Each coworker gets a real, isolated computer. A browser with its own logins, files it can read and write, and only the tools you grant. When an agent makes a mistake, it breaks its own sandbox, not your production environment. This is what turns AI agents from demos into something you can actually deploy at a company.

The AI agent trust problem

AI agents are powerful but dangerous. Giving them access to your browser, files, and tools means one bad action can break everything. Teams need transparency and isolation before they can deploy agents for real work.

Before

Agents share your environment. Most AI agent frameworks run in the developer's own browser or file system. One rogue action - deleting the wrong file, clicking the wrong link - affects everything. There is no isolation.

Black-box decision making. You tell the agent to do something and it does... things. What exactly did it browse? What did it write? The audit trail is spotty at best, nonexistent at worst.

Locked into one framework. You pick LangGraph or CrewAI or Mastra and you are committed. Swapping the orchestration layer means rewriting your agents from scratch.

After

Each agent gets its own sandbox. With OpenBot, every coworker runs in an isolated container. Its own browser, its own files, its own scoped tools. A mistake stays contained in that sandbox.

Full transparency by design. Every action is proposed before execution and logged after. Developers can approve, reject, or review any action. The audit trail is built into the protocol.

Bring any AG-UI agent. The AG-UI protocol decouples the agent from the platform. Swap LangGraph for CrewAI without touching your deployment. The platform does not care what framework powers the bot.

Deploy your first coworker

OpenBot is a template, not a package. Clone it, configure it, and run Docker Compose.

1

Clone the template

# Clone the OpenBot template
git clone https://github.com/CopilotKit/OpenBot.git
cd OpenBot

# Copy the environment template
cp .env.example .env

Edit .env with your model provider API key (OpenAI, Anthropic, or others) and your PostgreSQL credentials. OpenBot does not bundle a model - you bring your own.

2

Start the stack

# Bring up OpenBot with Docker Compose
docker compose up -d

# Verify services are running
docker compose ps

Docker Compose starts PostgreSQL, the OpenBot server, and the agent runtime. Each coworker gets its own container when it spins up. Your data stays in your own database.

3

Define a coworker

# Define a coworker in the config
# Each coworker is an AG-UI endpoint
# with scoped browser, files, and tools

# Example: a research coworker
name: "researcher"
agent: "langgraph://research-agent"
tools:
  - browser: { allow: ["*.google.com"] }
  - files: { read: true, write: false }

Coworkers are defined declaratively. Specify the AG-UI agent endpoint, what tools it can use, what sites it can browse, and what files it can access. The principle is least privilege.

Where OpenBot fits

OpenBot shines wherever you need AI agents doing real work with real accountability - not chat demos, but coworkers you can trust with production tasks.

Customer Support Bots

Deploy support agents that browse your docs and ticketing system. Each support coworker gets access to your knowledge base and Zendesk, but nothing else. It drafts replies, the team reviews and sends. Every interaction is logged.

Research Assistants

Agents that browse the web, summarize findings, and save to shared drives. A research coworker gets a browser scoped to approved sources and write access to a single Google Drive folder. It runs on a schedule and delivers daily briefings.

Internal Tool Automation

Automate repetitive workflows across internal tools. A coworker logs into your internal dashboards with its own credentials, pulls reports, and formats them. No screen-sharing your personal browser session with an AI.

Multi-Agent Orchestration

Teams of bots that hand off work to each other. A triage coworker reads incoming requests and routes them to specialized coworkers - one for billing, one for technical issues, one for account changes. Each with its own scoped access.

Watch Out For

  • It is a template, not a product. OpenBot is meant to be cloned and customized. There is no hosted version, no package to install, no managed service. If you want turnkey, this is not it - you are building and maintaining your own deployment.
  • Very early stage. The project was created August 17, 2026 and is at v0.0.14. The API surface is changing fast. Expect breaking changes between minor versions and plan for migration work.
  • CopilotKit commercial relationship. OpenBot is MIT-licensed but built by CopilotKit, which sells a commercial platform. Evaluate whether the open-source project will continue to get investment or whether features will migrate to the paid product over time.
  • Docker Compose complexity. Running multiple isolated containers per coworker means resource requirements scale with the number of agents. Plan your infrastructure accordingly - this is not a lightweight single-process tool.
