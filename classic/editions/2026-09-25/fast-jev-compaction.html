Claude Code Plugin - Context Compaction

tamaratran/fast-jev-compaction

Compaction without the summary. A Claude Code plugin that replaces the built-in /compact summary with Jev decisions. Every tool call and result is scored by a classifier - stale ones are dropped, everything kept stays verbatim. No rewriting. No lossy summaries. Just surgical deletion.

Delete the noise, keep the signal

fast-jev-compaction takes a fundamentally different approach to context compaction. Instead of asking an LLM to summarize old turns - which inevitably loses file paths, exact errors, and constraints - it asks Jev, TypeSafe AI's non-text-generating classifier, a yes/no question about every tool call. Stale calls are removed. Everything else passes through byte for byte.

● What makes it different

Zero rewriting

Nothing kept is ever summarized, paraphrased, or rewritten. Every retained message stays verbatim - the exact file paths, error strings, and constraints survive compaction intact.

Jev-scored decisions

Each tool call and result is scored by Jev, TypeSafe AI's "System One" classifier. Jev sees the whole conversation and decides what is still needed with a probability attached to each deletion.

Only tool calls are candidates

User and assistant text messages are never removed or shortened. Only tool calls and their results are eligible for deletion. A session that is long because of conversation will not shrink much - by design.

Attributable deletions

Every removed tool call has a probability score attached. You can audit exactly what was dropped and how confident the classifier was. No black-box summarization.

Graceful fallback

If Jev cannot remove enough to fit the context window, the plugin falls back to Claude Code's built-in summary. The toast reads "fallback to built-in summary" so you always know which path was taken.

Also an npm library

Not locked to the plugin system. Import it as a library for custom compaction pipelines, testing, or integration into other agent harnesses beyond Claude Code.

Single best feature

The file path that vanished is no longer a problem

Every developer using a coding agent has hit this: midway through a long session, the agent forgets a file path, an exact error message, or a constraint you stated twenty turns ago. It was lost during compaction because a summarizer decided it was not important enough. fast-jev-compaction eliminates this failure mode entirely. It never rewrites your transcript. It only deletes tool calls that Jev says are no longer needed. If a tool call is kept, its output is there byte for byte - the file path, the error string, the constraint. The agent reads exactly what happened, not someone's interpretation of what happened.

The lossy summary problem

Every compaction scheme in a coding agent rests on the same bet: that a model can read a long transcript and write a shorter one that keeps whatever matters later. That bet loses more often than you think.

Before

Summaries lose details that matter. A file path, an exact error string, a constraint the user stated once in passing - these are cheap to keep and impossible to reconstruct once a summarizer has decided they were not worth the tokens.

The agent hallucinates context. After a summary-based compaction, the agent may "remember" something that was not in the summary - or misremember a detail that was reworded. The summary introduced noise that was not in the original conversation.

You cannot audit what was lost. After summarization, the original turns are gone. There is no way to check whether a critical detail survived. You only discover the loss when the agent makes a mistake later.

After

Nothing is rewritten. Every kept message is verbatim. File paths, error strings, version numbers, and exact constraints survive compaction unchanged. The agent reads the real transcript, not an interpretation of it.

Only tool calls are removed. The classifier evaluates each tool call and result against the full conversation context. Stale reads, old directory listings, and superseded test runs get dropped. Everything else stays.

Every deletion is auditable. Each removed call has a Jev probability score. You know exactly what was dropped and how confident the model was. If something important was cut, you can see it and adjust the threshold.

Set up fast-jev-compaction

Install the plugin, set your TypeSafe API key, and restart Claude Code. Requires Claude Code 2.1.274 or later with function-hooks support.

1

Install the plugin

# Install from the Claude Code plugin marketplace
claude plugin marketplace add tamaratran/fast-jev-compaction

# Or use it as an npm library
npm install fast-jev-compaction

The plugin hooks into Claude Code's /compact command and auto-compaction. It replaces the built-in summarizer with Jev-scored deletions. The npm library is available for custom integrations.

2

Set your TypeSafe API key

# Get a key from TypeSafe AI (jev model access)
export TYPESAFE_API_KEY="your-key-here"

# The plugin calls Jev's classifier API
# to score each tool call in the session

Jev is TypeSafe AI's non-text-generating "System One Model" - a classifier, not a generator. It answers yes/no questions about whether each tool call is still relevant to the current conversation context.

3

Restart and verify

# Restart Claude Code or reload plugins
/reload-plugins

# Run /compact to trigger Jev-based compaction
# Success toast:
#   fast-jev-compaction: kept N/M messages, no summary

# Fallback toast (if Jev cannot shrink enough):
#   fallback to built-in summary

After reload, both /compact and auto-compaction use Jev. The toast message tells you which path was taken and how many messages were retained out of the total.

Where fast-jev-compaction fits

Any Claude Code session where you cannot afford to lose specific details during compaction.

Long debugging sessions

Error messages and stack traces survive compaction. When you are fifty turns into debugging a race condition, the exact error from turn twelve still matters. Jev keeps it if it is still relevant to the current thread.

Multi-file refactors

File paths and constraints do not vanish. A refactoring across twenty files accumulates a lot of tool output - reads, writes, test runs. Jev drops the superseded reads while keeping the paths and decisions that the agent still needs.

Sessions with tight constraints

Constraints stated once stay in the transcript. "Do not change the public API" or "keep backward compatibility with v2" - these user messages are never touched by the compactor. The agent reads them exactly as you wrote them, every time.

Auditing and trust

See exactly what was dropped and why. Each deletion carries a Jev probability. If your workflow requires accountability for what the agent knows and does not know, this is the only compaction scheme that gives you a receipt.

Watch out for

  • Conversation-heavy sessions will not shrink much. The plugin only removes tool calls and their results. If your session is long because of back-and-forth conversation rather than tool output, Jev will not find much to cut. This is by design - text messages are never removed - but it means the plugin is less effective for chat-heavy workflows.
  • Requires a TypeSafe API key. Jev is not a local model. Each compaction sends your tool-call history to TypeSafe AI's classifier API. Consider whether your session content is appropriate for an external API call before enabling.
  • Eight days old. Created September 17, 2026. Active development with PRs to validate keep thresholds and harden against malformed Jev responses, but the plugin is still very new. Expect rough edges and breaking changes.
  • Fallback is silent context loss. When Jev cannot remove enough to fit the window, the plugin falls back to Claude Code's built-in summary - which is the lossy approach this plugin exists to avoid. The toast tells you when fallback happens, but it is easy to miss.
