jaredpalmer/kev

● What makes it different

Three model scales

Kev ships at 0.8B, 4B, and 9B parameters. The 0.8B model runs on a MacBook. The 9B model scores 0.837 accuracy on the locked test set - within 2 points of hosted Jev at 0.857.

No text generation

Kev is not a chatbot. It takes one document and typed questions, then returns probability distributions in a single forward pass. The pointer head scores each option's hidden state against the question's hidden state; a softmax turns those scores into probabilities.

TypeSafe-compatible API

Kev serves TypeSafe's own POST /v1/systemone contract, so the official typesafe-sdk works against it by changing a base URL. Drop it into existing Jev-consuming code without rewriting the client.

LoRA + pointer head architecture

A rank-16 LoRA adapter plus a small pointer head sits on the Qwen3.5 base. The adapter is tiny - you can store all three model adapters in a few hundred megabytes. The base weights come from Qwen and are frozen.

$95 training cost

The entire Qwen3.5 port cost roughly $95 in Modal H100 time plus $0.03 in Jev API calls for generating calibration data. The repo includes the training script so you can reproduce or fine-tune on your own data.

Calibration pass included

All three models received a second training pass on generated examples - policy cases with explicit day counts and cases whose deciding evidence was removed - trained toward uniform answers. This reduces overconfidence on ambiguous inputs.

Single best feature

Decision intelligence without vendor lock-in

The real value of Kev is not any single accuracy number. It is the fact that decision models - a category TypeSafe introduced with Jev - now exist as open weights under Apache-2.0. You can run Kev on your own GPU, fine-tune it on your domain data, and deploy it behind your own API without paying per-call pricing or sending sensitive documents to a third party. The 9B model trails Jev by only 2 points on the test set. For many use cases - policy screening, triage, routing - that delta does not matter, and the cost difference is enormous. One forward pass on a consumer GPU versus an API call to a hosted model.

The decision model problem

Jev proved that decision models work. But Jev is a hosted API with proprietary weights. If you need to run locally, fine-tune on domain data, or avoid sending sensitive documents to a third party, you are stuck.

Before

Jev is hosted and proprietary. You send your document to TypeSafe's API and get probabilities back. You cannot inspect the weights, fine-tune on your data, or run it on your own hardware. Every call costs money and sends data off-premises.

LLMs are overkill for yes-or-no questions. Using GPT-4 or Claude to answer "is this claim eligible?" generates paragraphs of reasoning when you just need a probability. You pay for tokens you do not need and introduce latency from text generation.

Fine-tuned BERT is manual work. You can train a classifier, but you need labeled data, a training pipeline, and ongoing maintenance. Every new question type requires a new model or a retrain. There is no standard API shape.

After

Open weights under Apache-2.0. Kev's adapters and pointer head are yours. Run them on your GPU, behind your firewall, on your terms. No per-call pricing, no data leaving your infrastructure.

One forward pass, one probability. No text generation, no chain-of-thought, no token counting. Send a document and typed questions, get calibrated probabilities back in milliseconds. The 0.8B model runs in under 2 seconds on an M4 Mac.

Fine-tune with the included script. The repo ships a training script that works with Modal. Add your own labeled examples - the training instructions show that 50 to 100 examples can reach 95% accuracy in under 5 minutes on a CPU.

Run your own decision model

From clone to first inference in under 10 minutes. Weights download automatically from Hugging Face.

1

Clone and install

# Clone the repository
git clone https://github.com/jaredpalmer/kev.git
cd kev

# Install dependencies
pip install -e .

# Weights download automatically from Hugging Face
# on first run (0.8B, 4B, or 9B)

Kev requires Python 3.10+ and PyTorch. The 0.8B model needs about 2 GB of VRAM; the 9B model needs about 20 GB. CPU inference works but is slower.

2

Run inference

# Start the server (TypeSafe-compatible API)
kev serve --model 0.8b --port 8080

# Or run a single prediction
kev predict \
  --model 0.8b \
  --document "Patient presented with..." \
  --question "Is this claim eligible?" \
  --options "yes,no"

The server exposes the POST /v1/systemone endpoint. Point the typesafe-sdk at http://localhost:8080 and your existing Jev client code works without changes.

3

Fine-tune on your data

# Prepare training data (JSONL format)
# Each line: {"document": "...", "question": "...",
#            "options": [...], "answer": "..."}

# Fine-tune with Modal
modal run train.py \
  --base-model qwen3.5-0.8b \
  --data my_training_data.jsonl \
  --output ./my-kev-adapter

Training uses LoRA rank 16 by default. A dataset of 100 examples trains in about 5 minutes on an H100. The output is a small adapter you load alongside the base Qwen3.5 weights.

Where decisions beat generation

Kev shines when you need a probability, not a paragraph. Fast, cheap, and calibrated.

Policy Screening

Is this insurance claim eligible? Feed the policy document and a set of eligibility questions. Kev returns probabilities for each option in one forward pass. A threshold triggers auto-approval, manual review, or rejection. No LLM chain-of-thought needed for a binary decision.

Ticket Triage

Route support tickets by severity. The document is the ticket text; the question is "what is the severity?" with options like critical, high, medium, low. Kev returns calibrated probabilities that feed directly into routing logic. Sub-second latency means real-time triage.

Content Moderation

Flag or pass in milliseconds. Run each piece of user-generated content through Kev with questions like "does this contain hate speech?" and "is this spam?" The 0.8B model handles this on a single CPU core, keeping moderation costs near zero at scale.

Agent Tool Selection

Help an AI agent pick the right tool. When an LLM agent needs to decide which tool to call, Kev can score the options in one forward pass - faster and cheaper than asking the LLM itself to reason about tool selection. The probability distribution gives a confidence signal the agent can act on.

Watch out for

  • Still trails Jev on accuracy. Kev-9B scores 0.837 on the locked test set versus Jev's 0.857. That 2-point gap may matter in high-stakes applications. Evaluate on your own data before replacing a production Jev integration.
  • Calibration is not perfect. Jared Palmer noted on X that Kev is "still a bit overconfident at the moment." The second calibration pass helped, but you should validate probability calibration on your specific domain before trusting the numbers for anything critical.
  • Only 8 days old. Created September 17, 2026. The project is moving fast - three architecture changes in the first week - but it has not been battle-tested in production. Expect breaking changes.
  • The "decision model" category is debated. The Hacker News thread spent significant time arguing whether this is genuinely new or just classification with a fresh vocabulary. If you already have a fine-tuned BERT classifier that works, Kev may not add enough to justify a switch.
