● What makes it different

Drag-and-drop M3 Expressive parts

Over 40 real Material 3 Expressive components - buttons, icon buttons, FABs, split buttons, FAB menus, chips, app bars, navigation bars, cards, text fields, and more. Each part looks and behaves like the actual M3E specification.

One-click prompt export

Press the export button and get a structured natural-language brief with behavioral notes per component. The prompt includes layout relationships, navigation flows, and interaction details - not just a list of widgets.

Multi-language prompts

Export prompts in English, Japanese, Chinese, or Korean. The language toggle applies to all behavioral notes and component descriptions, so your AI coding agent gets instructions in the language you think in.

Magnetic snapping and Tidy

Components snap together magnetically. The Tidy feature snaps bars to edges, the FAB to corners, joins neighboring list items and buttons, and stacks the rest on 16dp margins. Press again to undo.

Tap-through navigation

Wire up multi-screen flows with tap-through navigation. Define which button goes to which screen, and the exported prompt includes the full navigation graph so your AI agent builds the routing correctly.

Optional AI helper

Bring your own API key - OpenAI, Claude, Gemini, or DeepSeek - and have the model write behavior notes or screen descriptions in your language. The key stays in your browser; requests go directly to the provider.

Single best feature

The prompt is the product

Most design tools produce images or design tokens. M3E Canvas produces something fundamentally different - a structured prompt that an AI coding agent can execute. The exported brief is not a vague description. It includes the exact component hierarchy, spacing relationships, color roles, navigation targets, and behavioral notes per widget. When you paste it into Claude Code or Cursor, the agent builds something that matches your sketch because the prompt carries enough context. The gap between "I sketched something" and "the AI built what I meant" shrinks to nearly nothing.

The design-to-prompt gap

Vibe coding works when the prompt is good. Most people cannot write a prompt that describes a UI well enough for an AI agent to build it correctly.

Before

Prompts are too vague. "Make me an app with a bottom nav and a card list" produces wildly different results depending on the AI agent, its mood, and the phase of the moon. You spend more time correcting the output than you would have spent building it manually.

Design tools export the wrong thing. Figma and Sketch export images, design tokens, or component specs aimed at human developers. None of that is a prompt. Converting a Figma frame into instructions an AI agent can follow is a manual, error-prone translation step.

Material 3 Expressive is new and complex. M3E introduced new component shapes, motion patterns, and layout rules. Most developers - and most AI agents - do not know the spec well enough to get the details right without explicit guidance.

After

Sketch your intent, export precision. Drag M3E components onto a canvas, arrange them the way you want, and the exported prompt captures exactly what you drew - component types, positions, nesting, colors, and behaviors.

Prompts carry behavioral notes. Each component in the export includes what it does, not just what it looks like. A FAB menu export says "expands to show three actions on tap" rather than just "floating action button." The AI agent builds the interaction, not just the shape.

Works with any AI coding tool. The output is plain text. Paste it into Claude Code, Codex, Gemini CLI, Cursor, or anything else that accepts a prompt. No plugins, no integrations, no vendor lock-in.

How people use it

M3E Canvas sits between design and code. Here is where that position pays off.

Solo Vibe Coding

Sketch what you want, then let the AI build it. A solo developer with no design background drags components onto a canvas, hits export, and pastes the prompt into Claude Code. The output follows Material 3 Expressive conventions because the prompt specifies them - no guessing, no "make it look like Material Design."

Client Communication

Replace wireframe meetings with interactive sketches. Sketch two or three screens, connect them with navigation, and show the client a clickable prototype in the browser. When the client says "yes," press export and hand the prompt to your AI coding agent. The spec is already written.

Android Prototyping

Go from idea to running Compose code in minutes. Set the target to Android, sketch your screens using M3E parts, export the prompt, and paste it into Gemini CLI or Claude Code. The prompt includes Compose-specific instructions, so the generated code uses Material 3 Expressive composables.

Design Education

Learn M3E by building with it. Students drag real Material 3 Expressive components and see how they relate. The behavioral notes in the exported prompt teach what each component does - a navigation rail is not just a sidebar, it has specific selection and expansion behaviors.

Watch out for

  • Only Material 3 Expressive. If your project uses a different design system - Fluent, Carbon, Ant Design, custom - M3E Canvas will not help. The components and the exported prompts are specific to M3E.
  • Prompt quality depends on your sketch. The tool exports what you draw. A sloppy layout produces a sloppy prompt. Use the Tidy button to clean up alignment before exporting.
  • No real data binding. The canvas deals in static screens and navigation flows. It does not model data sources, API calls, or state management. You still need to specify those in your prompt manually or let the AI agent infer them.
  • Local storage only. Your sketches live in the browser's local storage. Clear your browser data and they are gone. There is no cloud sync, no team sharing, and no export-to-file for backups yet.
