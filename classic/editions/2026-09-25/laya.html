AI Decision Engine - Open Source

NandhaKishorM/laya

Decisions in 33 milliseconds, not 3 seconds. Laya is a non-autoregressive System 1 decision engine built on a 421M ModernBERT backbone. Feed it any text and a typed question - choice, score, or yes/no - and it returns a calibrated answer in a single forward pass. No token generation, no streaming, no hallucination. 100+ languages out of the box.

One pass. One answer.

Laya replaces autoregressive LLM calls for structured decisions. Instead of generating tokens to arrive at "Option B," it evaluates all options simultaneously through a bidirectional encoder and returns calibrated probabilities. The result is a 7.8x latency reduction over comparable LLM-based approaches.

● What makes it different

Three typed primitives

Every decision fits one of three schemas: choice (pick one option from a list), score (place text on a numeric scale), or noul (calibrated yes/no probability). The API enforces the schema, so the model cannot return malformed output.

Script-aware router

A built-in router detects the input script in under 2ms and dispatches to the right checkpoint - English, multilingual, or enterprise. You do not need to know what language your input is in. The router handles it.

Calibrated probabilities

Laya is trained with proper scoring rules, so its confidence values are actually meaningful. When it says 0.85 probability, it is right roughly 85% of the time. This matters for downstream decision pipelines that need to threshold or rank.

Fine-tune friendly

The base model is a starting point. On the typed-decisions benchmark, the fine-tuned checkpoint scores 0.766 accuracy vs. 0.362 for the base. A Kaggle notebook shows fine-tuning on 2x T4 GPUs with the included training scripts.

No hallucination possible

Because Laya does not generate text, it cannot hallucinate. A choice question returns one of the options you provided. A score returns a number on your scale. A noul returns a probability between 0 and 1. The output space is always bounded.

LangChain and LangGraph integration

Official adapters let you drop Laya into existing agent pipelines as a fast decision node. Use it for routing, scoring, or gating without burning tokens on a full LLM call.

Single best feature

System 1 thinking for your pipeline

The most compelling aspect of Laya is its position in the architecture. Autoregressive models are System 2 - slow, deliberate, expensive. Laya is System 1 - fast, intuitive, cheap. Use it for the hundreds of small decisions in a pipeline that do not need chain-of-thought reasoning: is this email spam? Which department should handle this ticket? Is this review positive or negative? Each of those calls drops from seconds and cents to milliseconds and fractions of a cent. At scale, that changes what is architecturally possible.

The decision bottleneck

Every production AI pipeline has dozens of classification and routing decisions. Today, most of them burn a full LLM call. That is slow, expensive, and architecturally fragile.

Before

Every decision is an LLM call. Classifying a support ticket? That is a GPT-4 call. Routing an email? Another call. Scoring sentiment? Another. Each one takes 1-3 seconds and costs real money. The pipeline is bottlenecked by the slowest link in a chain of autoregressive calls.

Output parsing is fragile. You prompt the LLM to return "Option A" or "Option B," but sometimes it returns "I think Option A is best because..." and your parser breaks. Structured output modes help, but they add latency and still generate tokens you do not need.

Confidence is uncalibrated. When an LLM says it is 90% confident, that number is not meaningful. You cannot build reliable thresholding or escalation logic on top of uncalibrated confidence scores.

After

Decisions in 33ms, not 3 seconds. Laya replaces each slow LLM classification with a single forward pass through a 421M-parameter encoder. Batch multiple questions and the per-decision cost drops to 7.2ms. Your pipeline runs at the speed of the work, not the speed of token generation.

Typed output by construction. A choice question returns exactly one of your options. A score returns a number. A noul returns a probability. There is no parsing step because there is nothing to parse - the output schema is enforced by the model architecture itself.

Calibrated confidence for real decisions. Trained with proper scoring rules, Laya's probability outputs are calibrated. Build thresholds, escalation logic, and multi-stage pipelines on numbers that actually mean what they say.

Set up Laya

From pip install to your first decision in under two minutes.

1

Install from PyPI

pip install laya

# Or install from source for development
git clone https://github.com/NandhaKishorM/laya.git
cd laya && pip install -e ".[dev]"

Laya requires Python 3.10+. The package pulls the base checkpoint from Hugging Face on first use. For air-gapped environments, pre-download the convaiinnovations/laya model from Hugging Face Hub.

2

Make your first decision

# A simple choice decision
from laya import Laya

engine = Laya()

result = engine.predict(
    state="The customer is asking about a refund for a broken item",
    questions=[
        {"type": "choice",
         "prompt": "Which department should handle this?",
         "options": ["billing", "support", "returns", "shipping"]}
    ]
)

print(result)
# [{"answer": "returns", "confidence": 0.87}]

The state is any text - an email, a ticket, a document, a JSON blob. The questions list can contain choice, score, or noul questions. Batch multiple questions against the same state for maximum throughput.

3

Fine-tune for your domain

# Fine-tune on your labeled decisions
# See: notebooks/laya_finetune_typed_decisions_2xT4_kaggle.ipynb

from laya.train import Trainer

trainer = Trainer(
    base_model="convaiinnovations/laya",
    train_data="my_decisions.jsonl",
    output_dir="./laya-my-domain"
)

trainer.train(epochs=5, batch_size=32)

# Base accuracy: ~0.36 | Fine-tuned: ~0.77

Zero-shot accuracy on the base model is near random for domain-specific tasks. Fine-tuning is where Laya shines - the included Kaggle notebook runs on 2x T4 GPUs and takes the typed-decisions benchmark from 0.362 to 0.766 accuracy.

Where Laya fits

Laya is not a general-purpose LLM. It is a specialized decision engine for structured classification at scale.

Ticket Routing

Route support tickets in milliseconds. A fine-tuned Laya model classifies incoming tickets by department, priority, and category. At 7.2ms per decision batched, you can process thousands of tickets per second on a single T4 GPU - replacing what would otherwise be thousands of LLM calls.

Content Moderation

Flag content without generating text. Use noul questions to get calibrated probabilities for policy violations. "Is this comment toxic?" returns a probability, not a paragraph. Threshold at 0.8 for auto-removal, 0.5-0.8 for human review - and trust the numbers because they are calibrated.

Agent Decision Nodes

Drop fast decisions into LangChain/LangGraph pipelines. Use Laya for routing and gating decisions within an agent loop. "Should the agent search the web or query the database?" does not need chain-of-thought - it needs a fast, reliable choice. Laya provides that in 33ms instead of 2 seconds.

Multilingual Classification

Classify text in 100+ languages without separate models. The script-aware router automatically detects the input language and dispatches to the appropriate checkpoint. Build one classification pipeline that handles English, Hindi, Arabic, and Mandarin without language detection boilerplate.

Watch out for

  • Zero-shot accuracy is near random. Do not expect Laya to work well out of the box on your specific task. The base model scores 0.362 on the typed-decisions benchmark - barely above chance. You need to fine-tune it on labeled data from your domain to get useful accuracy.
  • Confidence calibration needs refitting. While the training procedure uses proper scoring rules, the calibration curves shift when you fine-tune. Re-calibrate on a held-out validation set from your own data before trusting the probability outputs for production thresholding.
  • Long documents degrade past 4K tokens. Laya supports up to 8,192 tokens, but accuracy becomes variable beyond roughly 4,000 tokens. For long documents, consider chunking and aggregating decisions rather than feeding the full text.
