● What makes it different

Persistent sessions and memory

Sessions, memory, schedules, and task checkpoints survive gateway restarts. Your agent crew continues working between conversations. Incognito and temporary session modes let you opt out when a conversation should not persist.

Multi-agent orchestration

Coordinate multiple AI agents working on different tasks simultaneously. Run several tasks at once instead of babysitting one prompt at a time. Each agent operates in its own context with shared memory across the crew.

Scheduled and reactive work

Cron schedules, webhook triggers, and heartbeat monitors keep your agent crews productive whether you are online or off. Long-running tasks move through checkpoints, validation, and retries automatically.

Self-improving skills

Memory, lessons, and skills carry across sessions so your crew evolves to fit your work. The workspace learns how you work and adapts its coordination patterns over time.

Multi-surface access

Work with your crew from the desktop app, web dashboard, and CLI, or continue the same work through connection tools like Slack and Discord. Same state, any interface.

Self-hosted, no AWS required

Deploy entirely on your own hardware - laptop, container, VM, or EC2 instance. No AWS account or managed control plane required. Your code, your data, your infrastructure.

Single best feature

Kick off a task, walk away, come back to something reviewable

This was the original design goal from the three Amazon engineers who built MeshClaw. You describe a task, the crew works on it asynchronously - through checkpoints, validation, and retries - and when you come back, you have a reviewable result waiting. Not a half-finished chat thread, not a stale context window, but an actual deliverable. Multi-step tasks run unattended, recurring jobs run on schedule, and heartbeats monitor systems until something needs attention. This is what "persistent" actually means: your agents keep working when you stop watching.

The ephemeral agent problem

AI coding agents are powerful in the moment but amnesiacs between sessions. Every conversation starts from scratch, long tasks die when the window closes, and running multiple agents means juggling multiple chat windows.

Before

Sessions die with the chat window. Close the terminal and your agent forgets everything. Context, progress, decisions, and half-finished work vanish. Tomorrow you start over from zero, re-explaining the same project and re-establishing the same patterns.

One task at a time. Most agent tools let you work on one task in one window. Running a migration, a test suite, and a code review simultaneously means three separate sessions with no shared context between them.

No unattended work. If a task takes two hours, you babysit it for two hours. There is no way to kick off a long-running job and come back when it is done. No scheduling, no retries, no checkpoints.

After

Sessions that survive everything. Sessions, memory, and task state persist across gateway restarts, network interruptions, and laptop reboots. Pick up exactly where you left off from any device or interface.

Multi-agent orchestration. Run several agents on different tasks concurrently. They share memory and lessons learned while operating in isolated contexts. One crew, many tasks, one state.

Async, scheduled, and reactive. Long-running tasks checkpoint their progress and retry on failure. Cron schedules handle recurring work. Webhooks trigger reactive jobs. Heartbeats monitor systems. Your crew works the night shift.

Set up KiroCrew

Get a persistent agent workspace running on your machine. Requires Python 3.12+, Node.js 22+ (24 LTS recommended), and npm.

1

Clone and install

git clone https://github.com/kirodotdev/KiroCrew.git
cd KiroCrew

# Install dependencies
npm install

KiroCrew supports macOS, Linux, and Windows. Docker images are also available for containerized deployments. The setup installs the gateway, dashboard, and CLI tooling.

2

Start the gateway

# Start the persistent gateway
npm run start

# Or run via Docker
docker compose up -d

The gateway is the persistent process that keeps your agents alive. It manages sessions, memory, schedules, and task checkpoints. Access it via the web dashboard at localhost or the CLI.

3

Create your first crew and task

# Open the web dashboard and create a crew
# Or use the CLI:
kiro crew create --name "my-project"

# Assign a task
kiro task start "Investigate the P1 latency spike in the
  payments service and set up prevention automation"

# Walk away. Come back later to review results.
kiro task status

Tasks run through checkpoints, validation, and retries automatically. The crew persists memory and lessons learned, so the next task benefits from everything the crew has seen before.

Where KiroCrew fits

Any workflow where agent work spans sessions, schedules, or team boundaries benefits from a persistent orchestration layer.

Incident Response

Autonomous P1 investigation. Kick off an incident investigation, walk into the war room, and come back to a structured report. The crew traces the issue across logs, metrics, and recent deploys, sets up prevention automation, and documents tribal knowledge - all for about $0.04 per incident in one reported case.

Recurring Ops

Scheduled maintenance on autopilot. Set up cron jobs for dependency updates, security scans, stale-branch cleanup, and test suite health checks. The crew runs them on your schedule, retries on failure, and only pages you when human judgment is needed.

Multi-Repo Work

Cross-repo changes with shared context. A feature that touches three services needs coordinated changes. One crew, one task, three repos. The crew shares context across all of them and produces reviewable PRs in each - without you context-switching between windows.

Team Onboarding

A crew that remembers so new hires do not have to. Your crew's memory accumulates project patterns, gotchas, and decisions over time. New team members inherit months of institutional knowledge from their first session. The crew evolves to fit how your team works.

Watch out for

  • Persistent agents can persist mistakes. A crew that remembers everything also remembers bad patterns. Memory and recurring jobs need regular review and pruning to avoid compounding errors over time.
  • Operational responsibility is on you. Self-hosted software means you manage updates, network access, secrets, and sandbox rules. KiroCrew is not a managed service - it is infrastructure you run.
  • Agent harness is not fully open. Forbes noted that AWS keeps the agent harness itself closed while open-sourcing the orchestration layer. Understand which parts are open and which depend on Kiro's proprietary components.
  • Resource consumption adds up. Persistent agents running scheduled tasks, heartbeats, and multi-agent workflows consume compute continuously. Monitor costs and set resource limits, especially when running on cloud infrastructure.
